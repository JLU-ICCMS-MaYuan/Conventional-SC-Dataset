# 06 AI 辅助 Tc 估算：页面结构与内容

## React/Vite 落地边界

本文定义 Tc 预测页面的结构和内容。模型接口、输入文件解析和结果保存以 API 与后端方案为准，视觉系统服从根目录 `design.md`。

## 页面承载

- 正式入口：`/tc-pre`。
- 静态示例：`index.html`。
- 页面目标：帮助用户提交结构和态密度输入、查看模型版本和预测结果，并明确预测结果不会自动进入公开数据库。

## Material 页面骨架

1. Top App Bar：显示“超导预测”和模型版本入口。
2. Navigation Rail：当前模块高亮为超导预测。
3. Upload Cards：上传 `CONTCAR` 与 `PDOS_H.dat`。
4. Config Card：模型版本、输入摘要和可用配置。
5. Result Card：预测 Tc、置信说明、失败原因。
6. History Data Table：历史任务与状态。
7. Snackbar / Dialog：预测完成、失败、提交审核确认。

## 页面区块

1. 顶部说明区：说明从结构和电子态输入估算 Tc。
2. 输入区：上传 `CONTCAR` 和 `PDOS_H.dat`。
3. 模型配置区：展示模型版本、输入摘要和可用配置。
4. 预测结果区：展示预测 Tc、置信说明、失败原因。
5. 任务历史区：展示历史任务并标注“有待建设”能力。
6. 提交审核提示区：说明预测结果可作为待审核候选，但不会自动入库。

## 内容规则

- 用户必须能区分即时预测和已审核数据。
- 失败原因要放在结果区域内，不能只用临时 toast。
- 提交审核入口为规划能力时必须标注“有待建设”。

## 验收标准

- 用户能看到输入文件、模型版本、输入摘要和预测结果。
- 错误原因清晰可读。
- 预测结果不会被表达为公开数据库记录。

## 旧版设计资产融合边界

- 继承旧版 SC-predict 的最小闭环：上传 POSCAR/CONTCAR 与 PDOS 文件，运行预测，展示预测 Tc 和特征明细。
- 保留旧版“PDOS_H.dat 必需、金属 PDOS 数量有限”的业务提示。
- 预测结果只作为即时工具结果或待审核候选，不自动进入公开数据库。
- 静态 demo 需要能模拟文件选择、按钮启用、loading、预测结果和失败提示。
