# 05 检索增强问答：页面结构与内容

## React/Vite 落地边界

本文定义 RAG 问答页面的结构、内容和证据呈现。模型调用和接口协议以 API 方案为准，视觉与组件规范服从根目录 `design.md`。

## 页面承载

- 正式入口：`/rag`。
- 静态示例：`index.html`。
- 页面目标：让用户看清回答依据，并明确 AI 生成的候选结构化记录不是已公开入库数据。

## Material 页面骨架

1. Top App Bar：显示“超导对话”和检索范围。
2. Navigation Rail：当前模块高亮为超导对话。
3. Conversation List Surface：历史会话和新对话入口。
4. Chat Surface：用户消息、AI 回答、引用标记和输入栏。
5. Evidence Side Sheet：论文片段、KG 结果、本地记录、外部来源。
6. Candidate Record Card：展示待审核结构化记录。
7. Snackbar / Banner：承载发送失败、RAG 降级和复制引用反馈。

## 页面区块

1. 顶部说明区：说明基于证据回答问题。
2. 会话列表：历史会话、新对话入口。
3. 对话流：用户问题、AI 回答、引用标记。
4. 输入区：问题输入、发送按钮、当前检索范围提示。
5. 证据面板：论文片段、KG 结果、本地记录、外部来源。
6. 候选记录区：AI 生成的待审核结构化记录，明确标注非公开数据。
7. 降级提示区：RAG 不可用或检索失败时展示。

## 证据类型

- 论文片段证据。
- 知识图谱关系证据。
- 本地记录证据。
- 外部来源证据。

## 内容规则

- AI 生成的候选数据不得被表达为已入库数据。
- 证据卡片必须展示来源类型和可追踪信息。
- 生成待审核结构化记录入口可规划，但需标注“有待建设”。

## 验收标准

- 用户能看清回答依据。
- 候选记录和正式入库数据有明确区分。
- RAG 不可用时有明确降级提示。
