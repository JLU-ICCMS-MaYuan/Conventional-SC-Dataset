# 02 数据维护与审核：页面结构与内容

## React/Vite 落地边界

本文只定义管理员审核中心的页面结构、字段内容和信息层级。权限、接口和数据写入以 API 与后端方案为准。

## 页面承载

- 正式入口规划：`/admin/dashboard`、`/admin/papers`、`/admin/users` 和后续记录审核页面。
- 静态示例：`index.html`。
- 页面目标：让管理员在公开入库前看清待审核对象、字段差异、影响范围和审核历史。

## 页面区块

1. 顶部说明区：说明“公开前审核”的职责和当前数据范围。
2. 指标条：论文、超导记录、晶体结构、图表可见性四类队列。
3. 审核队列：以表格展示待审核项。
4. 详情面板：展示选中项的提交人、来源、字段差异和审核意见。
5. 批量影响区：批量操作前展示影响范围。
6. 审核历史：展示提交人、审核人、审核时间和审核意见。
7. 操作区：通过、退回、标记待补充。

## 内容规则

- 队列中必须能区分论文审核、结构审核、图表展示控制。
- 逐条记录编辑入口需要清晰标注当前对象类型。
- 尚未完成的批量维护、审核历史和记录编辑能力标注“有待建设”。
- 普通用户不可看到管理员维护入口。

## 验收标准

- 管理员可以清楚区分论文、超导记录、晶体结构和图表控制。
- 批量操作前能看到影响范围。
- 审核历史能追溯提交人、审核人、审核时间和审核意见。
