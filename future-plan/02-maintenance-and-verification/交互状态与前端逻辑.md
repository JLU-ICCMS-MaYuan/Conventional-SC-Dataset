# 02 数据维护与审核：交互状态与前端逻辑

## React/Vite 落地边界

本文描述管理员审核中心的前端状态、事件、权限反馈和 Material 交互表达。不定义具体数据库变更。

## 核心状态

- `queueFilter`：当前队列筛选条件。
- `selectedReviewItem`：当前选中的待审核对象。
- `detailSheetState`：右侧详情或移动端 Bottom Sheet 状态。
- `diffViewState`：字段差异展开状态。
- `batchSelection`：批量选择对象集合。
- `reviewActionState`：审核动作提交中、成功、失败。
- `permissionState`：管理员权限、普通用户、未登录。
- `snackbarState` / `confirmDialogState`：轻量反馈与确认弹窗。

## 主流程

1. 管理员进入审核中心，顶部 Linear Progress 表示加载。
2. 前端加载待审核队列和指标摘要。
3. 管理员点击 Data Table 行，行出现 selected state 并打开 Side Sheet。
4. 右侧详情展示提交内容、字段差异和历史记录。
5. 管理员填写审核意见。
6. 管理员执行通过、退回或待补充。
7. 前端刷新队列和指标摘要，Snackbar 展示结果。

## 批量操作

- 勾选行后显示 Batch Action Bar。
- 批量操作前必须打开 Dialog 展示影响范围。
- 批量结果用 Snackbar + 结果详情 Dialog 表达全部成功、部分成功或全部失败。

## 权限状态

- 未登录用户跳转登录或展示无权限 Banner。
- 普通用户不可看到管理员维护入口。
- 管理员权限失效时，当前操作必须停止并提示重新登录。

## 验收标准

- 所有审核动作都有加载、成功和失败反馈。
- 批量操作不会在未确认影响范围时执行。
- 审核历史在动作完成后可追踪。

## 旧版设计资产融合边界

- 继承旧版 `batchReview`、`batchChartVisibility`、`openEditModal` 等业务动作，但 React/Vite 落地时拆成清晰状态：`selectedRows`、`batchActionState`、`detailSheetState`、`confirmDialogState`。
- demo 使用本地数组模拟审核队列，点击行更新详情，批量操作后用 Snackbar 显示结果。
- 不迁移旧版内联 `onclick`、全局 mutable DOM 查询和脚本级表单拼接。
