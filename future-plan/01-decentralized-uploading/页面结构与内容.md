# 01 去中心化超导数据上传：页面结构与内容

## React/Vite 落地边界

本文只定义页面 JSX 信息结构、区块层级、字段内容和页面文案。视觉 token、组件外观、动效和响应式基线服从根目录 `design.md`。接口字段和后端流程以本目录 `API接口调整方案.md`、`后端优化调整方案.md` 为准。

## 页面承载

- 正式入口规划：`/share`、后续数据提交页，以及 `/compound/:elementSymbols` 的补充上传区域。
- 静态示例：`index.html`。
- 页面目标：让用户明确“一条 `superconductor_records` 是一条完整超导样本”，包含材料、文献、压强、Tc、晶体结构和来源说明。

## Material 页面骨架

1. Top App Bar：显示“超导数据上传”、当前登录状态和帮助入口。
2. Navigation Rail / Drawer：保留七大模块入口，当前模块高亮为上传或分享相关入口。
3. Page Header Surface：说明上传目标、审核后公开入库、提交数据的责任边界。
4. Stepper / Progress Header：用 5 个步骤表示当前记录填写进度。
5. 主工作区：左侧为连续表单 Cards，右侧为 sticky Preview Card。
6. Floating Action Button：用于“新增一条记录”或“继续补充结构”，只保留一个主 FAB。
7. Snackbar / Dialog 容器：承载保存、校验失败、重复结构确认等反馈。

## 页面区块

1. 文献与材料 Card：采集 DOI、论文标题、年份、期刊、化学式、元素组成、数据来源类型。
2. 压强与超导参数 Card：采集压强、Tc、Tc 类型或计算方法、lambda、omega_log、N(Ef)、稳定性字段、计算软件和方法说明。
3. 晶体结构 Card：支持 CIF/POSCAR 上传、结构文本预览、空间群、原子数量、元素列表、晶胞参数和体积。
4. 结构来源 Card：采集 `structure_source_type` 与 `structure_source_label`。
5. 右侧记录预览 Card：展示当前记录摘要、结构解析状态和完整性检查清单。
6. 提交审核 Card：说明记录会进入审核队列，不会直接公开。

## 字段内容

### 文献与材料

- DOI
- 论文标题
- 年份
- 期刊
- 化学式
- 元素组成
- 数据来源类型：实验、理论、外部数据库、用户上传、管理员整理

### 压强与超导参数

- 压强，单位固定为 GPa。
- 临界温度 Tc，单位固定为 K。
- Tc 类型或计算方法。
- lambda、omega_log、N(Ef)、稳定性字段。
- 计算软件和方法说明。

### 晶体结构

- 结构格式：CIF 或 POSCAR。
- 结构文件上传。
- 结构文本预览。
- 空间群符号与空间群编号。
- 原子数量、结构元素列表、晶胞参数、晶胞体积。

### 结构来源

- `structure_source_type`：论文补充材料、论文正文或表格整理、用户上传、管理员整理、外部数据库导入、计算输出、结构预测结果、数据集批量导入、旧表合并来源、来源未知。
- `structure_source_label`：多行说明，提示用户填写 DOI、原始文件名、数据库 ID、压强、空间群和整理说明。

## 页面文案重点

- 不再表达“参数记录”和“结构表”分开管理。
- 明确结构解析成功不等于记录可提交，仍需 DOI、压强、Tc 和来源说明齐全。
- 明确审核状态只针对整条超导记录。

## 验收标准

- 页面结构能让用户理解一条记录同时包含材料、压强、结构、Tc 和超导参数。
- 页面不出现“论文上传”“参数上传”“结构补录”三个割裂流程。
- LaH10 200 GPa 这类样本可以在同一页面完成数据录入和结构来源说明。
