Lesson 01: 先读懂 SC-Wiki RAG 的主链路

学习目标：不是背 RAG 概念，而是能从代码里追踪一个用户问题如何进入系统、被检索、被组织成 prompt，并最终流式返回前端。

1. 先抓住四层结构

这套 RAG 的主链路可以先压缩成四层。读代码时不要一开始钻进细节，先确认自己站在哪一层。

API layer
api/rag.py
Service facade
service.py
RAG engine
rag/engine.py
Frontend stream
useStreamingChat.ts
request -> availability checks -> retrieval/generation -> SSE events

2. 一个问题如何流过系统

用户在前端提问后，请求会进入 /api/rag/chat/stream。API 层只做输入校验、history 格式化和 SSE 包装，然后把问题交给 service.chat_stream()。

service.py 是边界层。它先检查 RAG 数据库、Chroma 向量库和 LLM 配置是否可用；可用后才调用 backend.rag.rag.engine.ask_stream()。

engine.py 是核心。它会判断问题意图：事实型问题走结构化查询，解释型问题走语义检索，两者都有时构造融合 prompt。最后 LLM 生成 token，API 再把这些 token 作为 SSE 事件发给前端。

3. 你现在要记住的文件

  • backend/api/rag.py: 请求入口和 SSE 输出。
  • backend/rag/service.py: 可用性检查和异常边界。
  • backend/rag/rag/engine.py: 意图解析、检索选择、融合、生成。
  • frontend/src/lib/useStreamingChat.ts: 前端如何读取 SSE。

4. 暂时不要急着看的文件

  • ingest/*: 这是数据如何进入 RAG，属于第二阶段。
  • inspiration/*: 探索模式更复杂，等普通问答链路清楚后再看。
  • models/*: 先知道有哪些表，不必一开始逐字段读完。

小练习

不用改代码。请你在代码里找到三处函数，并用一句话说出它们各自负责什么：

  • rag_chat_stream()
  • chat_stream()
  • ask_stream()

如果你能把这三个函数串起来，就已经读懂了 RAG 主链路的骨架。
