# 文献采集与数据入库

## 1. 这是什么业务

这一模块负责把外部文献信息转成数据库中的结构化记录，覆盖单篇上传、DOI 元数据解析、多组物理参数录入、截图上传、批量上传、JSON 导入导出和数据迁移支持。

## 2. 单篇上传流程

### 2.1 入口
- 组合页上传弹窗
- 后端接口：`POST /api/papers/`

### 2.2 基本前提
- 必须登录
- 必须提供 DOI
- 必须指定文章类型和超导体类型
- 必须至少提供一组物理数据

### 2.3 上传步骤
1. 前端收集当前组合页的元素集合
2. 提交 DOI、元素、分类字段、物理数据、截图和备注
3. 后端校验登录态
4. 后端解析 JSON 字符串形式的元素列表与物理数据
5. 后端验证截图数量与图片有效性
6. 后端进行 DOI 有效性校验并尝试抓取元数据
7. 后端获取或创建元素组合
8. 检查该组合下 DOI 是否已存在
9. 生成 APS/BibTeX 引用
10. 创建文献、物理参数和图片记录

## 3. DOI 元数据策略

### 3.1 普通用户
- 必须通过 DOI 校验
- 必须成功拉取元数据，否则上传失败

### 3.2 管理员
- 可跳过严格 DOI 校验
- 如果元数据抓取失败，系统会使用占位信息创建记录

## 4. 物理数据模型

每篇文献可以有多组 `pressure/tc/lambda_val/omega_log/n_ef/s_factor` 数据点。

业务含义：
- 一篇论文可对应多个压强点或多组结果
- `s_factor` 可由后端依据压强与 Tc 自动计算
- 页面展示时按数组形式返回并逐组渲染

## 5. 图片处理

- 最多允许 5 张截图
- 后端会校验图片有效性
- 保存时同时生成压缩图与缩略图
- 页面展示第一张为主图，其余作为缩略图

## 6. 批量上传与导入

### 6.1 首页快速上传
- 入口位于首页
- 接口：`POST /api/papers/batch-upload`
- 接受 `.xlsx`、`.csv`、`.txt`
- 本质上是将文件解析成标准片段后再落库

### 6.2 JSON 导入导出

#### 导出
- 脚本：`python -m backend.export_data`
- 用于将数据库中的文献、物理数据和图片导出为可迁移数据

#### 导入
- 脚本：`python -m backend.import_data <json_path>`
- 支持清空后重新导入
- 导入时会对元素进行标准化过滤

### 6.3 ID 迁移
- 脚本：`python -m backend.migrate_ids`
- 用于为旧组合补齐 `element_id_list`
- 主要目的是提高组合检索和比较效率

## 7. 采集模块与其他模块的关系

- 依赖认证模块控制谁能上传
- 依赖元素组合模块决定文献归属到哪个体系
- 依赖审核模块控制文献后续状态
- 依赖图表模块决定是否在首页展示

## 8. 边界与限制

- 上传不是全文解析流程，当前主要依赖 DOI 元数据和手工补充字段
- 批量导入并不等价于自动高质量清洗，仍依赖输入文件质量
- 导入导出是运维级能力，不等于前端用户常规操作
- 当前系统没有完整的重复合并策略，主要依赖“同组合内 DOI 唯一”
