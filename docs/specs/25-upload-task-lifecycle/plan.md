# 实施计划：多任务上传中心与安全清理生命周期

## 技术方案

在 Python 后端新增专责 `/api/upload-tasks` Router 和任务服务。Redis 使用用户 ZSET 索引及原子事务/Lua 完成创建上限和状态转换；对外状态由 DTO 白名单生成。数据库以 `papers.upload_task_id` 唯一键作为提交幂等与清理保护。前端任务中心只用服务端列表恢复任务。

## 阶段

1. 先编写状态仓库、API、清理竞态和倒计时失败测试。
2. 实现 Redis 索引、状态机、保留策略和公开 DTO。
3. 实现取消、单项/批量清理及 Worker 防复活。
4. 实现前端任务中心、恢复、倒计时和操作保护。
5. 运行 Python、前端及容器契约测试。

## 关键质量门

- 不使用 SCAN 列任务。
- 清理必须 fail-closed：无法证明未提交就不删。
- `cleanup_at` 由服务端计算，客户端只显示。
- 状态转换使用比较并交换或等价原子操作。
