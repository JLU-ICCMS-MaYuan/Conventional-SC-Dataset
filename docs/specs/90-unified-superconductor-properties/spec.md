# Feature 规格：MaterialState 模块化物性与动态表单

**GitHub Issue**：[#90](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/90)

**创建日期**：2026-09-04

**重写日期**：2026-09-07

**状态**：设计已重写，待实施

## 背景与目标

当前科研数据按 `tc_results`、`calculation_contexts` 和 `superconductor_properties` 等底层表拆分，
上传、管理、详情和图表各自理解字段。新增一种方法或方法专属字段时，需要同时修改数据库模型、
接口类型和固定表单，扩展成本高，也容易让同一 `MaterialState` 下不同计算或实验的 Tc 与相关物性
发生错配。

本 Feature 以 `MaterialState` 为科研数据主体，引入可按需挂载的 `property_modules[]`。首批模块为：

- `superconductive_properties`：超导性质；
- `dynamical_properties`：动力学性质；
- `thermodynamical_properties`：热力学性质；
- `electronic_properties`：电子性质。

模块内保存平级 `PropertyRecord`。超导性质模块首批支持 `predicted_tc`、`measured_tc` 和其他超导
物性记录。`predicted_tc`、`measured_tc` 不是上下级分类容器，而是 Tc 记录类型；同一材料状态可有
任意多条不同方法或不同 Conditions 的 Tc。

表单采用版本化 Schema 驱动：定义规定字段、类型、单位、显示条件和提交规则，显示和提交使用同一
版本。核心事实必须稳定检索，方法特有字段必须符合声明的定义；已发布定义不可原地修改，旧记录继续
按原版本解释。

每篇论文保存自己的 `ChemicalSystem`、`Superconductor` 和 `MaterialState`。两篇论文即使都研究
LaH10，也分别拥有材料记录；跨论文检索依赖规范化字段，不依赖共享材料主键。

## 术语

- **物性模块**：挂载在 `MaterialState` 下的一组相关记录，例如超导性质模块。
- **PropertyRecord**：一条具体科学事实，例如“Allen-Dynes 预测 Tc=250 K”。
- **Conditions**：当前记录自带的计算或实验条件集合；不同记录分别保存，允许内容重复。
- **FormDefinition**：动态表单及后端校验所使用的版本化定义。
- **核心字段**：必须稳定查询、排序、关联和审计的固定字段。
- **扩展字段**：由特定记录类型或方法定义、保存在 `payload` 中并受 Schema 校验的字段。

## 用户场景与验收

### 用户故事 1：按需添加物性模块（P1）

贡献者在一个材料状态中只添加论文实际报告的模块，不需要填写空模块。

**验收场景**：

1. LaH10 状态只包含超导和电子性质时，保存并重新打开后只出现这两个模块。
2. 后续添加动力学模块不会改写现有超导记录。
3. 空模块可以直接删除；包含记录的模块必须先显式处理其中记录，不能通过删除模块静默级联删除事实。

### 用户故事 2：录入多条预测和测量 Tc（P1）

同一个 `MaterialState` 可包含不同理论方法和实验方法得到的多条 Tc，每条 Tc 都保留自己的方法、
Conditions、判据、证据和扩展字段。

**验收场景**：

1. `predicted_tc` 使用 Allen-Dynes 且包含本条计算 Conditions 时，显示并校验该定义允许的字段。
2. `measured_tc` 使用电阻测量且包含本条实验 Conditions 时，显示起始转变、零电阻等适用判据。
3. 预测 Tc 填入实验 Conditions，或测量 Tc 填入计算 Conditions 时，正式提交失败并定位到记录。
4. 用户切换记录类型或方法后，不适用字段不能仅在页面隐藏；提交前必须清理、迁移或明确报错。

### 用户故事 3：每条 Tc 自带完整资料（P1）

每条 Tc 独立保存结果、方法、Conditions、适用参数及证据。用户在同一个表单中填写这些内容。
λ、ωlog 会随 k/q 网格及展宽变化，因此随当前 Tc 保存；不同 Tc 可以重复保存相同资料，互不影响。

**验收场景**：

1. LaH10 的 Tc-A 保存 mu_star=0.10，Tc-B 保存 mu_star=0.15；各自的 λ、ωlog、网格、展宽及结果
   往返后保持原样。数值仅用于验证数据归属，不作为公式计算正确性的证据。
2. 复制 Tc-A 后只修改副本的参数或 Conditions，原记录不变；完全相同的两条记录也不自动合并。
3. 不要求先新建独立参数记录或 Conditions 记录；无需输入关联表即可理解一条 Tc。
4. Hc2、能隙等其他物性仍是模块内独立记录，可保存自己的条件；独立报告的 λ 等也可单独录入，
   但不会自动变成某条 Tc 的输入或与它联动。
5. 论文未报告的参数保留缺失，不能根据 Tc 反推补齐；方法适用字段和必填规则由版本化定义决定。

### 用户故事 4：由版本化 Schema 生成和校验表单（P1）

超级管理员可以发布新的表单定义版本来增加方法或扩展字段；历史记录不因新版本发布而失效。
用户自定义性质提升为全站通用性质采用 US7 的管理员直接发布路径，无需超级管理员二次批准。

**验收场景**：

1. `predicted_tc` 定义 v1 和 v2 同时存在，旧记录仍按 v1 展示，新记录默认使用已发布的 v2。
2. 前端按定义显示字段，后端拒绝类型、枚举、单位或条件规则不合法的 `payload`。
3. 已发布定义不能原地修改；修订必须发布新版本。
4. 未知、草稿或已停用且不允许新建的定义版本不能用于新记录。
5. 旧记录升级定义版本必须显式执行，先验证转换结果，不得在读取时静默升级。
6. 已执行的定义升级可以基于升级审计事件回滚到升级前快照；记录或论文 revision 已变化时拒绝过期回滚。

### 用户故事 5：每篇论文拥有独立材料记录（P1）

论文 A 和论文 B 即使都研究 LaH10，也分别保存自己的化学体系、材料和状态。

**验收场景**：

1. 两篇论文可分别创建 LaH10，二者数据库主键不同。
2. 修改、升版或删除论文 A 的 LaH10 不改变论文 B 的记录。
3. 按规范化学式搜索 LaH10 时仍能同时找到两篇论文的数据。

### 用户故事 6：统一上传、管理和公开读取（P2）

上传校对、管理员编辑和论文详情使用同一模块、记录及定义版本契约，下游图表从固定核心字段查询。

**验收场景**：

1. 三个入口对同一论文返回相同模块、记录、Conditions、定义版本和值。
2. Tc 图表仍能按预测/测量、方法和代表记录筛选，结果与详情一致。
3. 旧草稿和旧表数据只在迁移或输入边界转换；新写入不再产生旧结构。

### 用户故事 7：自定义性质审核保留与全站提升（P1）

贡献者可以在已有模块中录入尚未被系统收录的性质名称、值、值类型、单位和证据。管理员可以随论文
审核保留该性质，并独立决定是否提升为全站通用性质定义。

**验收场景**：

1. 用户添加未收录性质，保存草稿、提交并经管理员批准后，详情保留原名称、值、单位和 Evidence；
   未提升为全站定义不影响批准和展示。
2. 普通管理员可将已批准的自定义性质提升为全站通用定义，无需超级管理员二次批准；其他用户随后能
   从相应模块中选择此性质录入新记录。
3. 普通用户无法发布全站定义；管理员提升动作记录操作者、来源论文 revision、源记录快照和目标定义。
4. 同名不同义的论文内性质不自动合并；目标通用代码已存在或源记录在操作中变化时提示冲突，不能覆盖
   现有定义。失败不撤销已经批准的论文数据。
5. 提升只发布定义，源记录与其他历史记录的原始值、证据和定义绑定不被自动改写。

## 边界与异常

- 模块可以为空缺，不为论文未报告的内容创建空记录。
- 空模块可以删除；非空模块删除必须先显式处理其中记录，不能隐式级联删除。
- Conditions 是记录自带的资料，不跨记录共享可变实例；复制记录不建立联动。
- 普通物性可不填 Conditions；预测/测量 Tc 必须包含正确类型的 Conditions 对象，具体字段允许按定义未报告。
- 每条记录只属于一个物性模块，不建立跨模块持久引用；不同 Tc 内参数和条件允许重复。

- 核心字段与 `payload` 不得保存同一事实的两份可冲突副本。
- 草稿可暂存未完成字段；正式提交和批准使用发布定义的完整规则。
- 新批准或编辑后重新批准的记录必须有当前论文 revision 的 Evidence；历史迁移不得伪造 Evidence。
- 定义服务不可用时，已缓存且校验和一致的发布版本可继续读取；不能校验的新写入必须失败。
- 定义停用后允许读取历史记录，但不允许默认用于新记录。
- 自定义性质使用系统已发布的通用录入规则校验，未知性质名称不等于任意未知 Schema 字段；普通用户
  不能借此修改 Tc 专用规则或发布全站定义。

## 功能需求

- **FR-001**：`MaterialState` 必须作为结构、Conditions 和全部物性模块的共同归属。
- **FR-002**：系统必须通过 `property_modules[]` 按需挂载模块；首批支持四个已命名模块代码。
- **FR-003**：模块内记录平级，每条记录只属于一个模块；记录内部可组织条件、参数和补充信息，不建立跨模块记录引用。
- **FR-004**：超导模块必须支持 `predicted_tc`、`measured_tc` 和其他超导物性记录。
- **FR-005**：每条记录必须保存稳定键、模块代码、记录类型、物性代码、原始值、规范值、单位、
  定义键与版本、可选 Conditions、可选结构、`payload` 和 Evidence。
- **FR-006**：系统必须保留数值、范围、文本和布尔值表达，并保证范围完整、单位明确和原文不被覆盖。
- **FR-007**：`predicted_tc` 必须自带计算 Conditions，`measured_tc` 必须自带实验 Conditions，两类互斥。
- **FR-008**：每条记录拥有自己的 Conditions 和参数；允许复制及重复保存，编辑或删除一条不得改变另一条。
- **FR-009**：一条 Tc 必须完整表达当前结果及其已报告输入；λ、ωlog、μ*、k/q 网格与各自展宽按方法适用性保存。
- **FR-010**：不建立 Tc 输入关联表，不依靠共享条件键配对；不同输入或相同输入的记录均不得自动合并。

- **FR-011**：Tc 的结果类型、方法、判据、不确定度和代表标记属于单条记录；结果类型决定允许的方法和
  Conditions 类型。
- **FR-012**：每个“论文 + revision + MaterialState + Tc 记录类型 + 方法”最多一条代表 Tc。
- **FR-013**：前端必须根据 `FormDefinition` 生成字段、选项、单位提示和条件显示。
- **FR-014**：后端必须依据记录绑定的同一 `FormDefinition` 版本校验核心字段与 `payload`。
- **FR-015**：`FormDefinition` 必须包含稳定键、单调递增版本、目标类型、适用模块和记录类型、
  JSON Schema、UI 提示、规则、状态、校验和及审计信息；记录定义必须覆盖内部 Conditions、参数和预设扩展分组。
- **FR-016**：已发布定义不可变；新建记录使用当前发布版本，历史记录继续绑定原版本。
- **FR-017**：定义升级必须显式执行并可预览、验证和基于审计事件回滚；升级或回滚必须执行并发版本
  检查，读取不得自动改写记录版本。
- **FR-018**：核心字段是查询与关联权威；`payload` 只保存定义声明的扩展字段。
- **FR-019**：新方法或新的系统规范字段通过发布定义版本增加；用户在既有预留分组内新增字段按
  FR-041 保留，无需逐次发布定义。需要唯一约束或固定核心语义的字段须纳入核心契约，不能产生第二个可写来源。
- **FR-020**：每篇论文 revision 必须拥有自己的 `ChemicalSystem` 和 `Superconductor`；规范化学式和
  组成唯一约束必须限定在论文 revision 内。
- **FR-021**：论文升版、删除和重写不得影响其他论文拥有的同名材料记录。
- **FR-022**：跨论文检索必须使用规范化学式、组成等检索字段聚合结果，不依赖共享材料主键。
- **FR-023**：统一契约必须使用 `calculation_conditions` 和 `experimental_conditions` 表达两类 Conditions，
  切换完成后不得长期保留两套写入权威。
- **FR-024**：所有物性模块必须使用统一的 `PropertyRecord` 持久化语义，并保留 Tc 的约束与查询能力。
- **FR-025**：当前 Tc 使用的 λ、ωlog、μ* 作为本条记录内结构化参数保存，允许跨 Tc 重复；独立报告的物性可另录，但不要求拆分，不与 Tc 建立输入关联或同步修改。
- **FR-026**：记录与 Evidence 必须属于同一论文 revision；每条进入批准状态的记录至少关联一条 Evidence。
- **FR-027**：上传、管理员编辑和公开详情必须使用同一模块化契约与定义版本。
- **FR-028**：旧 Tc、普通物性、Conditions 字段和旧草稿必须通过可核对、可恢复的迁移或边界适配
  进入新模型；不得长期双写。
- **FR-029**：迁移期间不得丢失、意外重复或暂时隐藏已提交数据；复制到不同 Tc 的参数快照属于预期重复；切换失败时必须能够回到最近经过验证的
  稳定状态。
- **FR-030**：Tc 搜索、图表、审核、升版和删除行为必须完成回归验证。
- **FR-031**：结构记录与物性模块在 `MaterialState` 下平行；物性可选引用本论文 revision 内的结构，
  缺少结构不得阻止非结构必填的记录保存。
- **FR-032**：管理员（含超级管理员）可直接将已批准的自定义性质提升并发布为全站通用性质定义，
  无需二次批准；其余表单定义管理、版本升级和停用沿用超级管理员权限。每次发布、停用和升级必须审计。
- **FR-033**：未知定义版本、Schema 校验失败和不兼容升级必须使用稳定错误码并定位到模块、记录和字段。
- **FR-034**：实现必须为持久化约束、服务接口、动态表单、迁移恢复和跨入口往返提供自动化及端到端
  回归证据。
- **FR-035**：实现完成后必须更新受影响的 Overview，实施前不得把本设计写成当前事实。
- **FR-036**：贡献者必须能在已有模块录入自定义性质名称、数值/范围/文本/布尔值、单位及 Evidence，
  自定义记录使用已发布的通用定义，具有论文内稳定身份。
- **FR-037**：管理员可随论文审核保留自定义性质；批准和公开展示不得以提升为全站定义为前提。
- **FR-038**：管理员可独立决定提升已批准的自定义性质，确认名称、代码、模块、值类型和单位后直接
  发布可供全站新建记录使用的不可变定义，并保存来源与操作审计。
- **FR-039**：提升必须处理重复代码、重复请求和源记录并发变化，不自动合并同名性质、不覆盖已发布
  定义、不静默改写源记录和历史绑定；失败不得影响已批准数据。

- **FR-040**：系统必须支持按 MaterialState 导出完整数据包，包含材料和状态信息、结构、全部模块记录、
  每条 Tc 的条件及参数、证据内容与定位、所用定义版本；使用者无需另取关系表或联网查询才能解释数据。
- **FR-041**：用户只能在定义预留的分组中新增字段；创建位置固定字段的所属模块、记录和分组。
  字段名称、类型、单位、值及证据随论文审核后长期保留，未经全站发布不自动成为其他记录的字段。

## 关键实体

- **PaperRevision**：论文当前内容版本，是本次科研数据快照的根。
- **ChemicalSystem**：属于一篇论文 revision 的元素体系。
- **Superconductor**：属于一篇论文 revision 的材料记录，不跨论文共享主键。
- **MaterialState**：一篇论文中某材料在特定压力、温度和报告结构下的研究状态。
- **PropertyModule**：挂载在材料状态下的模块实例。
- **PropertyRecord**：模块中的一条科学事实。
- **CalculationCondition / ExperimentalCondition**：记录内部的计算或实验条件资料，不是跨记录共享节点。
- **FormDefinition**：不可变、版本化的动态表单与校验定义。
- **PaperEvidence**：论文原文及定位；通过统一连接表关联记录。

## 成功标准

- **SC-001**：固定样例中的四个模块均可独立添加、删除和往返保存，未添加模块不会生成空数据。
- **SC-002**：两条自带参数与条件的预测 Tc 和一条测量 Tc 往返后资料 100% 保留；复制后修改任一条，其他记录不变。
- **SC-003**：预测/测量类型与 Conditions 错配、同方法双代表、记录内参数类型或单位错误均被所有写入入口拒绝，
  并返回相同稳定错误码。
- **SC-004**：同一记录定义 v1/v2 并存时，100% 的历史记录仍按原版本读取，新记录使用当前发布版本。
- **SC-005**：动态表单显示规则与后端校验对统一测试矩阵的结果 100% 一致。
- **SC-006**：论文 A、B 分别保存 LaH10，修改或删除任一论文后另一论文的记录及查询结果不变。
- **SC-007**：迁移前后 Tc 及普通物性数量、核心值，以及按来源和目标 Tc 展开的 Conditions、参数及 Evidence 逐项一致，静默遗漏为 0。
- **SC-008**：上传、管理和详情返回的模块、记录、定义版本、核心值及关联 100% 一致。
- **SC-009**：Tc 图表和搜索的代表数据点、方法分类、值与迁移前一致，基准数据集的查询性能不低于
  迁移前基线。
- **SC-010**：旧 Conditions 和参数均可追溯到目标记录内快照；共享旧条件按使用记录复制，无引用旧资料被明确保留或列为阻断异常，目标环境只保留一套写入权威。
- **SC-011**：固定验收数据集中，合法输入均可保存并跨入口往返；非法输入均被拒绝且无部分数据写入，
  各恢复演练后已提交事实与检查点逐项一致。
- **SC-012**：定义升级预览与应用结果一致；应用后可依据升级事件恢复升级前版本和数据，过期应用或
  回滚请求 100% 被拒绝且不产生部分写入。
- **SC-013**：四种值类型的自定义性质经草稿、提交、管理员批准、详情往返后名称、值、单位和证据
  100% 保留，不提升也能公开展示。
- **SC-014**：普通管理员无需超级管理员介入即可发布提升定义，并由另一用户选择录入；普通用户发布
  请求全部被拒绝，冲突和重试不覆盖定义、不重复发布、不改写历史记录。

- **SC-015**：单个 MaterialState 导出后断开数据库，仍能读取全部记录、参数、条件、结构和证据，
  按包内原定义版本解释字段；不存在需外查的科学数据关系。
- **SC-016**：在 Tc 参数预留分组新增字段，审核后往返和导出均保留原分组、类型、单位和值；越组、
  覆盖系统键和非法类型被后端拒绝，其他 Tc 不被修改。

## 假设与依赖

- 依赖 #33 的论文 revision 与 Evidence 血缘、#76/#78 的共享编辑入口和 #84 的 Tc 规则。
- 首批四个模块代码由系统内置；新增模块仍需发布定义和注册展示信息，不执行运行时代码插件。
- JSON Schema 使用项目支持的受限子集；不允许定义执行任意脚本。
- Conditions 和输入参数归当前记录所有；本 Feature 不建立 Tc 输入关系表或共享条件组 ID。
- MaterialState 的压力、温度和报告空间群继续保存在状态本身。

## 范围外事项

- 不实现可执行代码插件或第三方插件市场。
- 不建设完整物性本体、自动单位换算引擎、张量或曲线专用模型。
- 不跨论文共享或自动合并 `ChemicalSystem`、`Superconductor`、`MaterialState`、物性或 Evidence。
- 不自动判断不同论文中的材料、结构或结果是否科学等价。
- 不在迁移中补造历史论文不存在的 Evidence。

## 澄清记录

### 2026-09-07

- 问：科研数据的主体是什么？→ 答：`MaterialState`，物性模块和 Conditions 均归属于它。
- 问：物性如何扩展？→ 答：通过可按需挂载的模块和版本化 `FormDefinition` 扩展。
- 问：Tc 如何表达？→ 答：超导模块内使用 `predicted_tc` 或 `measured_tc`，自带正确类型的 Conditions。
- 问：Tc 与 lambda、omega_log、mu_star 等如何对应？→ 答：采用用户确认的图二，参数随每条 Tc 保存，允许重复。此前共享条件键方案已撤销。
- 问：新方法字段如何加入？→ 答：核心字段固定，方法特有字段进入受 Schema 校验的 `payload`；定义发布新版本，
  已发布版本不可原地修改。
- 问：不同论文的 LaH10 是否共用材料记录？→ 答：否。每篇论文 revision 保存自己的材料记录，搜索时再按
  规范化字段聚合。
- 问：计算和实验条件使用什么名称？→ 答：统一契约分别使用 `calculation_conditions` 和
  `experimental_conditions`，中文统一称 Conditions（条件）。

### 2026-09-07 审查修订

以下为本轮完善采用的工程决策，不记录为新的用户访谈答复。

- 输入相同的重复记录不自动合并；此前 Conditions 身份和同组规则设计已由下述图二决定取代。
- 升级前保存审计快照；回滚必须显式指定升级事件并通过论文 revision
  和记录校验和检查，不能覆盖后续编辑。
- 每条记录只有一个所属模块，本 Feature 不增加跨模块关联模型。

### 2026-09-07 自定义性质权限澄清

- 用户确认：“管理员就能决定是否进一步提升为全站通用性质定义”。
- 自定义性质随论文审核保留；提升为独立可选动作，由管理员直接完成，不要求超级管理员再次批准。
- 发布全站定义不自动转换已经保存的自定义记录，避免影响历史数据和既有审核结果。

### 2026-09-07 每条 Tc 自带资料的最终确认

- 用户选择图二：每条 Tc 保存自己的结果、方法、Conditions、λ、ωlog、μ*、网格、展宽及证据，参数允许重复。
- 取消强制独立参数记录、共享 Conditions 配对、输入关联表和组级校验；统一 `property_records`、
  `superconductive_properties` 模块及版本化动态表单保留。
- Conditions 名称保留，实例改为记录内部资料；旧表迁移后退役，不再要求建立两个同名目标条件表。
- MaterialState 导出直接包含完整资料；用户新增字段的位置必须限定在预设分组内。
