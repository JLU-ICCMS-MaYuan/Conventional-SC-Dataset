# Feature 规格：统一材料状态的超导物性记录

**GitHub Issue**：[#90](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/90)

**创建日期**：2026-09-04

**状态**：已确认，待实施

## 背景与目标

当前系统在同一个材料状态下分别暴露 `tc_results`、`calculation_contexts` 和
`properties`。Tc 被视为独立结果，λ、ωlog、μ* 被视为计算上下文字段，DOS、Hc2、
超导能隙和 energy above hull 等才被称为“普通物性”。这种结构把数据库存储方式泄漏成了
领域分类，容易产生“哪些量才算超导物性”的无效争论，也让上传、管理、详情和搜索各自拼装
同一批科学数据。

本 Feature 在 `MaterialState` 下建立唯一、平级的 `SuperconductorProperties[]`：Tc、λ、
ωlog、μ*、DOS、Hc1/Hc2、超导能隙、临界电流、穿透深度、相干长度和稳定性等都作为
`SuperconductorPropertyRecord`。不再建立 `TcRelated`、`OtherProperties` 或
`UncontextualizedProperties`。同一次计算或实验产生的记录通过共同 Context 保持关系，
但 Context 不再代替物性记录保存 λ、ωlog、μ*。

统一的是领域模型、草稿和接口契约。Tc 仍保留方法、理论/实验互斥、代表结果唯一等专用
校验；底层可继续使用专用表，不要求为了概念统一而把所有字段塞进一张宽表。

`StructureModels[]` 与 `SuperconductorProperties[]` 在 `MaterialState` 下保持平行。物性记录
通过可选的 `structure_ref` 关联全局规范结构身份；用户没有上传结构、无法确认结构或选择跳过
候选时，`structure_ref` 可以为空，不因此拒绝物性记录。录入物性时，系统可根据化学式、压强、
空间群和结构计算方法检索已公开的结构候选，并由用户确认是否建立关联。

完整结构以 [data-model.md](data-model.md) 为权威定义，并在 Issue #90 正文中同步展示。

## 用户场景与验收

### 用户故事 1：在一个列表中校对全部物性（优先级：P1）

贡献者希望在一个材料状态下连续查看和编辑全部物性，不需要先判断某个量属于 Tc、计算参数
还是“其他普通物性”。

**优先级理由**：这是上传和管理员编辑的主路径，也是本 Feature 消除错误分类的直接价值。

**独立验收**：打开包含 Tc、λ、ωlog、DOS、Hc2 和超导能隙的材料状态，页面只显示一个
平级物性列表；保存并重新打开后记录名称、值、单位和顺序完整保留。

**验收场景**：

1. **假如**论文报告 Tc、Hc2 和超导能隙，**当**解析草稿进入校对页，**那么**三条记录在同一个 `SuperconductorProperties[]` 中平级显示。
2. **假如**用户新增 DOS 或自定义物性，**当**保存草稿，**那么**不需要选择 `OtherProperties` 等上层分类。
3. **假如**某条物性没有明确计算或实验上下文，**当**用户保存，**那么**该记录仍被保留且 Context 为空。

### 用户故事 2：保持同一次计算或实验的数据对应关系（优先级：P1）

研究者希望平级展示不会破坏参数之间的对应关系。例如同一论文在 μ*=0.10 和 μ*=0.15
下给出两个不同 Tc 时，系统必须知道每组数据来自哪一次计算。

**优先级理由**：解除类别分组后，如果丢失 Context，平级数据将无法被科学解释。

**独立验收**：建立两个计算 Context，每个 Context 分别关联一条 μ* 和一条 Tc；保存、读取
和再次编辑后，两个 μ*—Tc 对应关系不交换、不合并。

**验收场景**：

1. **假如**计算 A 报告 μ*=0.10、Tc=250 K，计算 B 报告 μ*=0.15、Tc=220 K，**当**往返保存，**那么**四条物性保持平级且仍按 A/B 正确关联。
2. **假如**同一实验同时报告 Tc、Hc2 和超导能隙，**当**读取详情，**那么**三条记录可以关联同一个实验 Context。
3. **假如**两个记录声明同一个 Context 但上下文内容冲突，**当**提交，**那么**系统拒绝请求并指出冲突记录，而不是任意覆盖。

### 用户故事 3：保持 Tc 专用科学约束（优先级：P1）

审核者希望 Tc 虽然与其他物性平级，但既有的实验/理论方法规则和代表结果规则不被削弱。

**优先级理由**：#84 已经通过应用层和 MySQL 约束解决实验 Tc 残留计算参数问题，统一模型
不能造成回退。

**独立验收**：实验 Tc 只能关联实验 Context，非实验方法 Tc 只能关联计算 Context；同一论文
revision、材料状态和 Tc 方法最多一条代表结果。

**验收场景**：

1. **假如**一条 Tc 的 `tc_method=experimental`，**当**它关联计算 Context，**那么**保存失败并返回字段级错误。
2. **假如**一条 Tc 使用 Allen-Dynes 方法，**当**它没有计算 Context 或关联实验 Context，**那么**保存失败。
3. **假如**同一材料状态和 Tc 方法已有代表结果，**当**再提交第二条代表结果，**那么**请求被拒绝。

### 用户故事 4：统一只读详情和下游展示（优先级：P2）

读者希望论文详情、探索页和社区页看到与校对页相同的物性集合，不再由页面分别读取三种
旧来源。

**优先级理由**：读取统一是领域契约完成闭环的必要条件，但可以在写入和约束稳定后实施。

**独立验收**：同一论文经上传页和管理端保存后，公开详情、探索页和社区页得到相同的记录
数量、名称、值、单位和 Context 关系；Tc 图表数值保持不变。

**验收场景**：

1. **假如**材料状态有 8 条平级物性，**当**分别打开上传校对、管理编辑和公开详情，**那么**三个入口均识别同一 8 条记录。
2. **假如**旧详情响应仍含 `tc_results`、`calculation_contexts` 和 `key_properties`，**当**兼容边界读取它，**那么**转换为统一列表且不重复 λ、ωlog、μ*。
3. **假如**社区 Tc 图表继续直接查询 `tc_results`，**当**统一结构上线，**那么**图表结果与统一详情中的代表 Tc 一致。

### 用户故事 5：录入物性时复用已有结构（优先级：P1）

贡献者在录入物性时可能没有结构文件，或不知道应选择哪一个结构。系统应在已填写的材料条件
足够时检索数据库中的已公开结构，并允许多个物性记录引用同一个结构身份。

**优先级理由**：结构不是每条物性的必备输入，但一旦已有可信结构，复用同一个引用可以避免
重复上传和不同物性之间的结构错配。

**独立验收**：同一材料状态下的多条物性可以写入相同的非空 `structure_ref`；无结构或跳过
候选时仍能保存 `structure_ref=null`；候选查询只返回已批准论文当前 revision 的结构，确认前
不改变物性数据。

**验收场景**：

1. **假如**用户填写化学式、压强、空间群和结构计算方法，**当**系统找到一个或多个匹配候选，
   **那么**页面显示候选的结构引用、条件、来源论文和压强差，并提示用户是否关联。
2. **假如**用户确认候选，**当**保存多条物性，**那么**这些记录的 `structure_ref` 相同，且
   每条记录仍属于自己的论文 revision；系统不复制或转移候选结构的 Evidence。
3. **假如**没有候选、候选距离相同或用户选择跳过，**当**保存物性，**那么**记录保持合法且
   `structure_ref` 为空，不自动创建或猜测结构身份。
4. **假如**同一材料条件存在多个候选，**当**用户未明确选择其中一个，**那么**系统只展示候选
   不写入关联；已存在的明确 `structure_ref` 不被查询结果覆盖。

### 边界与异常场景

- 同一 `property_code` 可以在不同 Context 下出现多次，不得仅按名称去重。
- 同一 Context 可以关联多条物性；Context 不得跨材料状态、论文或 revision 复用。
- Context 可为空，不因此创建单独的“无上下文物性”类别。
- 每条记录至少保留原始值；数值、范围、文本和布尔值均可表达，范围必须成对且下界不大于上界。
- λ、ωlog、μ* 作为平级记录时不得同时保留为新写入 `CalculationContext` 的权威字段。
- 旧 Context 中已有 λ、ωlog、μ* 时，迁移不得静默丢失或编造 Evidence。
- Tc 的原始值、规范 K 值、区间和不确定度必须能无损映射到统一值结构。
- 物性可直接关联结构；如果同时通过 Context 关联结构，两者必须一致。
- Evidence 不得跨论文或 revision；新建或编辑后进入批准状态的记录必须满足既有证据门槛。
- 旧草稿只在系统边界转换；内部业务逻辑和新响应不得长期维护两套并行事实来源。
- `StructureModels[]` 与 `SuperconductorProperties[]` 是平行集合；`structure_ref` 可空，且多个
  物性可以共享一个全局规范结构身份。
- 结构候选只从已批准论文的当前 revision 查询。查询条件使用标准化化学式、空间群精确匹配、
  压强绝对差不超过 `0.01 GPa`，以及已填写的结构计算方法字段精确匹配；候选按压强差从近到远排序。
- 结构计算方法匹配使用 `geometry_method`、`calculation_code`、`exchange_correlation`、
  `nuclear_treatment` 的标准化组合；未填写的字段不作为筛选条件。
- 候选提示是非阻断的，只有用户明确确认后才设置 `structure_ref`；没有候选、用户跳过或最近
  候选距离相同均保留空引用。
- 全局规范结构身份只由标准化化学式、规范压强、空间群和方法组合确定，不以几何等价性自动合并；
  每个身份必须保留至少一个已公开的来源 `StructureModel`。

## 需求

### 功能需求

- **FR-001**：系统必须在每个 `MaterialState` 下提供唯一的 `SuperconductorProperties[]` 平级集合。
- **FR-002**：系统不得在统一结构中建立 `TcRelated`、`OtherProperties`、`NonTcProperties` 或 `UncontextualizedProperties` 等互斥上层分组。
- **FR-003**：每条 `SuperconductorPropertyRecord` 必须具有物性标识、原始值、规范值、单位、可选的结果方法与判据、可选 Context、可选结构关系和 Evidence 集合。
- **FR-004**：系统必须通过 `property_code` 表达 Tc、λ、ωlog、μ*、DOS、Hc2、超导能隙及可扩展物性，不得依赖记录所在分组判断语义。
- **FR-005**：λ、ωlog、μ* 必须作为独立 `SuperconductorPropertyRecord`，不得作为新写入 `CalculationContext` 的物性值字段。
- **FR-006**：系统必须允许 Context 为空，并在同一平级列表中保留无明确 Context 的物性。
- **FR-007**：系统必须允许多条记录关联同一个计算或实验 Context，并保证上下文关系在保存、读取和编辑往返后稳定。
- **FR-008**：客户端使用的 Context 关联键不得等同于数据库主键；界面不得要求用户直接输入或管理 `calculation_context_id`、`experimental_context_id`。
- **FR-009**：同一 Context 键出现多份内容时必须完全一致；冲突时必须返回可定位到具体物性记录的校验错误。
- **FR-010**：Context、物性和 Evidence 必须属于同一论文、revision 和材料状态；论文内的
  `StructureModel` 与其 Evidence 仍遵守该归属，全局 `structure_ref` 可以被多个论文引用。
- **FR-011**：每条物性最多关联一个计算 Context 或一个实验 Context，两类 Context 不得同时关联。
- **FR-012**：`property_code=tc` 时，系统必须继续保存并校验 `tc_method`、自定义方法、不确定度和代表结果标记；`result_kind` 只能由 `tc_method` 推导，不得成为第二个写入权威。
- **FR-013**：`tc_method=experimental` 必须且只能关联实验 Context；其他已知 Tc 方法必须且只能关联计算 Context；`unknown` 只允许兼容读取或草稿暂存，正式提交前必须明确。
- **FR-014**：每个“论文 + revision + 材料状态 + Tc 方法”最多一条代表 Tc。
- **FR-015**：`superconductor_kind` 只负责论文分类，不得控制单条 Tc 的方法、字段或 Context。
- **FR-016**：每条物性必须拥有独立 Evidence 集合；Evidence 连接必须遵守 #33 的论文 revision 血缘。
- **FR-017**：系统必须同时保留论文原始名称、值和单位以及可空规范值，不得用规范化结果覆盖原文。
- **FR-018**：上传解析、上传草稿保存、上传提交和管理员科学数据重写必须使用同一规范化入口。
- **FR-019**：上传校对页和管理端编辑页必须复用同一个平级物性编辑组件和字段校验。
- **FR-020**：论文详情 API 必须按材料状态返回统一物性列表，详情、探索和社区页面不得自行拼装 Tc、计算参数和普通物性。
- **FR-021**：系统必须在读取边界兼容旧 `tc_results`、`calculation_contexts`、`experimental_contexts`、`properties` 和顶层 `key_properties`，并去除转换产生的重复记录。
- **FR-022**：新草稿保存和新详情响应必须只输出统一契约；旧结构不得继续作为第二写入目标。
- **FR-023**：上传状态或分段解析缓存契约变化时必须递增对应 schema version，旧缓存不得冒充新结构。
- **FR-024**：持久化适配层必须把统一 Tc 记录写入 Tc 专用存储，把其他物性写入通用物性存储，并统一读回 `SuperconductorPropertyRecord`。
- **FR-025**：既有 λ、ωlog、μ* 数据迁移必须可重复执行、可核对数量、可回滚且不得编造 Evidence；无法恢复 Evidence 的历史记录必须显式报告。
- **FR-026**：Tc 检索和图表可以保留专用查询，但其值选择、公开 revision 和方法规则必须与统一领域投影一致。
- **FR-027**：论文物理删除、升版重审和批准公开流程必须覆盖统一物性映射后的全部底层实体。
- **FR-028**：系统不得在本 Feature 中建立互斥的物理学分类树；新增物性通过定义目录扩展，不要求修改上层结构。
- **FR-029**：实现必须提供 Python、Go、前端和真实 MySQL 迁移/约束回归测试。
- **FR-030**：实现完成后必须更新受影响的 Overview，且不得在实现前把本 Spec 写成当前事实。
- **FR-031**：结果专属的 `method_raw` 和 `criterion` 必须属于单条物性记录；Context 只保存可被多条记录共享的计算或实验条件，不得保留 Tc 专属判据所有权。
- **FR-032**：`MaterialState` 必须同时暴露平行的 `StructureModels[]` 与 `SuperconductorProperties[]`；物性
  的 `structure_ref` 可为空，不得因为缺少结构而拒绝物性草稿或提交。
- **FR-033**：`structure_ref` 必须是系统生成的不透明全局引用，指向独立的规范结构身份；各论文的
  `StructureModel` 保留自己的来源、Evidence 和 revision，并可映射到同一规范身份。
- **FR-034**：物性录入界面必须在化学式、压强、空间群或结构计算方法变化后，按查询条件检索已批准
  论文当前 revision 的结构候选；查询至少支持标准化化学式、压强、空间群和方法组合。
- **FR-035**：候选匹配必须使用标准化化学式、空间群精确匹配、压强绝对差 `<=0.01 GPa`，以及已填写
  的 `geometry_method`、`calculation_code`、`exchange_correlation`、`nuclear_treatment` 精确匹配。
- **FR-036**：候选必须按压强差升序返回并包含来源和匹配字段；多个候选、最近距离相同或无候选时，
  系统不得自动设置 `structure_ref`。
- **FR-037**：用户明确确认候选后，多条物性和可选 Context 才能写入相同 `structure_ref`；跳过、清空
  或无法确认时必须继续允许保存空引用。
- **FR-038**：全局规范结构身份不得把不同论文的物性、Context 或 Evidence 合并为同一条记录；它只
  共享结构引用，且至少关联一个已公开的来源 `StructureModel`。
- **FR-039**：当物性直接引用结构且 Context 也引用结构时，两者必须指向同一个全局 `structure_ref`；
  本地来源模型若存在，必须映射到该身份。

### 关键实体

- **MaterialState**：论文当前 revision 中特定材料、压力、温度和报告结构条件下的状态，是结构和全部物性的共同归属。
- **SuperconductorPropertyRecord**：平级物性记录。Tc 与其他物性共享身份、值、Context、结构和 Evidence 语义；Tc 仅增加专用校验字段。
- **PropertyDefinition**：非 Tc 物性的规范代码、显示名、规范单位和值类型目录。它是可扩展词典，不是互斥物理学分类树。
- **PropertyContext**：一次计算或实验的共享条件集合，可被同一材料状态下多条物性共享。λ、ωlog、μ* 及单条结果自己的方法/判据不属于 Context 自身。
- **StructureModel**：真实结构文本及其派生信息。物性可直接或经 Context 引用它。
- **CanonicalStructureIdentity**：跨论文共享的规范结构身份，使用系统生成的不透明 `structure_ref`
  和四项条件定位；不承载某篇论文独有的 Evidence。
- **PaperEvidence**：来自论文当前 revision 的原文证据；通过记录级关系连接到每条物性。

## 成功标准

- **SC-001**：同一材料状态中的 Tc、λ、ωlog、μ*、DOS、Hc2、超导能隙和 energy above hull 100% 通过一个平级集合往返保存，无分组字段。
- **SC-002**：包含两个计算 Context 的 μ*—Tc 配对测试在保存、读取、管理员重写后 100% 保持原对应关系。
- **SC-003**：实验 Tc 错连计算 Context、理论 Tc 错连实验 Context、同方法双代表 Tc 三类非法请求均被应用层和数据库层拒绝。
- **SC-004**：上传页、管理端和详情页对同一测试论文返回的物性记录数量、代码、值、单位及 Context 键 100% 一致。
- **SC-005**：旧契约样本转换后不丢记录且不重复 λ、ωlog、μ*；再次保存只产生统一契约。
- **SC-006**：迁移前后的 Tc 数量及非空 λ、ωlog、μ* 数量逐项相等；无法恢复 Evidence 的历史项全部进入迁移报告，静默遗漏数为 0。
- **SC-007**：Tc 检索与两张社区图表的既有代表数据点数量和值保持不变。
- **SC-008**：Python、Go、Vitest、TypeScript 构建和隔离 MySQL 迁移/回滚验证全部通过。
- **SC-009**：结构候选查询对标准化化学式、`0.01 GPa` 压强容差、空间群和方法组合的匹配结果稳定；
  未满足条件的结构不会出现在候选中。

  `structure_ref=null` 的记录保存成功率为 100%。
- **SC-011**：跨论文候选只来自已批准当前 revision，候选确认不复制来源 Evidence，来源论文删除/升版

## 假设与依赖

- 父 Epic 为 #11。
- 依赖 #32 的材料状态、专用 Tc、Context 和 Evidence 基础 Schema，但部分替代其上层领域解释。
- 依赖 #33 的 revision/Evidence 血缘、#76/#78 的共享编辑和管理入口、#84 的 Tc 方法不变量。
- #46 和 #52 虽仍为 OPEN，但本地已有实现作为迁移基线；本 Feature 不将其协作状态擅自视为已关闭。
- #80 已关闭；其论文级分类所有权保留，但单条 Tc 字段规则以较新的 #84 为准。
- 数据量以单篇论文少量材料状态、每个状态数十条物性为主，嵌入 Context 不构成容量瓶颈。
- 新 Feature 采用一次性内部契约切换加边界兼容，不长期维护双写。
- 跨论文结构复用通过新增全局规范结构身份实现；既有 `StructureModel` 继续按论文 revision 保留，
  不能直接跨论文复用其数据库主键。
- 候选查询只读已批准论文当前 revision；待审核、拒绝和草稿结构不参与推荐。
- 压强候选采用绝对差 `<=0.01 GPa`，以压强差最近者优先；距离相同不自动归并，用户必须明确选择
  或保留空引用。
- 全局身份的规范键只使用标准化化学式、规范压强、空间群和方法组合，不自动比较或合并结构几何。

## 范围外事项

- 不把 `tc_results`、Context 表和 `superconductor_properties` 强制合并为一张宽表。
- 不仅为了命名统一而重命名现有数据库表。
- 不恢复旧 `superconductor_records` 或 `key_properties` 表。
- 不改变 Material family、Superconductor type、More type labels 和结构模型的既有所有权。
- 不建设完整的物性本体、单位换算引擎、张量/曲线数据模型或跨论文物性数据去重；结构身份只在
  用户确认候选后共享引用。
- 不在本 Feature 中补造历史论文不存在的 Evidence。
- 不改变 Tc 图表产品交互和 Tc 字段选项。

## 澄清记录

### 2026-09-04

- 问：Tc 是否属于 `SuperconductorProperties`？→ 答：是。底层专用存储不改变领域归属。
- 问：是否建立 `TcRelated` 与 `OtherProperties`？→ 答：否。DOS、Hc2、超导能隙等无法被合理定义为“其他”或“非超导”物性。
- 问：是否把 Tc 的理论参数继续嵌套在 Tc 下？→ 答：否。Tc、λ、ωlog、μ* 等全部是平级物性记录。
- 问：解除分组是否同时删除计算/实验对应关系？→ 答：否。多条平级记录仍可共享 Context，否则不同 μ* 下的 Tc 会失去对应关系。
- 问：实验判据属于共享 Context 还是单条结果？→ 答：属于单条物性记录；Context 只保存可共享的样品、仪器、软件、网格和外场等条件。
- 问：没有 Context 的物性放在哪里？→ 答：仍放在同一个平级集合中，Context 为空，不创建专用类别。
- 问：是否物理合并所有数据库表？→ 答：否。统一领域契约和物理存储归一化是两个问题；本 Feature 保留 Tc 专用约束和查询能力。

### 2026-09-05

- 问：`StructureModels[]` 与 `SuperconductorProperties[]` 是否平行，结构是否允许为空？→ 答：是。
  物性使用可选 `structure_ref`，没有结构或不知道结构时保留空引用。
