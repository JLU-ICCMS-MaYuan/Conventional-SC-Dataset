# 功能规格：管理端论文列表字段可读编辑

**GitHub Issue**：[#95](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/95)
**创建日期**：2026-09-08
**状态**：已确认实施（用户明确授权建立 Issue、Spec、实现与测试）

## 背景与目标

管理端论文编辑页直接展示保存列表用的中括号、引号，要求管理员手写数据格式。
目标是沿用上传页的阅读体验：作者为标签，关键词、研究方法为每行一项的文本。

## 用户场景与验收

### US1：查看并编辑作者（P1）

管理员和超级管理员打开论文后直接阅读姓名，增删作者并保存。
优先级理由：解决截图中的直接困扰。独立验收：修改作者并重开页面检查列表。

1. 假如论文作者为列表，当打开编辑页，那么显示独立姓名标签，不显示列表包装符号。
2. 假如输入一个新姓名，当按 Enter、离开输入框或直接保存，那么新姓名被完整保留。
3. 假如姓名含逗号、中文或括号，当编辑保存，那么姓名不会被这些字符拆开。
4. 假如删除作者，当保存并重开，那么删除结果保留，顺序与输入一致。

### US2：查看并编辑关键词与研究方法（P1）

两种管理员可在多行框编辑关键词和研究方法，无需维护数据格式。
独立验收：分别增改、删除、清空两字段并重新打开检查。

1. 假如字段包含多个条目，当打开编辑页，那么每项独占一行，不展示列表包装。
2. 假如编辑多行内容，当保存并重新打开，那么条目顺序、内部标点正确保留。
3. 假如全部清空，当保存并重新打开，那么保持空字段。

### 边界与异常场景

- 数组、JSON 文本数组、普通文本、空字符串及空值均可阅读。普通文本作为一项，不按逗号猜测分项。
- 不删除内容本身合法的引号和括号，例如材料 [FeSe]。
- 未编辑字段不因展示适配而被静默改写；数组输入保存时转换为后端文本列形式。
- 保存失败保留当前输入，显示已有错误提示，可重试。
- 空白新作者不新增；相同新作者不重复新增；已有作者顺序保留。

## 功能需求

- **FR-001**：两种管理员看到的作者均为可删除标签，支持完整姓名新增。
- **FR-002**：关键词和研究方法均提供每行一项的多行编辑区。
- **FR-003**：支持已有列表、文本及空值形态，不暴露列表包装，不误删内容符号。
- **FR-004**：保存、重载、清空保持条目顺序与内部标点；未编辑原值不被改写。
- **FR-005**：作者未确认输入在直接保存时不丢失，保存失败后输入可恢复和重试。

## 关键实体

论文的作者、关键词与研究方法均是有序文本列表；它们属于论文元数据，与材料状态物性记录独立。

## 成功标准

- **SC-001**：两种管理员的三字段均可读，无需编辑列表包装符号。
- **SC-002**：新增、删除、清空及未按 Enter 直接保存的内容，在验证重载中全部保持预期值。
- **SC-003**：原有论文元数据编辑、科学数据两段保存回归测试和前端类型检查通过。

## 假设与依赖

- 两种角色共用现有独立编辑页与保存接口。
- 用户“与上传页一样好看”采用上传页已有控件形式，不复制其逗号切分造成的内容歧义。
- 此次为现有页面展示与输入适配缺失，不需要数据迁移或新服务。

## 范围外事项

权限、审核语义、科学数据、数据库结构、作者通讯/共同第一作者角色管理和上传页改造。
