# 技术决策：论文历史版本名称

## 决策 1：保持管理员权限链

- 决策：复用前端 RoleRoute 和 Go 的 AuthRequired、AdminRequired。
- 理由：当前历史入口只在 AdminPage，生产路由组已拒绝普通用户。重复添加权限分支会造成规则漂移。
- 备选方案：单独创建版本接口；没有新的读取需求，故不采纳。
- 证据：`frontend/src/LazyRoutes.tsx`、`goserver/main.go`、`goserver/middleware/auth.go`。

## 决策 2：在展示层组合名称

- 决策：名称只由当前事件字段组合；本地时区、分钟精度与已有页面日期展示一致。
- 理由：`paper_history_events` 已保存不可变操作者、审核意见、时间与版本号；不需要新增列、迁移或读取当前用户资料。
- 备选方案：数据库持久化名称或接口新增版本名；会引入冗余及语言、时区歧义，故不采纳。
- 证据：`goserver/handlers/paper_history_read.go`、`frontend/src/pages/AdminPage.tsx`。

## 决策 3：区分事件类型与缺失值

- 决策：保留事件类型标题和评论正文；审核空评论使用现有“未填写审核意见”，上传/修改名称尾部用事件类型；未知日期与审核人用本地化提示。
- 理由：非审核动作没有审核人，不能伪造审核事实；长文本只在名称中折叠空白并允许换行，正文保持可追溯。
- 备选方案：为未审核事件跨版本寻找最近审核人；会把其他事件的事实误归属当前动作，故不采纳。
