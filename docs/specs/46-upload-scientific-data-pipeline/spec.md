# Feature 规格：论文上传科学数据结构化

**GitHub Issue**：[#46](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/46)

**创建日期**：2026-08-24

**状态**：已确认，实施中

## 背景与目标

论文上传已经能从全文提取 Tc、压力、空间群和电子-声子参数，但草稿仍使用扁平
`key_properties`。压力常被写入 `condition.pressure` 而页面只读取
`pressure_gpa`；空间群会与材料名混写；λ 和 ωlog 只能成为普通物性。更严重的是提交端仍按
旧表字段构造 `KeyProperty`，与 #32 已落地的新科学 Schema 不兼容。

本 Feature 将上传主链路切换为“材料状态—报告空间群—理论/实验上下文—Tc/普通物性”的
草稿与入库契约。无原文证据的值保持空白，不根据材料名或常识猜测。

## 用户场景与验收

### 用户故事 1：核对材料状态和压力（优先级：P1）

研究者希望 AI 已提取的压力直接显示在对应材料状态中，并能修正后提交。

**独立验收**：输入 `condition.pressure=300 GPa` 的旧草稿，页面显示 300，保存后使用新
材料状态契约。

**验收场景**：

1. **假如**旧草稿把压力保存为数字或 `{value, unit}`，**当**用户打开编辑页，
   **那么**页面显示规范 GPa 值并保留原文表达。
2. **假如**同一材料在 250 GPa 和 300 GPa 报告不同结果，**当**草稿归一化，
   **那么**生成两个独立材料状态，不互相覆盖。

### 用户故事 2：核对空间群和计算参数（优先级：P1）

研究者希望材料、空间群符号、群号、λ 和 ωlog 各自有明确字段。

**独立验收**：Li2MgH16 状态显示 `Fd-3m / 227` 和 `λ=3.35`；未报告的 ωlog 为空。

**验收场景**：

1. **假如**论文报告 Fd-3m-Li2MgH16，**当**提取和归一化完成，
   **那么**材料为 `Li2MgH16`、空间群符号为 `Fd-3m`、群号为 `227`。
2. **假如**论文只报告空间群而没有 CIF/POSCAR，**当**提交，
   **那么**空间群作为材料状态的论文报告对称性保存，不伪造完整结构模型。
3. **假如**论文报告 λ 但未报告 ωlog，**当**提交，
   **那么**理论上下文保存 λ，ωlog 保持空值。

### 用户故事 3：提交到新科学模型（优先级：P1）

研究者希望提交后的压力、Tc、计算参数和普通物性进入各自实体，并与论文当前 revision 一致。

**独立验收**：完整 Li2MgH16 草稿在隔离数据库中生成材料状态、计算上下文、Tc 和普通物性，
且旧 `key_properties` 写入器不再执行。

**验收场景**：

1. **假如**理论状态包含 Tc、λ 和 ωlog，**当**提交，
   **那么**Tc 关联理论上下文，λ/ωlog 不注册为普通物性。
2. **假如**实验状态包含 Tc，**当**提交，
   **那么**Tc 只关联实验上下文。
3. **假如**任一科学子实体违反约束，**当**事务失败，
   **那么**Paper、文件和科学子实体全部回滚，并返回真实错误而不是误报 DOI 重复。

### 边界与异常场景

- 仅支持能解析为明确化学式的研究材料进入科学实体；无法解析的标签在提交前明确报错。
- 压力支持单值和范围；无法安全换算到 GPa 时只保留原文并要求用户校对。
- 空间群号必须位于 1–230；已知符号必须与群号一致。
- λ 和 ωlog 必须非负；ωlog 的规范输入单位为 K。
- 旧草稿只在读取/保存边界转换一次；新 AI 请求和新提交只使用新契约。
- 没有结构文本时不创建 `StructureModel`；存在结构文本时继续满足其完整性约束。

## 需求

### 功能需求

- **FR-001**：系统必须把旧草稿中的数字、对象或范围压力归一化为材料状态压力字段，并保留原文和单位。
- **FR-002**：系统必须按材料、压力、物相和数据主体建立独立材料状态。
- **FR-003**：系统必须分别保存材料名、论文报告空间群符号和 1–230 群号，并校验已知符号—群号对应。
- **FR-004**：系统必须将 λ 和 ωlog 保存于理论计算上下文，缺少证据时保持空值。
- **FR-005**：系统必须将 Tc 保存于 `tc_results`，并按理论/实验类型关联且只关联正确上下文。
- **FR-006**：系统必须将 Tc、λ、ωlog 和空间群从普通物性集合中分流，其他物性保留原始名称、值和单位。
- **FR-007**：系统必须为可解析材料复用或创建规范 Superconductor，并使所有科学实体使用论文当前 revision。
- **FR-008**：系统必须在同一事务中保存论文、文件、Chunk、Evidence 和科学实体，失败时整体回滚。
- **FR-009**：系统必须保留每条分类、状态、Tc 和普通物性的原文 Evidence；可建立正式连接的实体使用对应 Evidence 连接表。
- **FR-010**：编辑页必须提供独立的材料状态、压力、空间群符号/群号、λ 和 ωlog 输入，不再使用普通物性卡表达这些字段。
- **FR-011**：系统必须兼容读取当前 schema version 的旧扁平草稿，但新请求和保存结果只输出新契约。
- **FR-012**：修改分段输出契约时必须递增缓存 schema version，旧缓存不得冒充新结果。
- **FR-013**：数据库必须允许材料状态保存“论文报告空间群”，并与完整结构模型字段明确区分。
- **FR-014**：非 DOI 完整性错误必须保留真实错误语义，不得统一误报为论文重复。

### 关键实体

- **上传材料状态**：一篇论文内的材料、物相、压力、温度、报告空间群和数据主体。
- **理论上下文**：同一材料状态的 λ、ωlog、μ*、声子近似与计算方法。
- **实验上下文**：同一材料状态的测量方法和 Tc 判据。
- **Tc 结果**：独立的理论或实验临界温度单值/范围。
- **普通物性**：排除 Tc、λ、ωlog 和空间群后的其他论文报告物性。

## 成功标准

- **SC-001**：实际 Li2MgH16 草稿中的 250/300 GPa 显示正确率为 100%。
- **SC-002**：Fd-3m 与群号 227 分字段显示和保存，材料字段不含空间群前缀。
- **SC-003**：λ=3.35 保存到理论上下文，未报告 ωlog 时数据库值为 NULL。
- **SC-004**：含科学数据的上传提交不再调用旧 `KeyProperty` 构造路径。
- **SC-005**：提交成功后全部科学实体与 Paper revision 一致；故意制造晚期失败时残留记录数为 0。
- **SC-006**：后端、前端、Go 模型、Alembic 隔离 MySQL 与生产构建测试全部通过。

## 假设与依赖

- 依赖 #32 的条件化超导数据模型和 #33 的论文 revision/Evidence 血缘。
- Fd-3m 对应群号 227，P-3m1 对应群号 164；本次只内置实际提取所需且经过测试的映射，
  其他符号允许用户同时输入合法群号。
- 一个上传材料状态在当前编辑器中最多维护一个理论上下文和一个实验上下文；各上下文可包含多条 Tc。

## 范围外事项

- 历史数据库与已提交论文回填。
- OCR 或图片表格识别。
- 跨论文合并材料、状态或结构。
- 多理论上下文的高级编辑器。
- 全量国际空间群符号词典。
