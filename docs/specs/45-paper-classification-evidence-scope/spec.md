# Bug 规格：论文分类证据作用域与汇总前状态

**GitHub Issue**：[#45](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/45)

**创建日期**：2026-08-24

**状态**：已确认，实施中

## 背景与目标

论文上传任务会在全文汇总前持续展示分段候选。当前系统没有区分句子是在描述本文工作，
还是在回顾引用文献；随后又把单值字段中的不同字符串直接标为冲突。这使纯理论论文因为
引言提到前人实验和研究综述而同时出现 `theoretical`、`experimental`、`review` 和
`unknown`，也使材料家族、超导特征和引用材料被误报为互斥的材料类型。

本 Bug 修复需要让分段证据带有明确作用域，只让本文证据参与本文分类，并在全文汇总完成前
把分类区域标为“候选尚未汇总”。材料类型继续允许自由文本，由用户和管理员完成最终确认。

## 用户场景与验收

### 用户故事 1：引用背景不污染本文分类（优先级：P1）

用户上传一篇在引言中回顾前人实验和综述、但核心贡献为理论计算的论文时，系统能够保留这些
引用证据，同时只用描述本文计算工作的证据形成本文分类候选。

**优先级理由**：错误的论文类型会直接污染草稿、人工审核和后续数据使用，是本 Bug 的核心故障。

**独立验收**：使用 Li–Mg–H 论文前两页的固定分段证据重放解析详情，确认引用实验和综述不进入
本文候选，而本文结构搜索和计算证据仍可追溯。

**验收场景**：

1. **假如** 一个分段描述“后续实验发现了超导态”，且该陈述属于引用工作，**当** 系统构建本文
   论文类型候选，**那么** 该证据继续可见，但不会产生本文 `experimental` 候选。
2. **假如** 一个分段回顾“该领域研究很少”，且该陈述属于引用工作，**当** 系统构建本文论文
   类型候选，**那么** 该证据不会产生本文 `review` 候选。
3. **假如** 分段描述本文使用结构搜索、第一性原理或 Eliashberg 方程得到结果，**当** 系统构建
   本文论文类型候选，**那么** `theoretical` 候选及其页码和原文保持可见。

### 用户故事 2：汇总前不显示正式分类冲突（优先级：P1）

用户查看仍处于分段阅读或全文汇总阶段的任务时，分类区域明确说明当前只是分段候选，尚未形成
全文结论；标题、DOI 等真实元数据不一致仍按冲突展示。

**优先级理由**：当前“有冲突”标签把正常中间状态误导为正式结论，直接造成用户对分类质量的误判。

**独立验收**：构造同时含 `unknown`、本文 `theoretical` 和引用工作候选的解析详情，确认分类字段
显示“候选尚未汇总”，而同一响应中的两个不同标题仍显示“有冲突”。

**验收场景**：

1. **假如** 任务处于分段阅读或全文汇总阶段，**当** 分类字段已有一个或多个候选，**那么** 状态
   显示“候选尚未汇总”，不显示“有冲突”。
2. **假如** 标题或 DOI 存在来自不同文件的不同值，**当** 临时表单展示基本信息，**那么** 仍显示
   “有冲突”并列出来源。
3. **假如** 当前只有 `unknown` 或没有可用的本文分类证据，**当** 用户查看分类字段，**那么** 页面
   说明当前分段尚无法判断并等待全文汇总，而不是把 `unknown` 当成反对其他类型的证据。

### 用户故事 3：自由材料类型继续进入人工审核（优先级：P2）

LLM 或用户可以提出数据库现有分类之外的材料类型，系统保留原始自由文本和本文证据；已有分类
只作为人工校对参考，不自动替换、合并或拒绝新类型。

**优先级理由**：新材料体系不能被固定枚举阻塞，这一约束已经由 #23 确认并落地。

**独立验收**：输入不在现有分类列表中的本文材料类型，确认其原文进入草稿和审核流程且未被改写。

**验收场景**：

1. **假如** 本文材料候选为新的自由文本，**当** 全文汇总和人工校对完成，**那么** 该文本可以原样
   保存为待审核值。
2. **假如** 引用论文出现另一种材料或超导机制描述，**当** 系统构建本文材料类型候选，**那么**
   引用证据仍可查看，但不会成为本文材料类型候选。

### 边界与异常场景

- 升级前已缓存且没有证据作用域的分段结果不得被默认为本文证据；系统应安全重读或显式降级。
- 一个分段可以同时包含本文工作和引用工作，证据项必须分别标记作用域。
- 全文最终确实同时包含理论和实验贡献时，仍由全文汇总按 #23 的核心贡献规则判断。
- 证据作用域不改变每条物性独立的 `article_type=e|t`。
- 任务失败或取消时不得伪造已汇总分类状态。

## 需求

### 功能需求

- **FR-001**：每条论文类型证据和材料类型候选必须标明其描述的是本文工作还是引用工作。
- **FR-002**：系统必须只使用本文作用域证据构建本文论文类型和材料类型候选。
- **FR-003**：引用工作证据必须继续保留来源文件、角色、章节、页码和原文，并可在分段证据中查看。
- **FR-004**：`unknown` 必须表示当前分段无法判断；存在有效本文候选时不得与其构成冲突。
- **FR-005**：任务处于分段阅读或全文汇总阶段时，分类字段必须显示“候选尚未汇总”。
- **FR-006**：标题、DOI 等非分类单值字段的真实候选不一致必须继续显示冲突。
- **FR-007**：材料类型必须继续支持 LLM 和用户自由文本，不得强制映射到现有枚举或自动合并同义词。
- **FR-008**：缺少作用域的旧临时分段结果不得被提升为本文证据，也不得导致任务详情读取失败。
- **FR-009**：全文汇总只能根据本文作用域的有效分类候选形成论文类型与材料类型建议。
- **FR-010**：系统必须提供基于 Li–Mg–H 代表性证据的确定性回归验证，不依赖实时 LLM 响应。

### 关键实体

- **分类证据**：候选值、证据作用域、来源文件、文件角色、章节、页码和原文。
- **证据作用域**：`current_paper` 表示本文作者的工作；`referenced_work` 表示被引用或回顾的工作。
- **临时分类字段状态**：全文汇总前为候选状态，全文汇总后由可编辑 AI 草稿承载最终建议。
- **自由材料类型**：LLM 或用户给出的原始分类文本，最终由人工审核确认。

## 成功标准

- **SC-001**：Li–Mg–H 回归样例中，引用实验和综述证据进入分段证据但不进入本文论文类型候选。
- **SC-002**：解析中分类字段不再出现正式“有冲突”标签，基本信息真实冲突仍保持原行为。
- **SC-003**：`unknown + theoretical` 样例只保留有效的 `theoretical` 本文候选；全部无法判断时显示等待全文汇总。
- **SC-004**：任意不在已有列表中的材料类型自由文本可无损进入最终草稿和人工审核。
- **SC-005**：旧无作用域临时结果可以安全读取，并且不会被静默当作本文分类证据。
- **SC-006**：相关后端、前端和上传工作流回归测试全部通过。

## 假设与依赖

- 依赖 #23 已确认的全文分类规则和自由材料类型决策。
- 依赖 #27 已实现的分段结果、临时表单和来源展示能力。
- 分段结果和解析预览属于 24 小时临时数据，不需要数据库迁移。
- 数据库已有材料类型由现有编辑界面提供参考，本 Bug 不建立全局类型目录。

## 范围外事项

- 不建立材料类型别名库或自动同义词治理。
- 不限制 LLM 或用户提出新材料类型。
- 不更换 LLM、PDF 提取器或分段算法。
- 不修改论文类型枚举和理论二级类型规则。
- 不改变物性 `article_type`、正式论文审核状态或数据库模型。
