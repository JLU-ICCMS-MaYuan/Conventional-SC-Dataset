# 技术研究：已提交论文详情页持久入口

**Feature**：[spec.md](spec.md) ／ **日期**：2026-08-26

## D1：详情页可达性的承载方式

**决策**：新增客户端路由 `/papers/:id`，由 `PaperDetailPage` 页面壳承载，论文编号来自 URL 参数。

**理由**：缺陷根因是详情页可达性依赖组件内一次性状态。`frontend/src/pages/UploadPage.tsx:46-47`
用 `stage: 'list' | 'detail'` 与 `detailPaperId` 两个 `useState` 决定是否渲染详情，
`:364-367` 的 `handleDetailBack` 把 `detailPaperId` 置 `null`，可达性随之永久消失。只有把
状态外化到 URL，才能同时满足刷新保持、前进/后退与地址分享三项要求（FR-002）。

**备选方案**：

- 在上传任务中心列出用户已提交论文作为入口：改动更小，但仍无法刷新保持、无法分享地址，
  且需要新增「按用户查询已提交论文」的后端能力。已在 Issue 澄清阶段由用户否决。
- 把 `detailPaperId` 持久化到 `localStorage`：能扛刷新，但无法分享、无法前进/后退，且引入
  与真实导航不一致的隐藏状态，违反 KISS。

**证据**：`frontend/src/LazyRoutes.tsx:27-40` 显示前端已使用 `react-router-dom` 的
`Routes`/`Route`，新增一条路由属既有体系的自然扩展，无需引入依赖；同文件 `:36` 的
`/users/:username` 证明动态参数路由已有先例。

## D2：错误分流放在页面壳而非详情组件

**决策**：把论文数据加载与错误分流上移到 `PaperDetailPage`；`PaperEditView` 通过 props 接收
已就绪的论文数据，不再自行请求。

**理由**：FR-006 要求区分「无权查看」「论文不存在」「编号无效」三类结果并各自给出明确提示。
当前 `frontend/src/components/PaperEditView.tsx:70-93` 的 `loadPaper` 把所有异常压成
`e.message || '加载论文失败'`，既不读 `status` 也不区分类型，无法满足该需求。加载逻辑上移后，
页面壳承担「寻址与结果分流」单一职责，`PaperEditView` 回归纯展示。

**备选方案**：在 `PaperEditView` 内部增加状态码分流。可行但会让该组件同时承担数据获取、错误
语义与字段渲染三重职责；而 #57 还要重写它的字段展示，职责越少越利于后续改动。

**证据**：`frontend/src/lib/api.ts:3-5`、`:35` 显示 `ApiError` 携带 `status`，前端具备按状态码
分流的能力，无需新增基础设施。

## D3：前端不复制权限规则

**决策**：前端不读取用户角色、不判断 `review_status`，仅按 `GET /api/papers/{id}` 的 HTTP
状态码渲染提示。

**理由**：权限规则已完整实现于后端 `goserver/handlers/papers.go:71-81` `canViewPaper`：
管理员或 approved 一律可见；未登录且非 approved 不可见；登录用户可见 pending；rejected 仅
上传者可见。前端复制这套判断会形成双份业务规则，一旦后端调整即产生行为分裂（DRY，
且违反本 Skill「不得在两个组件中复制权限」的约束）。

**已核实的响应契约**：

| 情形 | 后端行为 | 证据 |
|------|----------|------|
| 论文不存在 | `404` + `{"error": "论文不存在"}` | `papers.go:38-41` |
| 无权查看 | `403` + `{"error": "无权查看该论文"}` | `papers.go:45-48` |
| 编号非数字 | `400` + `{"error": "无效的论文 ID"}` | `papers.go:27-30` |
| 可以查看 | `200` + 论文详情对象 | `papers.go:49` |

前端对编号无效的情形在本地先行拦截（不发请求），因为 URL 参数可由用户任意输入，
本地校验可避免无意义的网络往返；后端 `400` 分支仍作为兜底保留。

## D4：SPA 深链接的服务端回退

**决策**：无需修改部署配置。

**理由**：直接访问 `/papers/123` 时浏览器会向服务器请求该路径，若无 SPA 回退会返回 404。
已确认 `docker/nginx.conf:12-14` 存在 `location / { try_files $uri $uri/ /index.html; }`，
任意非静态资源、非 `/api/` 路径都会回退到 `index.html` 并交给客户端路由处理，因此
`/papers/:id` 深链接（FR-002 的「直接输入或分享地址」）天然可用。

**证据**：`docker/nginx.conf:12-14`（SPA 回退）与 `:17`（`/api/` 反向代理）路径不重叠，
新增前端路由不会与 API 前缀冲突。

## D5：Bug 分类

**决策**：归类为「主路径实现缺失」，不涉及历史数据兼容或部署版本不一致。

**理由**：后端接口与数据均正常——`papers` id=4 可正常查询，数据完整入库。缺陷纯在前端：
详情页从未被赋予可寻址入口。因此修复方式是补齐前端主路径能力，不需要数据迁移、契约版本化
或降级分支，也不存在只为旧数据服务的兼容代码。

**验证边界要求**：回归测试必须覆盖用户实际遇到的故障边界，即「离开详情页后能否再次到达」。
仅断言组件能渲染不足以证明修复；测试需覆盖「按 URL 渲染」与「不同 URL 渲染不同论文」，
并由 quickstart 在浏览器中验证真实的刷新与前进/后退行为。
