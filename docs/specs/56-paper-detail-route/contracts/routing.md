# 契约：论文详情路由与错误分流

**Feature**：[../spec.md](../spec.md) ／ **日期**：2026-08-26

## 路由契约

| 路径 | 参数 | 页面 | 权限 |
|------|------|------|------|
| `/papers/:id` | `id`：论文编号，正整数 | `PaperDetailPage` → `PaperEditView`（只读） | 由后端 `GET /api/papers/{id}` 判定，前端不预先拦截身份 |

- 页面内容完全由 `:id` 决定，不依赖任何组件内可达性状态（FR-001）。
- 路由不包裹 `RoleRoute`：论文可见性不是「按角色准入页面」，而是「按论文状态与归属逐篇判定」，
  必须由后端逐篇裁决。用 `RoleRoute` 会错误地把匿名用户挡在 approved 论文之外。

## 导航契约

| 触发 | 来源 | 行为 |
|------|------|------|
| 提交审核成功 | `UploadPage` 提交回调 | 导航至 `/papers/<新论文编号>`（FR-003） |
| 详情页「返回上传列表」 | `PaperDetailPage` | 导航至 `/upload`；该论文详情地址此后仍可访问（FR-004） |
| 浏览器刷新 / 前进 / 后退 | 浏览器 | 由路由重新解析 `:id` 并重新加载，结果与首次访问一致（FR-002） |

## 后端接口依赖

依赖既有 `GET /api/papers/{id}`，本 Feature 不修改其实现、权限或响应结构。

已核实的响应契约（`goserver/handlers/papers.go`）：

| 状态码 | 条件 | 响应体 | 证据 |
|--------|------|--------|------|
| `200` | 通过 `canViewPaper` 判定 | 论文详情对象 | `papers.go:49` |
| `400` | 路径参数非数字 | `{"error": "无效的论文 ID"}` | `papers.go:27-30` |
| `403` | 论文存在但当前身份无权查看 | `{"error": "无权查看该论文"}` | `papers.go:45-48` |
| `404` | 论文不存在 | `{"error": "论文不存在"}` | `papers.go:38-41` |

权限规则（`papers.go:71-81` `canViewPaper`，本 Feature 不改动）：

- 管理员或超级管理员：可见全部。
- `approved`：任何身份可见，含匿名。
- `pending`：任何已登录用户可见。
- `rejected`：仅上传者本人可见。
- 其余情形不可见。

## 前端错误分流契约

`PaperDetailPage` 依据本地校验与响应状态码分流，四类结果互相可区分，且失败时**不渲染任何论文
字段**（FR-006、SC-003）：

| 情形 | 判定依据 | 页面表现 |
|------|----------|----------|
| 编号无效 | 本地校验：`:id` 非正整数 | 明确的「论文编号无效」提示 + 返回操作；不发起请求 |
| 无权查看 | 响应 `403` | 明确的「无权查看该论文」提示 + 返回操作 |
| 论文不存在 | 响应 `404` | 明确的「论文不存在」提示 + 返回操作 |
| 加载失败 | 其他非 2xx 或网络异常 | 可区分于上述三类的加载失败提示 + 返回操作 |
| 正常 | 响应 `200` | 渲染只读详情 |

约束：

- 前端不读取用户角色、不判断 `review_status`，权限语义只来自状态码（FR-005）。
- 三类失败提示的文案必须互不相同，以便用户与测试区分。
- 失败状态下不得渲染 `PaperEditView`，避免任何字段内容泄漏。

## 兼容性

- 不改变任何后端接口、数据结构或权限规则，无版本化需求。
- `UploadPage` 移除 `stage`/`detailPaperId` 属内部实现调整，不影响上传、解析、校对与提交的
  既有行为（SC-004）。
- 不引入新依赖，不修改 `docker/nginx.conf`（SPA 回退已覆盖新路径，见 [../research.md](../research.md) D4）。
