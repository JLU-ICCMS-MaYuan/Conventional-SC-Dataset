## 端到端场景

### 场景 1：刷新保持（US1，验收 SC-001）

1. 以论文上传者身份登录，打开 `/papers/4`。
2. 确认显示只读的「论文详情」页与该论文标题。
3. 按 F5 刷新浏览器。
4. **预期**：仍停留在同一篇论文的只读详情页，不跳回 `/upload`，地址栏仍为 `/papers/4`。

### 场景 2：返回后仍可再次到达（US1，验收 SC-002）

1. 在 `/papers/4` 点击「返回上传列表」。
2. **预期**：进入上传页，地址栏变为 `/upload`。
3. 点击浏览器「前进」。
4. **预期**：重新回到 `/papers/4` 的只读详情页。
5. 在新标签页直接输入 `/papers/4` 并回车。
6. **预期**：直接显示该论文只读详情，无需先经过上传流程。

### 场景 3：三类失败提示可区分（US2，验收 SC-003）

1. 访问 `/papers/999999`（不存在的编号）→ **预期**：显示「论文不存在」类提示 + 返回操作，  
   不出现任何论文字段。
2. 访问 `/papers/abc`（无效编号）→ **预期**：显示「论文编号无效」类提示，且浏览器开发者工具  
   Network 面板中**没有** `/api/papers/abc` 请求。
3. 退出登录后访问 `/papers/4`（该论文为 `pending`）→ **预期**：显示「无权查看」类提示，  
   页面不出现论文标题、摘要或任何字段内容。
4. 确认上述三条提示文案互不相同。

### 场景 4：提交后直达详情（US1，验收 FR-003）

1. 上传一篇新论文，完成解析与校对后点击「提交审核」。
2. **预期**：提交成功后地址栏变为 `/papers/<新编号>`，页面显示该论文只读详情。
3. 刷新页面 → 仍停留在该详情页。

### 场景 6：用户页「我的论文」列表（US3，验收 FR-007、SC-005）

1. 以论文上传者身份登录，打开左侧导航「用户」页。
2. **预期**：看到「我的论文」区块，其中列出该账号提交过的论文，含标题与审核状态（如「待审核」）。
3. 点击其中一条记录。
4. **预期**：进入该论文的 `/papers/<id>` 只读详情页，全程未手工输入网址，点击次数不超过两次。
5. 用一个从未提交过论文的账号查看该区块 → **预期**：显示明确空状态说明，不是空白区域。

### 场景 7：提交成功后直接查看详情（US3，验收 FR-008）

1. 上传并提交一篇新论文。
2. **预期**：提交成功提示中出现「查看详情」操作。
3. 点击该操作 → **预期**：进入刚提交论文的只读详情页。

### 场景 8：未定义地址不再白屏（验收 FR-009、SC-006）

1. 访问 `/upload/papers/999999`（模拟相对路径误拼）。
2. **预期**：显示「页面不存在」提示与返回操作，**不是全白页面**。
3. 访问 `/thispagedoesnotexist` → **预期**：同样显示「页面不存在」提示。

### 场景 5：既有流程无回归（验收 SC-004）

1. 打开 `/upload`，确认上传区、任务中心列表、展开/收起解析详情均正常。
2. 对一个 `ready` 任务打开校对表单，确认编辑与自动保存仍工作。
3. **预期**：上传、解析、校对、提交流程行为与本次改动前一致。
