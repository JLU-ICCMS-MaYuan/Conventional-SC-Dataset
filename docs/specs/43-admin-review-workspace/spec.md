# Feature 规格：管理员工作台

**GitHub Issue**：[#43](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/43)

**创建日期**：2026-08-24

**状态**：已确认

## 背景与目标

现有管理页把论文审核、图表、快讯和用户治理堆在一个组件中，管理员不仅看到超出职责的入口，后端还存在权限混用。本 Feature 将 `/admin` 收敛为“管理员工作台”，仅提供概览和论文审核，并抽取唯一可复用的审核模块。

## 用户场景与验收

### 用户故事 1：查看审核概览（优先级：P1）

管理员进入 `/admin` 后只看到与论文审核相关的状态和统计。

**独立验收**：管理员页面不请求用户治理、图表或快讯数据。

### 用户故事 2：完成论文审核（优先级：P1）

管理员可以筛选、查看、编辑并审批论文，现有审核能力和证据信息不回归。

**独立验收**：从待审列表完成一次批准和一次拒绝，审核事件正确记录。

### 用户故事 3：获得明确权限反馈（优先级：P2）

普通用户访问显示 403；超级管理员访问 `/admin` 自动进入 `/superadmin`。

### 边界与异常场景

- 管理员概览不得为显示总用户数而调用超级管理员接口。
- API 403 不得被吞成空表或零统计。
- 窄屏 Tabs、编辑表单和表格不得产生页面级横向溢出。
- 共享审核组件不能根据页面复制两套状态或请求逻辑。

## 需求

### 功能需求

- **FR-001**：`/admin` 必须只允许 active admin 访问。
- **FR-002**：页面标题必须为“管理员工作台”，只包含审核概览和论文审核。
- **FR-003**：图表组合、快讯、管理员申请、用户、角色、权限和审计入口不得在 `/admin` 出现或加载。
- **FR-004**：论文列表、详情、编辑、单篇/批量审核和审核反馈必须保持可用。
- **FR-005**：论文审核 UI、状态与 API 逻辑必须抽取为 `/admin` 与 `/superadmin` 共用的唯一模块。
- **FR-006**：普通用户访问必须显示 403 页面并提供返回用户中心操作。
- **FR-007**：superadmin 访问 `/admin` 必须重定向 `/superadmin`。
- **FR-008**：403、加载失败和空数据必须使用不同反馈，不得互相伪装。

## 成功标准

- **SC-001**：管理员工作台渲染和网络请求中超级管理员专属功能出现次数为 0。
- **SC-002**：现有论文审核核心回归场景全部通过。
- **SC-003**：管理员与超级管理员工作台引用同一个审核组件实现。
- **SC-004**：user/admin/superadmin 三角色路由矩阵全部自动化通过。

## 假设与依赖

- 依赖 #38 的后端权限边界；#44 依赖本 Feature 的共享审核模块。
- 不改变论文审核业务规则、统计口径或审核事件模型。

## 范围外事项

- 图表、快讯、用户治理、管理员申请和系统配置。

## 澄清记录

### 2026-08-24

- 问：管理员工作台包含什么？ → 答：仅概览和论文审核。
- 问：超级管理员如何审核？ → 答：在 `/superadmin` 直接复用同一审核模块。
