# 技术研究：管理员工作台

## 决策 1：按能力拆分而不是按角色复制

- **决策**：唯一 `ReviewWorkspace` 被两工作台组合。
- **理由**：论文审核字段和弹窗复杂，复制会让修复、权限和测试漂移。
- **备选方案**：保留 AdminPage 并用 isSuper 分支；拒绝，因为当前文件已过大且高权限数据仍会被加载。

## 决策 2：管理员概览使用审核统计

- **决策**：管理员概览只读取论文相关统计。
- **理由**：当前通过全用户接口计算概览既越权又会把 403 伪装成 0。

## 决策 3：路由守卫不替代 API 权限

- **决策**：RoleRoute 负责体验，Go 中间件负责安全。
- **理由**：localStorage 可被修改，前端角色不能作为授权证据。

## 决策 4：明确区分 403、错误和空状态

- **决策**：权限错误进入 ForbiddenPage，加载失败用 Alert，合法零结果用教学性空状态。
- **理由**：当前吞错会让用户误以为没有数据。
