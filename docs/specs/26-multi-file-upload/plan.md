# 实施计划：正文与附件分组及批量文件上传

## 方案

扩展 #25 任务服务为 manifest 驱动流程。每个文件独立流式落盘、计算 SHA-256 并原子更新状态；全部完成后 CAS `uploading→queued`。Worker 按文件顺序抽取文本并建立一致性报告。Alembic 新增 PaperFile 和来源定位字段，提交服务负责单一事务。

## 阶段

1. 先写 manifest、三并发、重复哈希、单次入队及事务回滚测试。
2. 实现文件模型、上传 API、校验与锁定。
3. 实现多文件抽取、一致性检查和提交确认。
4. 实现 PaperFile/Chunk/Evidence 迁移和事务提交。
5. 实现前端文件队列与旧接口适配。

## 依赖

依赖 #25 状态仓库；向 #27 提供稳定 file/chunk 标识；向 #28 提供永久文件和正式论文 ID。
