# Feature 规格：分文件、分段和全文汇总的实时解析详情

**GitHub Issue**：[#27](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/27)
**父 Epic**：[#24](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/24)
**状态**：已确认，待实施

## 目标

用户无需等待整篇完成，即可按文件、分段和全文汇总查看真实解析状态、结构化结果与证据，并能只重试失败/缺失分段。服务默认同时处理 2 篇论文且可配置。

## 用户故事

- **US1**：每个文件显示等待、提取、阅读、完成或失败。
- **US2**：每段显示所属文件、角色、章节、页码范围、状态和已完成的结构化结果。
- **US3**：全部必要段完成后显示全文汇总；部分失败时标记“汇总不完整”。
- **US4**：重试只运行失败或缺失段，已成功缓存不重复调用 LLM。

## 功能需求

- **FR-001**：预先建立稳定 chunk manifest，状态为 `waiting/processing/completed/failed`。
- **FR-002**：结果写入采用临时文件加原子替换，禁止返回半截 JSON。
- **FR-003**：公开结果只含结构化候选、证据句及来源定位；不含提示词、原始响应、路径、内部评分和异常堆栈。
- **FR-004**：活跃页面默认每 2 秒轮询；稳定状态停止高频轮询；轮询不得触发 #25 续期。
- **FR-005**：分段完成立即可查，不等待全文汇总。
- **FR-006**：重试复用 completed 缓存，并通过 revision/CAS 防重复 job 和状态倒退。
- **FR-007**：Worker 在文件和分段边界检查取消标记。
- **FR-008**：默认论文级 LLM 并发为 2，由服务端环境变量配置；不在线程内并行挤占单任务。

## 成功标准

- 任一分段完成后下一次轮询可看到结果。
- 重试不会再次调用已完成段，也不会重复写入。
- API 响应零内部路径、提示词或原始 LLM 内容泄漏。
- 默认最多两篇论文同时进入 LLM 处理，配置变更可生效。

## 范围外

- 不提供 SSE/WebSocket；本 Feature 使用轮询。
- 不展示流式 token 或未完成 JSON。
