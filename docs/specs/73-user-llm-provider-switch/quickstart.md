# 快速验证：顶栏 AI 供应商切换

**关联**：[spec.md](spec.md) · [plan.md](plan.md) · [contracts/llm-provider-headers.md](contracts/llm-provider-headers.md)

本文件是人工验收脚本。实施完成后逐场景执行，每条对应 spec 中的验收场景与成功标准。

## 前置条件

- 中英文切换 Issue 已落地，顶栏槽位可用。
- 后端与前端已按 plan 完成改造并重启（重建后端后需重启 nginx，否则 502 会被误判为功能失败）。
- 准备一份**真实可用**的第三方密钥（如 Kimi 或 DeepSeek），以及一份故意写错的密钥。
- 服务端默认配置（`.env` 中的 `DEEPSEEK_API_KEY`）保持可用，用于回退验证。

## 场景 1：入口可见与状态一致（US1 / SC-001）

1. 未配置任何供应商，打开 `/news`。
2. 确认顶栏头像左侧出现供应商入口，标签为「默认模型」。
3. 依次访问 `/search`、`/knowledge`、`/share`、`/upload`、`/rag`、`/tc-predict`。
4. 确认 7 个页面入口均可见、标签一致。
5. 点击入口，确认面板列出 8 个选项（服务端默认 + 6 家预置 + 自定义），当前项高亮。

**通过标准**：7/7 页面可见且状态一致。

## 场景 2：预置供应商 placeholder 行为（US2 / FR-003 FR-004）

1. 面板中选择 Kimi。
2. 确认 Base URL 输入框以浅灰 placeholder 显示 `https://api.moonshot.cn/v1`，模型名显示
   `moonshot-v1-8k`，二者均可编辑。
3. 确认 API Key 输入框为空，未预填任何值。
4. 不填密钥直接保存，确认被拒绝并提示密钥必填。
5. 切到 GLM，确认 placeholder 随之变化。

**通过标准**：预置项只给 placeholder，服务端不代付；密钥必填。

## 场景 3：凭据说明与掩码（US5 / FR-008 FR-009）

1. 打开面板，确认密钥输入框下方常驻显示「密钥仅保存在你当前浏览器，不会上传或存入服务器
   数据库」。
2. 输入密钥，确认默认掩码显示，可手动切换为可见。
3. 保存后重新打开面板，确认密钥以 `sk-****abcd` 形式回显，不显示完整明文。

**通过标准**：说明常驻可见，回显不含完整明文。

## 场景 4：全部 AI 功能改用所选供应商（US2 / SC-002）

填入真实 Kimi 密钥并保存，然后逐条验证四条链路：

1. **RAG 对话**：在 `/rag` 提问，确认回答返回 `provider: "kimi"`。
2. **论文解析**：在 `/upload` 上传一篇 PDF，确认解析完成后元信息抽取、分段分类、知识图谱
   标题均由 Kimi 生成（任务状态回显 `provider: "kimi"`）。
3. **灵感探索**：触发探索模式，确认意图识别、证据整理、评审环节均使用 Kimi。
4. **Reranker**：发起需要重排的检索，确认重排调用走 Kimi。

**通过标准**：4/4 链路无一落回 `server-default`。

> 这是本 Feature 最容易静默失败的一条。灵感探索经 `run_in_executor` 跨线程池，若
> contextvars 未 `copy_context()` 传播，会静默使用服务端凭据——不报错、答案照出，只是
> 花错了钱。必须逐条核对 `provider` 字段，不能只看答案是否正常。

## 场景 5：未配置用户行为不变（FR-013 / SC-005）

1. 点击「清除配置」，确认顶栏回到「默认模型」。
2. 在 `/rag` 提问，确认回答正常且返回 `provider: "server-default"`。
3. 上传一篇论文，确认解析全流程正常。
4. 执行后端回归测试：`tests/05_rag_question_answering/` 与
   `tests/01_decentralized_uploading/` 全通过。

**通过标准**：清除配置后行为与改造前一致，回归测试 100% 通过。

## 场景 6：自定义端点与 URL 校验（US3 / SC-004）

1. 选择「自定义」，确认三项均为空必填。
2. 填入合法 https 端点与模型名，确认可正常对话。
3. 填 `http://example.com/v1`，确认被拒并提示必须 https。
4. 逐个填入以下地址，确认全部被拒并提示不允许访问内网：
   - `https://192.168.1.10/v1`
   - `https://10.0.0.5/v1`
   - `https://172.16.0.1/v1`
   - `https://169.254.169.254/`
   - 一个 DNS 解析到私有网段的公网域名
5. 填 `http://localhost:11434/v1`，确认放行（本地模型支持）。

**通过标准**：非法 URL 拒绝率 100%，localhost 例外放行。

## 场景 7：连接测试四类失败（US4 / SC-006）

| 输入 | 期望提示 |
| --- | --- |
| 正确凭据 | 成功 + 实测耗时 |
| 故意写错的密钥 | API Key 无效或已过期 |
| 不可达地址（如 `https://no-such-host.example/v1`） | 服务地址不可达 |
| 不存在的模型名（如 `not-a-real-model`） | 模型名不存在 + 原始错误摘要 |
| 慢响应端点 | 15 秒后超时提示，可重试 |

**通过标准**：五种输入给出五种可区分结果。

## 场景 8：密钥零泄露（FR-018 / SC-003）

配置真实密钥并跑完一轮对话与一次上传解析后：

1. 全库检索密钥明文：数据库中命中 0 次。
2. 检索后端日志文件：命中 0 次。
3. 检索 nginx 访问日志：命中 0 次；并核对 `log_format` 不含 `$http_x_llm_api_key`。
4. 触发一次凭据错误，确认错误响应体与堆栈中密钥已脱敏。

**通过标准**：四处检索全部命中 0 次。

## 场景 9：RQ 凭据生命周期（FR-020 / SC-007）

1. 配置真实密钥，上传一篇论文触发解析。
2. 解析进行中，确认 Redis 中存在 `upload:llm:{task_id}` 键且带 TTL。
3. 任务成功完成后，确认该键已被删除。
4. 重复一次并中途让任务失败，确认失败终态同样清除该键。
5. 重复一次并取消任务，确认取消终态同样清除。

**通过标准**：三种终态（成功、失败、取消）后键均不存在。

## 场景 10：用户凭据失败不静默回退（FR-019）

1. 配置一个格式合法但无效的密钥。
2. 在 `/rag` 提问。
3. 确认返回明确错误，`code` 为 `LLM_USER_CREDENTIAL_FAILED`，提示指出是用户配置的供应商
   失败，并告知可切回默认模型。
4. 确认**没有**用服务端默认配置产出回答。

**通过标准**：报错而非静默回退。
