# Feature 规格：全新空库的条件化超导数据模型

**GitHub Issue**：[#32](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/32)

**创建日期**：2026-08-21

**状态**：已确认，实施中

## 背景与目标

当前超导数据分散在横向 Tc 字段、`key_properties` 和独立结构表中，无法稳定表达一篇论文内
“化学组分—材料状态—结构—理论/实验上下文—Tc/普通物性—原文证据”的完整关系。

本 Feature 只为全新空 MySQL 建立目标 Schema，并同步 SQLAlchemy 与 GORM。论文当前内容
revision 是唯一审核边界：管理员只审核一篇论文一次，该决定同时覆盖该版本中提取的全部
Tc、结构、普通物性和 Evidence。两个现有数据库及历史数据不读取、不回填、不修改。

## 用户场景与验收

### 用户故事 1：一次审核整篇论文当前内容（优先级：P1）

管理员希望一次审核即可确认论文当前版本中的全部结构化科学内容，不再分别审核论文、结构、
Tc 或普通物性。

**独立验收**：论文当前 revision 通过审核后，同 revision 的 Tc、结构、普通物性和 Evidence
同时可公开；任一科学内容变化后整篇论文回到 `pending`，旧批准不再有效。

**验收场景**：

1. **假如**论文当前版本包含多条 Tc、结构和普通物性，**当**管理员批准论文，
   **那么**全部内容同时获得公开资格，不需要第二次结果级审核。
2. **假如**已批准论文的文件、Chunk、Evidence 或科学字段变化，**当**保存新版本，
   **那么**论文整体回到 `pending`，直至新版本再次审核。
3. **假如**论文为 `pending` 或 `rejected`，**当**公开查询，
   **那么**该论文的科学子记录均不可公开。

### 用户故事 2：保存条件化结构、Tc 和普通物性（优先级：P1）

研究者希望同一组分、同一名义压力下的竞争相、不同结构、不同方法和多条 Tc 独立存在，
不被材料+压力或结构哈希错误合并。

**独立验收**：同一材料和压力可保存多个状态、结构及同方法 Tc；LaH10 与 LaD10 是不同
组分；普通物性存于 `superconductor_properties`，Tc 只存于 `tc_results`。

**验收场景**：

1. **假如**论文在 200 GPa 报告两个物相，**当**入库，
   **那么**两个材料状态独立存在，`phase_label` 只保存在材料状态。
2. **假如**同一状态包含经典结构和量子非谐派生结构，**当**入库，
   **那么**两个结构通过父结构关系表达派生链。
3. **假如**同一论文对同一状态使用多个 μ* 或 Tc 方法，**当**入库，
   **那么**每个独立结论各占一行，不发生覆盖。
4. **假如**论文报告非 Tc 物性，**当**入库，
   **那么**系统同时保留规范属性代码/单位与论文原始名称、值和单位。

### 用户故事 3：保留论文原文并选择代表 Tc（优先级：P1）

研究者查看数据时，希望优先看到论文原本写法，同时获得规范值用于筛选和比较。

**独立验收**：Tc 和普通物性同时保存原文与规范值；审核者可在同一论文、材料状态和 Tc
方法内指定至多一条代表结果，代表选择不影响其他 Tc 直接随论文公开。

**验收场景**：

1. **假如**论文使用非标准名称或单位，**当**展示属性，
   **那么**默认展示原始名称、值和单位，规范值作为补充。
2. **假如**同一方法有多条 Tc，**当**指定代表结果，
   **那么**相同 `paper_id + material_state_id + tc_method` 最多一条代表结果。
3. **假如**论文 B 使用与 A 相同的结构几何，**当**B 独立完成计算，
   **那么**A、B 的状态、结构和 Tc 各自独立，互不形成审核依赖。

### 用户故事 4：从空库建立可验证 Schema（优先级：P1）

维护者希望在隔离空 MySQL 中一次建立完整目标表和约束，避免开发环境 `create_all()` 掩盖
Alembic 缺表或约束差异。

**独立验收**：隔离空 MySQL 执行 `alembic upgrade head` 成功；目标表、外键、CHECK、
唯一约束和索引与双 ORM 一致。

**验收场景**：

1. **假如**数据库完全为空，**当**升级到 head，**那么**全部目标表按单一 revision 链建立。
2. **假如**目标 revision 检测到现有业务数据，**当**执行，
   **那么**迁移明确中止，不读取、转换或删除现有数据。

### 边界与异常场景

- `superconductor_id + pressure` 不是状态、结构或 Tc 的唯一键。
- `phase_label` 只属于 `material_states`；同位素只属于 `superconductors` 组分身份。
- 理论上下文允许结构未知，但必须记录缺失原因，不按压力猜测结构。
- 结构哈希只用于候选比较，不用于跨论文自动合并。
- JSON 只保存低频扩展参数；高频筛选和完整性字段结构化。
- 代表 Tc 只影响默认展示，不改变其他结果的真实性或公开资格。
- 两个现有数据库、旧 SQL dump 和历史文件均不属于本次输入。

## 需求

### 功能需求

- **FR-001**：系统必须保留 `chemical_systems → superconductors`，并使用包含同位素的
  规范组分键区分身份。
- **FR-002**：每个科学子记录必须属于一篇论文的明确 `paper_revision`；论文审核状态只使用
  `pending/approved/rejected`。
- **FR-003**：系统必须只在论文级审核一次；科学子实体不得包含独立审核状态、审核人或时间。
- **FR-004**：只有 `approved_revision = content_revision` 的已批准论文当前版本可公开；
  科学内容、文件、Chunk 或 Evidence 变化必须使整篇论文回到 `pending`。
- **FR-005**：`material_states` 必须保存论文、组分、物相和外部条件，不得对材料+压力设
  唯一约束；`phase_label` 不得重复进入结构实体。
- **FR-006**：`structure_models` 必须保存几何、生成方法、核处理和可空父结构；父子结构
  必须属于同论文 revision 和组分，派生图不得成环。
- **FR-007**：`calculation_contexts` 必须关联材料状态，可选关联结构，并分开保存电子、
  声子/EPC 与求解参数；结构核处理与声子核处理不得互相推断。
- **FR-008**：`experimental_contexts` 必须保存样品、制备、测量方法、Tc 判据、外场和压力
  不确定度，且不得强制已知结构。
- **FR-009**：`tc_results` 必须一行保存一个独立方法/参数/判据结论，至少支持
  `experimental/anisotropic_eliashberg/isotropic_eliashberg/allen_dynes/mcmillan/unknown`。
- **FR-010**：理论 Tc 必须且只能关联理论上下文；实验 Tc 必须且只能关联实验上下文；
  单值或有效范围至少存在一种。
- **FR-011**：每个 `paper_id + material_state_id + tc_method` 最多一条代表 Tc。
- **FR-012**：`property_definitions` 必须保存规范属性代码、名称、单位和值类型；Tc 不得
  注册为普通物性。
- **FR-013**：非 Tc 普通物性必须保存于 `superconductor_properties`，同时保留论文原始
  名称、值、单位及可选规范数值；目标 Schema 不建立 `key_properties`。
- **FR-014**：结构、Tc 和普通物性必须通过连接表关联当前论文 revision 的 Evidence，
  不得跨论文或跨 revision。
- **FR-015**：规范压力、温度、Tc 和普通物性数值使用固定精度十进制，并保留原文值和单位。
- **FR-016**：不同论文的状态、结构、上下文和结果独立保存；相同几何不自动合并，也不形成
  审核依赖。
- **FR-017**：公开和网页展示契约默认优先论文原始名称、值和单位；规范字段用于筛选和补充。
- **FR-018**：数据库必须用外键、CHECK、唯一约束和索引保护 revision、上下文互斥、代表 Tc、
  数值范围和证据归属。
- **FR-019**：目标 revision 只接受空业务库；发现现有业务数据时必须中止，不迁移、不回填、
  不删除。
- **FR-020**：SQLAlchemy、GORM 与 Alembic 的表名、列、类型、空值、外键和索引必须一致。

### 关键实体

- **超导组分**：含同位素的规范化化学计量身份，例如 LaH10、LaD10。
- **论文版本**：一次整体审核的文件、Chunk、Evidence 和科学内容集合。
- **材料状态**：论文内特定物相和外部条件的研究状态。
- **结构模型**：论文内可独立引用的具体几何和方法版本。
- **理论/实验上下文**：产生 Tc 或普通物性的条件与参数。
- **Tc 结果**：一个独立 Tc 方法、参数或实验判据结论。
- **属性定义**：非 Tc 普通物性的规范词典。
- **超导普通物性**：论文原文与规范值并存的一条非 Tc 结论。

## 成功标准

- **SC-001**：论文级审核是结构、Tc、普通物性和 Evidence 的唯一公开依据，子实体独立审核
  字段数量为 0。
- **SC-002**：同一论文、材料和压力下可无冲突保存至少两个物相、两个派生结构、三条 Tc
  和两条普通物性。
- **SC-003**：每条 Tc、结构和普通物性可解析到同论文 revision Evidence，跨论文/revision
  关联写入拒绝率为 100%。
- **SC-004**：代表 Tc 重复写入拒绝率为 100%，非代表结果数量不受限制。
- **SC-005**：LaH10 与 LaD10 身份不同；状态表同位素字段和结构表物相字段数量为 0。
- **SC-006**：Tc 与普通物性原文名称/值/单位保留率为 100%，展示契约明确原文优先。
- **SC-007**：隔离空 MySQL 从空库升级到 head 成功，目标 Schema 与双 ORM 一致。
- **SC-008**：空库迁移、Python 和 Go 模型测试通过，且不会连接或修改现有数据库。
