# Feature 规格：超级管理员工作台与账号治理

**GitHub Issue**：[#44](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/44)

**创建日期**：2026-08-24

**状态**：已确认

## 背景与目标

超级管理员需要独立且权限更高的 `/superadmin` 工作台，在复用论文审核能力的同时集中内容管理、管理员申请和账号治理。本 Feature 还把现有物理删除改造成保留科研与审计链条的可追溯注销。

## 用户场景与验收

### 用户故事 1：在一个工作台完成高权限职责（优先级：P1）

超级管理员可在一个页面切换概览、论文审核、图表、快讯、管理员申请、用户治理和审计。

**独立验收**：所有面板可用，论文审核直接复用 #43 模块。

### 用户故事 2：安全治理账号（优先级：P1）

超级管理员带原因封禁、解封、注销或调整角色，并在操作前看到明确后果。

**验收场景**：

1. **假如**目标是 active 用户，**当**确认封禁并填写原因，**那么**用户旧会话立即失效、不能登录或写入，公开页保留并标注封禁。
2. **假如**目标已封禁，**当**带原因解封，**那么**账号恢复 active，但旧 Token 仍不可复用。
3. **假如**确认注销，**当**事务成功，**那么**账号不可登录、公开资料和头像被移除，历史贡献显示“已注销用户”。

### 用户故事 3：查看不可变审计（优先级：P2）

超级管理员可分页查看姓名/机构、用户名和治理动作审计；其他角色不能读取。

### 边界与异常场景

- 超级管理员不能封禁、注销或降级自己。
- 系统必须始终保留至少一名 active superadmin，并发操作也不能突破。
- 注销不得物理删除用户行或破坏论文、贡献、审核、申请和审计外键。
- 敏感操作取消或失败时不得产生半更新审计。
- 管理员和普通用户访问 `/superadmin` 必须 403。

## 需求

### 功能需求

- **FR-001**：`/superadmin` 必须只允许 active superadmin 访问，标题为“超级管理员工作台”。
- **FR-002**：工作台必须复用 #43 的概览和论文审核模块，不复制审核代码。
- **FR-003**：工作台必须提供图表组合、快讯、管理员申请、用户角色与权限、账号治理和审计面板。
- **FR-004**：图表组合和快讯写操作必须只允许 superadmin，公开读取保持原契约。
- **FR-005**：封禁必须禁止登录和所有写操作，递增会话版本，保留公开资料和历史贡献并标注封禁。
- **FR-006**：解封必须恢复 active 并保留既有 Token 失效状态。
- **FR-007**：注销必须保留用户行和历史关联，移除头像及公开资料，历史贡献显示“已注销用户”。
- **FR-008**：封禁、解封、注销和角色变化必须要求原因，并与账号更新在同一事务追加治理审计。
- **FR-009**：超级管理员不得对自己执行封禁、注销或降级；系统始终至少保留一名 active superadmin。
- **FR-010**：敏感操作必须使用说明后果、原因输入和明确确认的二次确认界面。
- **FR-011**：真实姓名/机构审计和 #31 用户名审计必须只读、分页且仅 superadmin 可见。
- **FR-012**：管理员与普通用户访问必须显示 403，不得加载专属数据。

### 关键实体

- **账号状态**：`active/banned/deactivated`。
- **治理审计事件**：记录动作、角色/状态变化、原因、操作者和时间。
- **资料审计、用户名审计**：保持各自独立只追加表。

## 成功标准

- **SC-001**：非 superadmin 成功调用任一专属写接口的次数为 0。
- **SC-002**：封禁、解封、注销和角色变化每次成功动作都有且仅有一条治理审计。
- **SC-003**：任何并发治理操作后 active superadmin 数量至少为 1。
- **SC-004**：注销前后的论文、贡献、审核和审计关联计数不减少。
- **SC-005**：两工作台的论文审核实现文件与行为测试共用同一模块。

## 假设与依赖

- 依赖 #38 权限修复、#40 资料/会话、#42 管理员申请、#43 共享审核模块。
- 图表与快讯现有组件复用，权限收紧不改变公开读取。

## 范围外事项

- 系统配置、运行监控、数据库管理、物理删除、代改他人科研资料。
