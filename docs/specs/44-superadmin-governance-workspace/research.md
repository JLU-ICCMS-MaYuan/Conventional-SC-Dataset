# 技术研究：超级管理员工作台与账号治理

## 决策 1：独立路由而非同页角色分支

- **决策**：`/admin` 与 `/superadmin` 独立，后者组合更多能力。
- **理由**：权限、信息密度和演进节奏不同；高权限页面需要明确边界。

## 决策 2：状态化注销而非物理删除

- **决策**：用户行永久保留，状态改为 deactivated，移除公开资料。
- **理由**：物理删除会破坏论文上传者、审核者、贡献和审计外键。

## 决策 3：动作端点替代通用 User 更新

- **决策**：ban/unban/deactivate/demote 分别定义接口。
- **理由**：每个动作具有不同前置条件、原因、审计和副作用。

## 决策 4：数据库级并发保护最后超管

- **决策**：事务锁定相关 superadmin 行后判断，禁止先 count 后 update。
- **理由**：两个并发降级/注销请求可能各自看到 count=2 并同时成功。

## 决策 5：按 Tab 懒加载

- **决策**：超级管理员工作台仅加载当前面板所需数据。
- **理由**：避免首次进入同时请求论文、用户、申请、图表、快讯和三类审计。
