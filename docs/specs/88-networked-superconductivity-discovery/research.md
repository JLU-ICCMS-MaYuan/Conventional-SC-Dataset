# 技术研究：联网超导资讯发现

## 决策

1. 保留现有定时队列和独立资讯表作为缓存与去重层；联网发现发生在 Python 采集进程，不让 Go API 或浏览器直接访问外部站点。
2. OpenAlex 作为 Crossref 的公开聚合补充，使用 `search=superconduct` 与出版日期过滤；请求端限定 `article` 和期刊主来源，本地再次拒绝明确未发表、未接收及 Zenodo `10.5281/` 仓储 DOI。题名可直接证明相关性；OpenAlex 自动生成的关键词或主题达到最低置信度后才可作为依据；仅摘要命中时还必须存在超导学术上下文。Crossref/OpenAlex 结果必须保留原始 DOI/落地页。
3. OpenAlex 免费接口按 `updated_date` 过滤需要付费计划，不能用于当前无凭证采集。系统因此每次至少滚动回看最近 30 天出版记录，并依靠 DOI/OpenAlex 身份键幂等更新，以覆盖延迟进入索引的论文。
4. 出版商官方入口采用可插拔来源注册表；未配置或不稳定的入口不伪造成功，聚合索引继续提供有限覆盖。
5. 内容语义与展示栏位分离，以兼容 Phys.org 展示在期刊论文栏但仍标注科研报道。
6. Worker 队列连接不设置短读超时；连接失败由入口循环重建连接，容器和本地进程同时保留自动重启能力。
7. arXiv、Crossref、OpenAlex、出版社补充任务和 Phys.org 使用不继承系统代理的直连客户端；Google News 保留系统代理。各来源仍只允许访问固定白名单端点。

## 理由与备选

- 直接让前端抓各出版社会泄露凭证、受 CORS/限流影响，也无法统一去重；因此选择后端采集缓存。
- 只扩展 Crossref 会受索引延迟和题名关键词限制；OpenAlex 可提供第二个公开索引，但不承诺覆盖所有出版社。
- OpenAlex 宽关键词检索会返回仓储上传、错误期刊映射及仅在摘要中提到超导的内容；限制发布状态与期刊来源、拒绝仓储 DOI、过滤低置信度主题并要求摘要的第二个领域信号，可在不引入全文抓取或 AI 分类的前提下排除这类误收。
- 本地系统代理对 OpenAlex 出现连接超时，而同一端点直连成功；Google News 直连受网络限制。按来源选择连接池可以隔离代理故障，同时不取消社会资讯所需的代理能力。
- 不把 Phys.org 改写成同行评审论文；单独保存 `content_type` 与 `display_kind` 可避免数据语义污染。

## 证据

- 现有 #63 采集器固定使用 arXiv、Crossref、Phys.org，`news_feed_items` 仅保存三源结果。
- Crossref 记录 `10.1021/jacs.6c10135` 可单独按题名查到，但宽关键词窗口曾返回空结果，证明需要补充索引与官方入口策略。
- 2026-09-04 使用无写库的真实 OpenAlex 30 天窗口扫描 800 条候选，目标 DOI `10.1021/jacs.6c10135` 被接受；三个已知 Zenodo 脏 DOI 均被拒绝。
- 2026-09-08 验收再次以无写库方式扫描 830 条候选、接受 277 条；目标 DOI 的发现来源为 `openalex`、原文来源为 `acs`，没有 `10.5281/` DOI 被接受。历史已写入的 164 条 Zenodo 记录交由 [Issue #92](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/92) 独立清理。
- RQ Worker 日志显示 Redis 服务仍运行，但 Worker 因长期连接读超时退出；现有 `socket_timeout=10` 与长期阻塞队列不匹配。
