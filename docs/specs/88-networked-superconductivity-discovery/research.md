# 技术研究：联网超导资讯发现

## 决策

1. 保留现有定时队列和独立资讯表作为缓存与去重层；联网发现发生在 Python 采集进程，不让 Go API 或浏览器直接访问外部站点。
2. OpenAlex 作为 Crossref 的公开聚合补充，使用 `search=superconduct` 与日期过滤；Crossref/OpenAlex 结果必须保留原始 DOI/落地页。
3. 出版商官方入口采用可插拔来源注册表；未配置或不稳定的入口不伪造成功，聚合索引继续提供有限覆盖。
4. 内容语义与展示栏位分离，以兼容 Phys.org 展示在期刊论文栏但仍标注科研报道。
5. Worker 队列连接不设置短读超时；连接失败由入口循环重建连接，容器和本地进程同时保留自动重启能力。

## 理由与备选

- 直接让前端抓各出版社会泄露凭证、受 CORS/限流影响，也无法统一去重；因此选择后端采集缓存。
- 只扩展 Crossref 会受索引延迟和题名关键词限制；OpenAlex 可提供第二个公开索引，但不承诺覆盖所有出版社。
- 不把 Phys.org 改写成同行评审论文；单独保存 `content_type` 与 `display_kind` 可避免数据语义污染。

## 证据

- 现有 #63 采集器固定使用 arXiv、Crossref、Phys.org，`news_feed_items` 仅保存三源结果。
- Crossref 记录 `10.1021/jacs.6c10135` 可单独按题名查到，但宽关键词窗口曾返回空结果，证明需要补充索引与官方入口策略。
- RQ Worker 日志显示 Redis 服务仍运行，但 Worker 因长期连接读超时退出；现有 `socket_timeout=10` 与长期阻塞队列不匹配。
