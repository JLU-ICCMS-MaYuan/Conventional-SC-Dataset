# Feature 规格：论文全文解析与 LLM 自动分类

**GitHub Issue**：[＃23](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/23)

**创建日期**：2026-08-19

**状态**：已确认，待实施

## 背景与目标

完善 PDF 上传、全文解析和自动分类链路，解决大文件失败、后台失败假成功、分类工具缺失/参数不一致等问题。用户需要看到可靠的分类、材料类型、判断理由和待审核建议。

## 用户场景与验收

### 用户故事 1：可靠上传与解析状态（优先级：P1）
普通用户上传 PDF 后可看到上传、解析、分类状态；任一步失败都显示明确原因，不显示假成功。

**验收**：大 PDF、解析失败、数据库失败分别验证状态和错误信息。

### 用户故事 2：全文分类与解释（优先级：P1）
系统全文分段读取并汇总证据，判断论文整体类型和理论二级类型，并在网页显示理由。

**分类规则**：理论主导归 `theoretical`；实验主导归 `experimental`；理论和实验都重要且无法分主次时归 `experimental`；综述归 `review`。理论二级类型为 `calculation`、`method`、`theory`。

### 用户故事 3：材料类型建议与审核（优先级：P2）
用户可选已有类型、采用 AI 建议或手动填写新类型；新类型可先入库并标记待管理员确认，不阻塞上传；管理员可接受、修改、合并或拒绝。

### 边界与异常场景
- 文本抽取失败或 LLM 超时：显示失败/无法判断原因，不伪造成功。
- 论文整体分类与每条物性数据的实验/理论属性分开。
- 材料类型不在现有列表：允许新类型；近似重复由管理员处理。

## 需求

### 功能需求
- **FR-001**：反馈上传、解析、分类当前状态及失败原因。
- **FR-002**：支持生产环境大 PDF 请求并传递代理错误。
- **FR-003**：全文分段读取论文，再汇总分类证据。
- **FR-004**：按核心贡献和理论/实验服务关系判断论文整体类型。
- **FR-005**：支持理论二级类型 `calculation`、`method`、`theory`。
- **FR-006**：显示分类理由和证据。
- **FR-007**：允许已有、AI 建议和用户自定义类型共同作为提交选项。
- **FR-008**：新材料类型可先入库并标记待管理员确认。
- **FR-009**：管理员可接受、修改、合并或拒绝新类型。
- **FR-010**：论文整体类型与物性数据实验/理论属性独立。
- **FR-011**：修复 `paper_is_experimental`、`infer_sc_type`、`rebuild_from_clean_results` 导入、参数和错误传播问题。

### 关键实体
- 论文分类结果：整体类型、理论二级类型、材料类型、理由、证据、来源和审核状态。
- 材料类型建议：名称、来源、理由、审核状态及管理员处理结果。
- 物性数据来源属性：每条物性数据独立标记实验或理论。

## 成功标准
- **SC-001**：上传、解析、分类失败均显示具体原因，零假成功提示。
- **SC-002**：分类读取完整论文文本，非固定前几页或固定字符数。
- **SC-003**：基准论文分类符合规则，且有理由和证据。
- **SC-004**：用户可提交新材料类型，管理员可完成审核闭环。
- **SC-005**：物性数据实验/理论属性不因论文整体分类改变。

## 假设与依赖
- LLM API 由部署方提供；本 Feature 定义输入输出和失败语义，不绑定供应商。
- #19 负责上传链路基础错误；#22 负责缺失工具恢复；本 Feature 统一其契约。
- 不新增失败历史垃圾记录；当前处理状态使用现有状态机制，材料类型建议按审核需要持久化。

## 范围外事项
- 实验论文二级分类暂不实现。
- 不增加刷新后的重试按钮；用户刷新后重新上传。
- 新类型不自动永久加入正式枚举，须经管理员审核。
