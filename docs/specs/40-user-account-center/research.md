# 技术研究：用户中心与账户安全

## 决策 1：资料接口与公开接口分离

- **决策**：本人完整资料使用 `/api/account/profile`，公开资料由 #41 独立白名单接口提供。
- **理由**：避免复用 ORM JSON 时泄漏邮箱和账号状态。
- **备选方案**：同一接口按身份裁剪；拒绝，因为缓存和匿名行为更难验证。

## 决策 2：头像使用独立服务

- **决策**：头像落入独立持久卷，数据库只保存随机对象键，Go 负责解码、裁剪和读取。
- **理由**：论文上传目录有 24 小时清理生命周期，不能复用。
- **备选方案**：数据库 BLOB 或外部 URL；分别增加数据库体积和供应链隐私风险。

## 决策 3：ORCID 使用标准校验位

- **决策**：保存规范化 `0000-0000-0000-000X` 格式并建立唯一索引。
- **理由**：格式检查不足以发现误填，唯一约束可处理并发绑定。

## 决策 4：会话撤销统一化

- **决策**：改密只递增 `session_version`，认证中间件统一拒绝旧版本。
- **理由**：同一机制可被封禁、注销和角色治理复用。
- **备选方案**：Redis Token 黑名单；需要存储每个 Token 且生命周期长。
