# Feature 规格：实验 Tc 的条件字段与计算上下文一致性

**GitHub Issue**：[#84](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/84)

**创建日期**：2026-09-03

**状态**：实施完成，等待后续迁移链恢复后关闭 Issue

## 背景与目标

当前共享材料状态编辑器先按论文级 `superconductor_kind` 决定是否展示 λ、ωlog、μ*，新增条目又按材料状态 `state_kind` 推断方法。这使每条 Tc 的实际 `tc_method` 不能成为字段集的唯一依据，实验 Tc 仍可能保留理论计算参数。

本 Feature 将 `tc_method` 定义为每条 Tc 的权威开关：`experimental` 条目只含测得的 Tc 数据与实验上下文，任何计算上下文均非法。该规则必须在上传校对、用户审核 AI 表单、管理员和超级管理员科学数据编辑，以及数据库持久化中一致成立。

## 用户场景与验收

### 用户故事 1：上传者校对实验 Tc（优先级：P1）

上传者新增或编辑一条 Tc，先选择 Tc method；选中实验方法后，只填写 Tc 数值、范围、原始值/单位和证据。

**优先级理由**：这是错误产生的首要入口。

**独立验收**：在上传校对页添加 Tc、选择 `experimental` 并提交，草稿和数据库均不存在计算上下文。

**验收场景**：

1. **假如** 一条 Tc 当前使用理论方法并有 λ、ωlog、μ*，**当** 用户改选 `experimental`，**那么** 三项输入立即消失且草稿删除该条目的 `calculation_context`。
2. **假如** 用户新增 Tc，**当** 尚未选择方法，**那么** 不出现理论计算参数；选择非实验方法后才显示参数输入。

### 用户故事 2：审核者修正论文科学数据（优先级：P1）

管理员或超级管理员在编辑论文页修改 Tc 时，得到与用户审核表单相同的条件字段和清理行为。

**优先级理由**：#76 明确要求两个入口共用编辑器，规则不能漂移。

**独立验收**：编辑已存在论文的实验 Tc 并保存，科学数据整体重建后不存在关联计算上下文。

**验收场景**：

1. **假如** 管理员编辑一条 Tc，**当** 选择 `experimental`，**那么** 只显示实验 Tc 所需字段，保存请求不含计算参数。

### 用户故事 3：数据维护者防止绕过界面写入（优先级：P1）

无论请求来自上传提交还是管理员科学数据重写，服务端和数据库均拒绝或阻断实验 Tc 关联计算上下文。

**优先级理由**：客户端隐藏字段不能作为数据完整性保证。

**独立验收**：向两个 API 发送 `tc_method='experimental'` 与非空计算上下文，均得到定位到 Tc 条目的 400，且事务未产生部分数据。

**验收场景**：

1. **假如** 历史数据中实验 Tc 曾关联计算上下文，**当** 数据迁移执行，**那么** 实验 Tc 的外键被清空，只由这些 Tc 引用的上下文被删除，理论数据不变。

### 边界与异常场景

- `tc_method='other'`、`unknown` 或任何理论方法都不视为实验方法；其计算上下文仍遵循已有理论 Tc 约束。
- 前端切换到实验方法必须清除整个条目级 `calculation_context`，而不是只清空三个数值，避免证据或附加计算字段残留。
- 历史计算上下文同时被非实验 Tc 或普通物性引用时不得删除；只解除实验 Tc 关联。
- `result_kind` 与 `tc_method` 不一致时，以方法语义校验并拒绝，不能静默改写用户输入。

## 需求

### 功能需求

- **FR-001**：每条 Tc 的编辑 UI 必须先提供 `tc_method`，并仅以该值决定计算参数字段是否渲染。
- **FR-002**：当 `tc_method='experimental'` 时，UI 必须删除该条目的 `calculation_context`，提交负载不得含 `lambda_ep`、`omega_log_k` 或 `mu_star`。
- **FR-003**：上传校对、用户审核 AI 表单、管理员和超级管理员编辑页必须复用同一 Tc 编辑规则与组件行为。
- **FR-004**：上传草稿保存、上传提交和 `PUT /api/rag/papers/{paper_id}/scientific-draft` 必须拒绝实验 Tc 的非空计算上下文，并返回包含材料状态和 Tc 序号的错误。
- **FR-005**：持久化层必须以 `tc_method` 强制实验条目 `result_kind='experimental'`、`calculation_context_id IS NULL`、`experimental_context_id IS NOT NULL`；非实验条目必须是理论结果并关联计算上下文。
- **FR-006**：数据库迁移必须清理历史实验 Tc 的计算上下文关联，并仅删除不再被任何 Tc 或普通物性引用的孤立上下文。
- **FR-007**：迁移后数据库约束必须阻止任何绕过应用层的违例写入。
- **FR-008**：`Tc method` 选项的提交值保持英文稳定枚举；界面按当前语言显示。中文界面必须为每个选项提供中文说明，专有方法名可保留原文。

### 关键实体

- **TcResult**：一条材料状态下的临界温度结果，`tc_method` 决定其结果语义和允许关联。
- **CalculationContext**：理论 Tc 或理论普通物性的 λ、ωlog、μ* 等计算条件；实验 Tc 不得关联。
- **ExperimentalContext**：实验 Tc 的测量条件；实验 Tc 必须关联。

## 成功标准

- **SC-001**：三个编辑入口对 `experimental` Tc 都只显示 Tc 所需字段，端到端 UI 回归测试通过。
- **SC-002**：对所有新写入和迁移后的实验 Tc，查询结果均满足 `calculation_context_id IS NULL` 与 `experimental_context_id IS NOT NULL`。
- **SC-003**：向任一科学数据写入接口提交实验 Tc 计算参数时，100% 返回 400 且无部分持久化。
- **SC-004**：迁移前后有效理论 Tc 及其关联 `CalculationContext` 的计数和关联关系保持不变。
- **SC-005**：中文界面的 `Tc method` 下拉选项均为中文可读标签，不把英文枚举值写入草稿或数据库。

## 假设与依赖

- #32 已存在 `tc_results`、`calculation_contexts` 和 `experimental_contexts` 结构；本 Feature 只收紧既有语义。
- #52、#76 的共享 `MaterialStatesEditor` 是三个前端入口的共同实现点。
- MySQL 版本支持现有 `CHECK` 约束并会实际执行。

## 范围外事项

- 不新增或删除理论 Tc 方法枚举。
- 不改变论文详情页对已有理论计算上下文的只读内容。
- 不依据论文级类型或材料状态类型自动替用户选择 Tc method。
