# 技术研究：英文规范值与无建议副本

**GitHub Issue**：[#85](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/85)

## R1：单一英文 canonical draft

**决策**：审核表单、提交快照和 MySQL 只使用英文 canonical draft，不再维护展示用复制对象。

**理由**：两份内容相近的数据会产生语言漂移、额外模型调用和审核困扰。单一事实来源让用户编辑、服务端校验和持久化保持一致。

**备选方案**：仅隐藏建议区。拒绝，因为 Redis、产物和 Worker 仍会保留不需要的内容与调用成本。

## R2：原文证据独立保留

**决策**：`quote`、标题、摘要、作者和原始数值不受英文验证约束，证据组件只显示这些原文资料。

**理由**：它们是可追溯来源，不是模型归纳。翻译会破坏逐字核验能力。

## R3：有界历史兼容

**决策**：读取旧草稿可忽略 `ai_original`；任何保存、提交或新任务不再写入建议字段。活动 Pb 任务作定向清理。

**理由**：避免因旧 Redis 数据让页面失败，同时不让兼容分支扩散到正常数据路径。

## R4：证据不是建议，也不是绝对原文

**决策**：保留非空 `quote`，但默认折叠为“论文片段”；空 `quote` 不渲染。上传审核页面不再使用“原文”标记该内容。

**理由**：证据链对人工复核仍有价值，删除会损失出处；但 PDF OCR/文本提取可能损坏字符，直接称“原文”会给出错误的可靠性暗示。默认展开的大块引文还会被用户误认为逐字段 AI 建议。

**备选方案**：完全删除所有 `quote`。拒绝，因为这会破坏已有的人工核对能力，且不符合已确认的保留来源文本边界。
