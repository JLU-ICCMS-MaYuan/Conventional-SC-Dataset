# Feature 规格：修复超级管理员删除文献操作的级联删除

**GitHub Issue**：[#60](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/60)

**创建日期**：2026-08-31

**状态**：草稿

## 背景与目标

当前超级管理员在论文审核页面删除文献后，只删除了部分关联数据（`key_properties` 和 `papers` 表记录），导致大量关联数据（材料状态、Tc 结果、晶体结构、审核历史等）仍保留在数据库中，形成孤儿数据。

本 Feature 修复删除操作，使其真正从数据库彻底删除论文及其所有关联数据，避免数据孤岛和存储浪费。

**业务价值**：
- 数据治理：避免孤儿数据累积，保持数据库整洁
- 存储优化：彻底删除无用数据，释放存储空间
- 一致性保障：删除操作覆盖所有关联系统（MySQL、Qdrant、Neo4j）

## 用户场景与验收

### 用户故事 1：超级管理员彻底删除单篇论文（优先级：P1）

超级管理员在论文审核页面发现一篇错误上传或重复的论文，希望将其彻底从系统中删除，包括所有提取的科学数据和关联记录。

**优先级理由**：这是修复现有 bug 的核心功能，影响数据一致性和存储管理。

**独立验收**：删除论文后，数据库中不再存在该论文的任何关联记录，向量库和图数据库中的对应数据也被清理。

**验收场景**：

1. **假如** 超级管理员在论文审核页面看到一篇论文（记录数 > 0），**当** 点击删除图标并确认删除，**那么**：
   - 论文记录从 `papers` 表中删除
   - 所有关联的材料状态、Tc 结果、晶体结构等数据被级联删除
   - Qdrant 中的论文向量被删除
   - Neo4j 中的论文节点和关系被删除
   - 删除后刷新页面，论文不再出现在列表中
   - 论文总数统计正确更新

2. **假如** 超级管理员在论文审核页面看到一篇论文（记录数 = 0），**当** 点击删除图标并确认删除，**那么**：
   - 论文记录从 `papers` 表中删除
   - 相关的审核历史、证据、分块等元数据被删除
   - 删除后刷新页面，论文不再出现在列表中

3. **假如** 删除操作过程中发生错误（如数据库连接中断），**当** 事务回滚，**那么**：
   - 所有已删除的数据恢复（事务保证原子性）
   - 前端显示错误提示："删除失败，请重试"
   - 论文及其关联数据保持完整

### 用户故事 2：超级管理员批量删除多篇论文（优先级：P1）

超级管理员需要清理多篇待审核的垃圾论文，希望能批量删除以提高效率。

**优先级理由**：批量操作是高频场景，提升管理效率。

**独立验收**：批量删除多篇论文后，所有选中论文及其关联数据被彻底删除。

**验收场景**：

1. **假如** 超级管理员选中 3 篇论文（勾选复选框），**当** 点击"批量删除"按钮并确认，**那么**：
   - 3 篇论文及其所有关联数据被删除
   - 删除操作在一个事务中完成
   - 用户贡献统计正确更新（删除论文的上传者贡献数减少）
   - 前端显示成功提示："批量删除完成"

2. **假如** 批量删除中某篇论文的外部依赖清理失败（如 Qdrant 连接超时），**当** MySQL 事务已提交但外部清理失败，**那么**：
   - 前端显示警告："论文已从数据库删除，但向量库清理失败，请检查外部服务"
   - 记录错误日志，便于后续手动清理

### 边界与异常场景

- **权限控制**：只有超级管理员（`role = 'superadmin'`）可以删除论文
- **状态无关**：可以删除任何审核状态（pending/approved/rejected）的论文
- **并发删除**：两个管理员同时删除同一篇论文，第二个操作应返回 404 而非报错
- **部分失败**：MySQL 删除成功但 Qdrant/Neo4j 清理失败时，记录日志并提示管理员
- **上传任务保留**：删除论文时保留 `upload_tasks` 记录但清空 `paper_id` 引用（用于审计）
- **共享实体保留**：删除 `material_states` 但保留 `superconductors` 记录（可能被其他论文引用）

## 需求

### 功能需求

- **FR-001**：系统必须在超级管理员删除论文时，级联删除以下关联数据：
  - `key_properties`（关键物性）
  - `material_states`（材料状态）
  - `tc_results`（Tc 结果）
  - `calculation_contexts`（计算上下文）
  - `experimental_contexts`（实验上下文）
  - `structures`（晶体结构）
  - `paper_chunks`（论文分块）
  - `paper_evidences`（证据快照）
  - `paper_review_events`（审核历史）

- **FR-002**：系统必须在删除论文后，清理 Qdrant 向量库中的对应向量记录。

- **FR-003**：系统必须在删除论文后，清理 Neo4j 图数据库中的对应论文节点和关系。

- **FR-004**：系统必须在删除论文时，将 `upload_tasks` 表中对应记录的 `paper_id` 设为 NULL（保留审计记录）。

- **FR-005**：系统必须在删除论文时，保留 `superconductors` 表中的超导材料记录（可能被多篇论文共享）。

- **FR-006**：系统必须使用数据库事务保证删除操作的原子性：所有 MySQL 删除操作要么全部成功，要么全部回滚。

- **FR-007**：系统必须在删除成功后清理相关缓存：`chart:*`、`search:*`、`community:contributions:*`。

- **FR-008**：系统必须在批量删除时，对每篇论文独立处理外部清理（Qdrant/Neo4j），单个失败不影响其他论文。

- **FR-009**：系统必须在删除失败时返回明确的错误信息，区分数据库错误、权限错误和外部服务错误。

### 关键实体

**论文（Paper）**：
- 主实体，拥有唯一 ID
- 关联多个材料状态、关键物性、审核历史等子实体
- 删除论文时级联删除所有子实体

**材料状态（MaterialState）**：
- 一篇论文中的一个条件化材料状态（如不同压强下的同一材料）
- 关联 Tc 结果、晶体结构、计算/实验上下文
- 通过 `superconductor_id` 引用共享的超导材料记录

**超导材料（Superconductor）**：
- 规范化的材料记录（化学式、组成等）
- 可被多篇论文的 `material_states` 引用
- 删除论文时不删除此表记录

**上传任务（UploadTask）**：
- 记录论文的上传历史
- 删除论文时清空 `paper_id` 但保留任务记录（审计需求）

## 成功标准

- **SC-001**：删除单篇论文后，直接查询数据库，该论文的所有关联记录（FR-001 列出的 9 张表）均不存在。

- **SC-002**：删除单篇论文后，调用 Qdrant API 查询该论文的 DOI，返回空结果。

- **SC-003**：删除单篇论文后，调用 Neo4j Cypher 查询该论文节点，返回空结果。

- **SC-004**：批量删除 N 篇论文后，论文总数统计减少 N，用户贡献数统计正确更新。

- **SC-005**：删除操作中途失败（如数据库连接中断）时，事务回滚，论文及其关联数据保持完整，前端收到错误提示。

- **SC-006**：删除已被其他论文引用的超导材料的论文时，`superconductors` 表中的材料记录仍存在。

- **SC-007**：删除论文后，`upload_tasks` 表中对应记录的 `paper_id` 为 NULL，但任务记录本身存在。

## 假设与依赖

- Go 后端可以访问 Python FastAPI 服务的内部端点（用于 Qdrant/Neo4j 清理）
- Qdrant 和 Neo4j 服务正常运行，API 可访问
- 数据库支持事务（MySQL InnoDB 引擎）
- 前端已有删除确认交互（`window.confirm`）

## 范围外事项

- **不提供软删除**：本 Feature 只实现物理删除，不提供标记删除或回收站功能
- **不迁移历史数据**：不处理已存在的孤儿数据，只保证新的删除操作正确
- **不实现删除权限细化**：权限保持为"仅超级管理员"，不支持普通管理员删除
- **不实现批量删除的部分成功处理**：MySQL 事务要么全部成功要么全部失败，不支持"删除部分论文"
- **不清理已导出的数据**：如果论文数据已通过导出功能下载，删除操作不影响已导出文件

## 澄清记录

### 2026-08-31

- 问：删除操作是否需要检查论文的审核状态？ → 答：不需要，超级管理员可以删除任何状态的论文。
- 问：`superconductors` 表是否需要级联删除？ → 答：不删除，因为同一材料可能被多篇论文引用。
- 问：`upload_tasks` 表的处理方式？ → 答：保留任务记录，但清空 `paper_id` 引用（用于审计）。
- 问：删除后是否需要清理 Qdrant 和 Neo4j？ → 答：都需要清理，保证数据一致性。
- 问：级联删除的实现方式？ → 答：使用应用层级联删除（在 Go 代码中显式删除），而非数据库外键的 ON DELETE CASCADE。
