# Feature 规格：论文详情数据一致性（后端读取契约补全）

**GitHub Issue**：[#57](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/57)

**创建日期**：2026-08-27

**状态**：草稿

## 背景与目标

用户提交论文后，只读「论文详情」页展示的内容与提交时的结构化数据不一一对应：Tc、电声耦合常数等核心科学数据完全不显示，物性名称为空，Issue #54 刚验收入库的压强单臂区间也看不见。用户认可正式记录不可修改，但要求展示内容至少与提交内容统一。

根因不在前端排版，而在**后端读取契约**：论文详情接口既不查询承载核心科学数据的表，也把一批永不读库的兼容字段当作真实数据序列化输出，同时裁剪掉材料状态的大部分字段。同一批兼容字段还使记录搜索接口查询一张已不存在的表，以及使管理员修改物性静默失效。

本 Feature 的目标是让论文的正式科学数据能被真实、完整、无恒零值地读出，并使所有依赖这批数据的接口回到真实数据源。展示层的字段集与排版对齐由 [#59](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/59) 承担。

Bug 分类：**原设计缺陷**。数据模型迁移到条件化科学实体（`material_states` / `tc_results` / `calculation_contexts` / `superconductor_properties`）后，读取侧沿用了旧 `key_properties` 的字段假设，靠 `gorm:"-"` 兼容字段维持编译通过，读取契约从未随写入契约一起迁移。

## 用户场景与验收

### 用户故事 1：提交者能完整复查自己提交的科学数据（优先级：P1）

**优先级理由**：这是 Issue 的直接诉求，也是「提交内容与展示内容统一」的核心。当前 Tc 这类最关键的数据完全不可见，用户无法确认自己提交的内容是否被正确保存。

**独立验收**：打开一篇已提交论文的详情页，其中的临界温度、电声耦合常数、压强区间与原文压强表述均可见，且与数据库中该论文的记录逐项一致。

**验收场景**：

1. **假如** 论文 4 已提交且库中有 1 条 Tc 结果（274 K）与 2 条计算上下文（含 λ=2.56、μ*=0.1），**当** 请求该论文详情，**那么** 响应中包含这条 Tc 结果与这两条计算上下文的数值。
2. **假如** 论文 4 的材料状态记录了压强值 250 GPa、压强下限 200 GPa、无上限、原文表述 `above 200 GPa`，**当** 请求该论文详情，**那么** 响应中这四项均可取得。
3. **假如** 论文 4 的材料状态记录了报告空间群 `Fm-3m`、国际群号 225、晶系 cubic，**当** 请求该论文详情，**那么** 这三项均可取得。
4. **假如** 论文 4 有一条物性，其名称为 `thermodynamic stability`、数值 200、单位 `meV/atom`，**当** 请求该论文详情，**那么** 该物性的名称非空且与库中一致。

### 用户故事 2：详情数据中不再出现恒定无意义的字段（优先级：P1）

**优先级理由**：恒零值字段是「物性对不上」的直接原因。字段存在但永远为空/false，比字段缺失更具误导性——消费方无法区分「该论文确实没有此数据」与「系统从不读取此数据」。

**独立验收**：论文详情响应中，任一字段的值要么来自数据库真实列，要么该字段不存在；不存在其值与库内容无关的字段。

**验收场景**：

1. **假如** 请求任一论文详情，**当** 检查其物性条目，**那么** 不含任何值恒为空字符串、恒为 null 或恒为 false 且与库内容无关的键。
2. **假如** 某物性在库中确有条件说明，**当** 请求详情，**那么** 该说明来自数据库列而非兼容字段。

### 用户故事 3：依赖同批数据的其他功能回到真实数据源（优先级：P1）

**优先级理由**：这批兼容字段被记录搜索与管理员物性编辑共同依赖，二者当前均已失效。若只修详情页，兼容字段无法删除（编译依赖仍在），用户故事 2 只能做一半，且会留下「详情页对了、搜索仍为空」的行为分裂。

**独立验收**：记录搜索能返回符合条件的已批准论文记录；管理员修改物性后，改动能在库中生效。

**验收场景**：

1. **假如** 库中存在符合筛选条件的已批准论文记录，**当** 执行记录搜索，**那么** 返回这些记录，且服务端日志无「表不存在」错误。
2. **假如** 记录搜索按压强、超导类型或主记录标记筛选，**当** 执行搜索，**那么** 筛选基于数据库中真实存在的列，结果与库内容一致。
3. **假如** 管理员修改某物性的名称与数值并保存，**当** 重新读取该物性，**那么** 修改已生效。
4. **假如** 管理员提交的字段在当前数据模型中没有对应列，**当** 保存，**那么** 系统不静默丢弃该字段，而是明确不接受它。

### 边界与异常场景

- 论文没有任何 Tc 结果或计算上下文时，对应数据段为空集合而非缺失键或 null，消费方无需区分两种「无数据」形态。
- 材料状态的可选字段（压强上限、磁场、备注等）在库中为 NULL 时，保持为 null 并可与「值为 0」区分。
- 压强只有单臂区间（只有下限或只有上限）时，缺失的一侧保持 null，不补造边界；这是 #54 已确认的入库语义。
- 物性的原文值与解析数值不一致时（如原文 `0` 而解析值 200），两者都原样返回，由展示层决定优先级；本 Feature 不修正历史数据。
- 论文无结构模型数据时，结构相关数据段为空集合；当前全库无结构模型记录，空态是唯一可实测路径。
- 权限判定不因新增数据段而改变：#56 已确立的逐篇后端鉴权继续生效，新增数据段随论文整体一起受同一权限控制。

## 需求

### 功能需求

- **FR-001**：论文详情必须包含该论文全部 Tc 结果，含结果类型、Tc 判定方法、Tc 数值及其区间与不确定度、原文值与原文单位。
- **FR-002**：论文详情必须包含该论文全部计算上下文，含电声耦合常数、μ*、ωlog 及计算方法相关字段。
- **FR-003**：论文详情的材料状态必须包含压强的值、下限、上限、原文表述与原文单位，使单臂区间可被识别。
- **FR-004**：论文详情的材料状态必须包含报告空间群符号与国际群号、温度值与原文温度、磁场、状态类型与备注。
- **FR-005**：论文详情的物性必须显示来自数据库的真实名称，名称不得为空字符串。
- **FR-006**：论文详情响应中不得包含其值与数据库内容无关的字段；无法映射到真实数据列的字段必须从输出中移除。
- **FR-007**：记录搜索必须查询当前数据模型中真实存在的表与列，不得依赖已废弃的表名。
- **FR-008**：记录搜索的压强、超导类型与主记录筛选必须基于真实数据列求值，筛选结果与库内容一致。
- **FR-009**：管理员对物性的新建与更新必须写入真实数据列；系统不得接受并静默丢弃无对应列的字段。
- **FR-010**：既有可见行为不得回归，包括论文详情的权限判定、已有字段的取值、图表分组编辑与分享页的既有布局。

### 关键实体

- **材料状态**：一篇论文中一个「材料 + 条件」组合，承载压强（值/下限/上限/原文）、温度、磁场、晶系、报告空间群、状态类型与备注。其余科学数据均挂在材料状态之下。
- **Tc 结果**：隶属材料状态的临界温度测定或计算结果，区分理论与实验来源，保留判定方法与原文表述。
- **计算上下文**：隶属材料状态的计算条件，承载电声耦合常数 λ、μ*、ωlog 与计算方法。
- **物性**：隶属材料状态的其他数值型性质，真实名称来自物性定义或原文名称，数值区分原文值与解析值。

## 成功标准

- **SC-001**：论文 4 详情中可取得 Tc=274 K、λ=2.56、μ*=0.1，且物性名称非空。
- **SC-002**：论文 4 详情中可取得压强值 250 GPa、下限 200 GPa、原文 `above 200 GPa`、空间群 `Fm-3m`/225。
- **SC-003**：论文详情响应的字段集与库中该论文的材料状态、Tc 结果、计算上下文、物性记录逐项一致，无恒零值字段。
- **SC-004**：记录搜索对含已批准论文的数据集返回非空结果，服务端日志无「表不存在」错误。
- **SC-005**：管理员修改物性名称与数值后，改动在库中可查证。
- **SC-006**：Go 与前端既有测试全部通过，新增数据段与字段映射有测试覆盖。

## 假设与依赖

- Go 侧 `TcResult`、`CalculationContext`、`StructureModel` 模型与 `MaterialState` 上的关联关系已定义完整，本 Feature 无需新增建模（已核实）。
- `superconductor_properties` 表不含 `pressure_gpa`、`temperature_k`、`superconductor_type`、`is_primary`、`name`、`structure_text` 等列；这些概念在新模型中由材料状态或物性定义承载（已核实表结构）。
- 物性真实名称可由物性定义的展示名或原文名称取得（论文 4 两者均为 `thermodynamic stability`）。
- 当前 dev 环境无已批准论文，SC-004 的非空结果需构造已批准数据后验证。
- 当前全库无结构模型记录，结构相关验收只能覆盖空态。
- 本 Feature 是 #59 的前置：#59 依赖本 Feature 提供的完整读取契约，其根因 3 依赖本 Feature 的用户故事 2。

## 范围外事项

- 详情页字段集与校对表单的排版对齐、结构预览改源、研究方法与分类理由的展示语义：属 #59。
- 详情页入口与路由可达性：#56 已完成。
- AI 解析完整性；论文 4 的 27 个材料状态入库 1 个已确认为用户在校对页主动删除，非缺陷。
- 论文编辑能力与管理员审核流程的功能性改动。
- 提交期写入的历史数据不一致（论文 4 物性原文值 `0` 而解析值 200）：属写入侧问题，本 Feature 只如实呈现两者。
- `PaperEditView` 的死代码清理：该组件是否保留取决于 #59 是否以校对页只读模式替代它，在 #59 中一并决策，避免先清理再整体删除的重复劳动。
