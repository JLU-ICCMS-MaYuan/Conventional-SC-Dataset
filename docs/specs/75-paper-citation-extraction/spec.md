# Feature 规格：材料状态「材料」字段改名为「化学式」

**GitHub Issue**：[#75](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/75)

**创建日期**：2026-09-01

**状态**：草稿

## 背景与目标

上传校对页材料状态卡片的首个输入框标签为「材料」，但该字段实际承载的一直是化学式：其值经 `backend/ingest/scientific_drafts.py:220` 传入 `_get_or_create_superconductor`，最终落到 `superconductors.chemical_formula`；`backend/ingest/upload_jobs.py:934` 还用 `_formula_from_material` 对它做化学式归一化，并据此计算元素种类数。

标签与实际语义不符，用户无法判断该填化学式（`LaH10`）还是材料通称（`lanthanum hydride`）。填入通称会导致化学式归一化失败、元素种类数算不出来，且与数据库导出表单的 `chemical_formula` 列对不上。

本 Feature 把真正承载化学式的界面标签改名为「化学式」，使标签与落库语义、导出表单列名三者一致。字段名与数据库列名不变。

## 用户场景与验收

### 用户故事 1：上传者明确知道该填化学式（优先级：P1）

上传者在校对页填写材料状态时，首个输入框明确标示「化学式」，据此填入 `LaH10` 而非材料通称。

**优先级理由**：这是本 Feature 的核心价值，也是错填的主要发生位置。上传校对是数据进入系统的第一道关口，此处填错会连带影响元素种类数、化学式检索与图表上点。

**独立验收**：打开校对页材料状态卡片，首个输入框标签为「化学式」；英文界面为 `Chemical formula`。

**验收场景**：

1. **假如** 上传者打开校对页的材料状态卡片，**当** 查看首个输入框，**那么** 标签显示「化学式」。
2. **假如** 界面语言为英文，**当** 查看该输入框，**那么** 标签显示 `Chemical formula`。
3. **假如** 上传者在该框填入化学式并提交，**当** 请求发出，**那么** 请求体的字段名仍为 `material`，接口契约不变。
4. **假如** 上传者未填写该框即提交，**当** 后端返回校验错误，**那么** 提示文案指明缺少的是化学式，且页面仍能定位到出错的材料状态卡片。

### 用户故事 2：管理员编辑物性时标签一致（优先级：P2）

管理员在编辑论文的物性数据时，对应输入框标签同样标示化学式。

**优先级理由**：排在 P1 之后。管理员编辑的是已入库数据，量少且有专业背景，误填风险低于上传环节；但标签一致性仍有必要，避免同一概念在两个页面用两种叫法。

**独立验收**：管理员编辑弹窗的物性行中，该输入框标签为「化学式 (material)」。

**验收场景**：

1. **假如** 管理员打开论文编辑弹窗的物性数据区，**当** 查看该输入框，**那么** 标签显示「化学式 (material)」，括号内保留字段名以便对照接口。
2. **假如** 界面语言为英文，**当** 查看该输入框，**那么** 标签显示 `Chemical formula (material)`。

### 边界与异常场景

- 校验错误定位：后端错误文案的「第 N 个材料状态」前缀是前端定位出错卡片的依据（`frontend/src/components/UploadTaskEditor.tsx:148` 的正则 `/第\s*(\d+)\s*个材料状态/`）。改名只改该文案的后半句，前缀必须保留，否则定位失效且不报错。
- 图表组合的自定义点标签：该处标签虽写作「材料名」，但绑定的是图表数据点显示标签，允许填 `LaH10 @ 200GPa` 这类非纯化学式内容，不参与化学式落库。本 Feature 不改动该处（见范围外事项）。
- 「材料家族」「材料维度」「研究材料」等标签语义正确，不在改名范围内。

## 需求

### 功能需求

- **FR-001**：上传校对页材料状态卡片承载化学式的输入框标签必须显示为「化学式」。
- **FR-002**：管理员编辑页物性数据中承载化学式的输入框标签必须显示为「化学式 (material)」。
- **FR-003**：上述标签必须在中英两种语言下都有对应文本。
- **FR-004**：改名不得改变请求体与响应体的字段名，`material` 键保持不变。
- **FR-005**：改名不得改变数据库列名，`superconductors.chemical_formula` 与 `superconductor_properties.material_raw` 保持不变。
- **FR-006**：化学式缺失的后端校验文案必须指明缺少的是化学式。
- **FR-007**：校验文案必须保留「第 N 个材料状态」前缀，使前端仍能解析序号并定位到出错卡片。
- **FR-008**：语义正确的既有标签（材料家族、材料维度、研究材料）不得改动。

### 关键实体

不涉及新实体或字段变更。本 Feature 只改展示标签与校验文案。

## 成功标准

- **SC-001**：两处目标标签在中英两种语言下均显示为化学式相关文案，无遗漏。
- **SC-002**：改名前后提交同一份草稿，请求体逐键比对完全一致。
- **SC-003**：化学式留空提交时，错误提示含「化学式」字样，且出错卡片被正确定位并滚动到可见区域。
- **SC-004**：既有自动化测试在文案断言同步更新后全部通过，无行为回归。

## 假设与依赖

- 依赖 [Issue #74](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/74) 的 i18n 基建先落地，两处新标签直接以双语字典方式编写，避免先写中文再返工。
- 数据库列名 `material_raw` 语义确为「原文材料名」，与 `chemical_formula` 是两个不同的量，因此不改列名不构成语义遗留问题。
- 后端校验文案与前端定位正则的耦合已由 `tests/01_decentralized_uploading/submit-validation-feedback.test.tsx` 固定，文案改动会被测试立即发现。

## 范围外事项

- 修改 JSON 字段名 `material`。改名需同步前端、Go、Python、LLM prompt 与既有草稿数据，收益仅为命名美观，风险不成比例。
- 修改数据库列名 `superconductors.chemical_formula` 与 `superconductor_properties.material_raw`。迁移风险远大于收益，且 `material_raw` 语义本就不是化学式。
- 修改 LLM prompt 中的 `material` 键名。它与草稿结构和既有 review artifact 快照绑定。
- 图表组合编辑器的「材料名」标签。该字段是图表数据点的显示标签而非化学式，改名会误导用户（见澄清记录）。
- 「材料家族」「材料维度」「研究材料」等语义正确的标签。

## 澄清记录

### 2026-09-01

- 问：Issue 正文列出的三处标签是否都该改为「化学式」？ → 答：只改两处。核查 `frontend/src/components/ChartGroupEditor.tsx:490` 的「材料名」后确认，它绑定 `customLabel`，同时写入 `material` 与 `custom_label` 两个字段（第 230–235 行），用途是图表上自定义数据点的显示标签，允许填入 `LaH10 @ 200GPa` 这类非纯化学式内容，且不参与 `superconductors.chemical_formula` 落库。改名为「化学式」会错误地限制用户输入，故排除该处并记入范围外事项。Issue 正文的原始判断在此点上不准确。
