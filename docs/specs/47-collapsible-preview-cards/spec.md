# Feature 规格：AI 临时表单字段卡片渐进展开

**GitHub Issue**：[#47](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/47)

**创建日期**：2026-08-24

**状态**：草稿

## 背景与目标

“上传论文”页面的“AI 临时表单”会持续展示 AI 已填写的候选值、来源定位和证据句。字段内容较多时，单张卡片会占用大量纵向空间，用户需要长距离滚动才能扫描同组其他字段，也难以快速定位真正需要核对的冲突项。

本 Feature 为内容溢出的字段卡片增加默认收起和独立展开能力。页面保持现有响应式列宽，短内容直接完整显示；用户只在需要时展开长内容，并可再次收起，从而兼顾快速扫描和证据完整性。

## 用户场景与验收

### 用户故事 1：快速扫描临时表单（优先级：P1）

作为正在等待论文解析的科研用户，我希望超长字段默认收起、短字段直接完整显示，以便快速浏览标题、DOI、作者、期刊等字段并发现冲突状态。

**优先级理由**：这是本 Feature 直接解决的主要问题；没有默认收起，页面仍会被少数长字段拖长。

**独立验收**：使用同时包含短字段和明显超长字段的临时表单，确认短字段完整显示且无多余控制，超长字段默认收起并保留标题、状态和展开入口。

**验收场景**：

1. **假如**字段内容没有超过当前布局下的收起展示区域，**当**用户查看临时表单，**那么**卡片完整显示内容且不出现“展开”控制。
2. **假如**字段内容超过当前布局下的收起展示区域，**当**用户首次查看临时表单，**那么**卡片默认收起，并持续显示字段标题、字段状态和“展开”入口。
3. **假如**同一组内同时存在短字段和超长字段，**当**超长字段处于收起状态，**那么**其他卡片的列宽和内容展示不受影响。

### 用户故事 2：独立核对完整候选与证据（优先级：P1）

作为需要核对 AI 结果的科研用户，我希望只展开当前关注的字段并查看全部候选值、来源和证据句，核对完成后再收起，同时不干扰其他字段。

**优先级理由**：收起不能以牺牲证据可追溯性为代价，用户必须能够随时恢复完整内容。

**独立验收**：连续展开两张超长卡片，再单独收起其中一张，确认另一张保持展开，且展开内容与收起前的数据完全一致。

**验收场景**：

1. **假如**超长字段处于收起状态，**当**用户激活该卡片的标题区或“展开”控制，**那么**卡片显示全部候选值、来源定位和证据句，列宽保持不变。
2. **假如**字段已经展开，**当**用户再次激活同一控制，**那么**该字段恢复收起状态。
3. **假如**两张字段卡片已经展开，**当**用户收起其中一张，**那么**另一张保持展开。
4. **假如**用户在字段正文中选择或复制文字，**当**完成选择或复制操作，**那么**卡片不会因此意外切换展开状态。

### 用户故事 3：在动态解析和不同设备上保持可用（优先级：P2）

作为在解析过程中持续查看结果的用户，我希望内容更新、窗口变化和任务切换不会产生错误的展开状态，也希望使用键盘和辅助技术时能够完成相同操作。

**优先级理由**：临时表单会轮询更新且需要响应式展示；状态错乱或只能鼠标操作会破坏可靠性。

**独立验收**：在解析结果追加、桌面与窄屏切换、键盘操作和任务切换场景下，验证溢出判断、独立展开状态和可访问名称始终正确。

**验收场景**：

1. **假如**用户已展开一个字段，**当**轮询为该字段追加候选或证据，**那么**该字段保持展开并显示新增内容。
2. **假如**原本未溢出的字段因内容追加或可用宽度变窄而发生溢出，**当**页面完成更新，**那么**该字段显示“展开”入口且默认收起。
3. **假如**字段不再溢出，**当**页面完成重新布局，**那么**字段完整显示且不保留无效的展开控制。
4. **假如**用户切换到另一上传任务，**当**新任务包含相同字段路径，**那么**前一任务的展开状态不会泄漏到新任务。
5. **假如**用户只使用键盘或屏幕阅读器，**当**聚焦并激活展开控制，**那么**能够完成展开和收起，并获知当前状态及对应字段。

### 边界与异常场景

- 没有候选值、仍在等待解析的字段不显示展开控制。
- 单个候选中的长单词、DOI、公式化字符串、JSON 文本或连续字符不得造成横向页面滚动。
- 冲突字段收起时仍显示“有冲突”状态；展开后必须显示全部冲突候选及各自来源。
- 同一行一张卡片展开时，相邻卡片不得被动扩展其可见内容区域。
- 多张卡片可同时展开，不限制为单一展开项。
- 减少动效偏好启用时，状态切换不得依赖位移动画才能理解或完成。

## 需求

### 功能需求

- **FR-001**：临时表单必须保持桌面双列、窄屏单列的响应式字段布局，展开和收起不得改变字段卡片的列宽。
- **FR-002**：系统必须依据字段内容在当前可用宽度下是否超过统一的收起展示区域，决定是否提供展开控制。
- **FR-003**：未溢出的字段必须完整显示，且不得显示无效的展开或收起控制。
- **FR-004**：溢出字段首次显示时必须默认收起，并始终露出字段标题、字段状态和具有明确文字的“展开”入口。
- **FR-005**：用户必须能够通过字段标题区或明确控制独立展开和收起每张溢出卡片；正文区域不得触发展开状态切换。
- **FR-006**：展开状态必须按当前上传任务和字段分别维护；操作一张卡片不得改变其他卡片，也不得跨任务继承状态。
- **FR-007**：展开状态必须只改变目标卡片的可见高度，不得改变其列宽，也不得强制相邻卡片扩展可见内容区域。
- **FR-008**：展开后必须显示该字段的全部候选值、来源定位和证据句；收起只能改变视觉呈现，不得删除、改写或重新排序数据。
- **FR-009**：解析轮询追加内容时，已经展开的字段必须保持展开；此前未溢出但更新后溢出的字段必须获得默认收起状态和展开入口。
- **FR-010**：当布局变化使字段不再溢出时，系统必须完整显示内容并移除无效控制；字段再次溢出时必须重新提供正确控制。
- **FR-011**：展开控制必须支持键盘聚焦与激活，并向辅助技术提供字段名称、当前展开状态和受控内容关系；焦点状态必须可见。
- **FR-012**：交互状态不得只靠颜色或方向图标表达，必须同时提供“展开”或“收起”文字。
- **FR-013**：状态切换动效必须简短且只用于表达展开变化；启用减少动效偏好时必须提供无位移动效的等效体验。
- **FR-014**：长单词、连续字符和预格式化内容必须在卡片边界内安全换行，不得引起页面横向滚动。
- **FR-015**：现有“已填写 / 等待解析 / 有冲突”状态、冲突候选并列展示及来源证据语义必须保持不变。

## 成功标准

- **SC-001**：在包含单行字段和至少 20 行字段内容的验收数据中，所有短字段均完整显示且无展开控制，所有超长字段均默认收起并可完整展开。
- **SC-002**：用户可连续展开至少 3 张卡片并任意收起其中一张，其余卡片状态保持不变，操作结果为 100% 可重复。
- **SC-003**：在桌面双列和窄屏单列验收视口中，展开、收起及动态内容追加均不产生横向页面滚动或卡片列宽跳变。
- **SC-004**：使用鼠标、仅键盘和屏幕阅读器语义查询三种方式，均可识别并完成每张溢出卡片的展开与收起。
- **SC-005**：现有临时表单状态、冲突候选、来源定位及 ready 后切换最终草稿的自动化测试全部继续通过。

## 假设与依赖

- “固定宽度”解释为在当前响应式布局中保持稳定列宽，而不是为所有设备指定同一像素宽度。
- “超过固定宽度”解释为内容在稳定列宽下产生超出统一收起展示区域的纵向溢出；长内容通过收起控制渐进呈现。
- 本 Feature 仅覆盖任务尚未进入 `ready` 时的只读“AI 临时表单”，不覆盖最终可编辑草稿。
- 解析详情继续使用现有字段路径作为字段身份，候选值和来源数据契约保持不变。
- 父 Epic #24 与实时解析详情 #27 已提供页面、状态和证据展示基础。

## 范围外事项

- 不修改上传任务、解析详情或轮询 API。
- 不修改候选合并、冲突判定、字段排序或字段分组规则。
- 不改变任务进入 `ready` 后的最终可编辑表单。
- 不改变“分段解析与证据”页签的现有展开行为。
- 不增加全局“全部展开 / 全部收起”、展开状态持久化或跨会话记忆。
- 不更新根 README；本 Feature 不改变安装、启动或顶层使用流程。

## 澄清记录

### 2026-08-24

- 问：卡片的“固定宽度”和超出后折叠应如何理解？ → 答：保持响应式列宽稳定，长内容在统一收起展示区域内默认收起；展开只改变目标卡片高度，不改变宽度。
- 问：是否允许分别查看多张卡片？ → 答：每张卡片独立展开，可同时展开多张，再次激活当前卡片即可收起。
- 问：本轮是否扩大到最终可编辑表单？ → 答：不扩大，仅处理解析中的只读“AI 临时表单”。
