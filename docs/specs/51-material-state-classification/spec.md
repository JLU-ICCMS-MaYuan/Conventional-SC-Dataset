# Feature 规格：材料状态多维分类目录与统一审核

**GitHub Issue**：[#51](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/51)

**创建日期**：2026-08-25

**状态**：已确认

## 背景与目标

现有上传校对页面把论文级 `sc_type` 作为自由文本，用静态英文编码和原生 `datalist` 提供候选。该实现没有查询数据库，无法把 LLM 输出的中文名称与英文编码稳定对应，也不能表达同一篇论文中的多个材料状态。管理员审核和论文编辑仍读写旧 `key_properties.superconductor_type` 兼容字段，正式科学数据模型没有材料分类归属。

本 Feature 建立材料状态级的正式分类目录和确定性归一化流程。上传、论文编辑和管理员审核统一使用规范中文名称；材料家族、结构家族、元素种类数、压力和材料维度分开保存。引用工作证据继续供后台判断本文研究对象，但引用材料不进入普通界面或最终科学数据。

## 用户场景与验收

### 用户故事 1：从数据库选择材料家族（优先级：P1）

论文贡献者校对每个材料状态时，可以展开数据库中的正式材料家族，输入规范名或已审核别名并得到同一个中文结果，也可以提交无法匹配的新名称等待审核。

**优先级理由**：这是截图中候选无法弹出、中文和英文不匹配以及类型归属错误的共同主路径。

**独立验收**：打开含 `高压氢化物` AI 建议的上传草稿，材料状态显示“氢基超导体”，候选列表来自数据库；压力仍显示论文提取的独立 GPa 数值。

**验收场景**：

1. **假如**目录存在“氢基超导体”及别名 `hydride`、`氢化物`，**当**用户输入任一名称，**那么**系统选择同一个正式目录项并只显示“氢基超导体”。
2. **假如**AI 返回未匹配名称，**当**用户查看材料状态，**那么**界面显示待确认名称和处理入口，不把它伪装成正式类型。
3. **假如**同一材料有多个压力状态，**当**用户批量设置材料家族，**那么**全部目标状态获得相同家族且仍可逐状态修正。

### 用户故事 2：保存独立分类维度（优先级：P1）

论文贡献者可以为每个材料状态维护一个主材料家族、多个结构家族及唯一主结构家族；系统从化学式计算不同元素种类数，并独立保存材料维度和压力。

**优先级理由**：把“高压氢化物”等复合字符串拆成可验证事实，避免分类含义混杂。

**独立验收**：提交 `LaH10 @ 150 GPa` 后，正式数据分别得到“氢基超导体”、元素种类数 2、压力 150 GPa、材料维度和结构家族，不产生“高压氢化物”正式目录项。

**验收场景**：

1. **假如**化学式为 `LaH10`，**当**草稿规范化，**那么**元素种类数为 2，而不是原子总数 11。
2. **假如**一个状态选择多个结构家族，**当**保存，**那么**最多一个条目标记为主项。
3. **假如**论文没有说明材料维度，**当**提交，**那么**保存“未知”，不得由压力或结构名称猜测。
4. **假如**材料公式含铜但论文明确归类为重费米子超导体，**当**归一化，**那么**系统不得按元素把它改为铜基超导体。

### 用户故事 3：审核建议并治理目录（优先级：P2）

管理员可以把待确认名称映射到已有目录、提交为别名或建议创建正式项；超级管理员可以批准正式项及别名，并对正式目录执行创建、重命名、停用和合并。

**优先级理由**：正式目录需要可持续治理，但不阻塞已有目录的 P1 选择和提交路径。

**独立验收**：管理员将一个待确认名称映射到已有家族后，相关材料状态使用正式目录项；超级管理员的目录修改产生可查询审计记录。

**验收场景**：

1. **假如**普通管理员处理待确认名称，**当**选择已有家族，**那么**材料状态更新为该家族并记录审核人和处理结论。
2. **假如**管理员认为名称是同义词，**当**提交别名建议，**那么**别名在超级管理员批准前不能参与自动匹配。
3. **假如**超级管理员合并两个正式项，**当**事务完成，**那么**现有归属和别名转向目标项，旧项停用且审计记录保留变更前后内容。

### 用户故事 4：一次性兼容旧草稿和旧数据（优先级：P2）

系统可以读取仍含 `sc_type` 的旧草稿并按白名单转换；保存后只保留新结构。拥有旧数据库或备份时，维护者可以执行只做唯一匹配的迁移并得到歧义报告。

**优先级理由**：避免未提交草稿突然失效，同时阻止兼容字段长期扩散。

**独立验收**：读取 `sc_type=hydride` 的旧草稿后，每个缺少家族的材料状态显示“氢基超导体”；保存请求和后续读取均不再含 `sc_type`。

**验收场景**：

1. **假如**旧值位于确定性白名单，**当**首次读取，**那么**系统转换并返回迁移提示。
2. **假如**旧值为 `carbon` 或 `others`，**当**首次读取，**那么**系统产生待确认项，不猜测正式家族。
3. **假如**旧数据库记录不能唯一对应一个材料状态，**当**运行迁移，**那么**记录进入报告且目标数据库不被修改。

### 用户故事 5：只保留本文正式分类（优先级：P1）

论文贡献者和最终数据消费者只看到本文主要研究材料的分类。后台仍区分 `current_paper` 与 `referenced_work`，引用工作证据不参与本文分类，也不作为“引用材料”字段公开。

**优先级理由**：引用论文中的材料不是当前论文的研究对象，进入最终数据会直接污染研究对象信息。

**独立验收**：解析同时提及本文 `Li2MgH16` 和引用工作的 `LaH10` 时，正式材料状态只包含本文对象；管理员仍可在内部证据中核对引用作用域。

**验收场景**：

1. **假如**分段证据作用域为 `referenced_work`，**当**构建全文草稿，**那么**它不产生材料状态、正式分类或普通界面字段。
2. **假如**管理员检查分类依据，**当**打开内部审核证据，**那么**仍可看到作用域、页码、原句和 AI 原始名称。

### 边界与异常场景

- 目录查询失败时，编辑器显示可重试错误，不退回静态英文候选；已加载草稿保持可见。
- 停用或已合并目录项不能用于新选择；历史记录读取时返回当前规范项和历史审计，不显示失效编码。
- 同一维度的规范化别名必须唯一；冲突别名不能批准。
- 材料家族在论文批准前必须确认；结构家族和材料维度可以为未知。
- 非法化学式不能伪造元素种类数，必须进入人工确认。
- 普通管理员不能创建、重命名、停用或合并正式目录；超级管理员不能绕过审计。
- 新接口拒绝带顶层 `sc_type` 的保存请求；只有旧草稿读取路径执行一次性转换。
- 目录、别名或建议的并发处理必须保证一个建议只产生一个最终结论。

## 需求

### 功能需求

- **FR-001**：系统必须为每个材料状态保存零或一个正式材料家族；论文批准前每个主要研究材料状态必须确认一个家族。
- **FR-002**：系统必须维护材料家族正式目录，首批包含氢基、铜基、铁基、镍基、无机硼碳氮基、有机和重费米子超导体七项。
- **FR-003**：系统必须维护结构家族正式目录，并允许一个材料状态关联多个结构家族且最多一个为主项。
- **FR-004**：系统必须把材料家族、结构家族、元素种类数、压力和材料维度作为独立字段或关系保存。
- **FR-005**：材料维度必须使用零维、一维、二维、三维、准一维、准二维和未知七个受控值；单个材料状态只能保存一个值。
- **FR-006**：系统必须从确认的规范化化学式计算不同元素种类数；计算失败时保持空值并要求人工确认，不得使用化学计量总和代替。
- **FR-007**：系统不得根据化学式包含某个元素自动决定材料家族；归类只能来自论文明确表述、已审核别名映射或人工审核。
- **FR-008**：系统必须提供数据库驱动的材料家族和结构家族查询，普通响应显示规范中文名，不把内部稳定编码作为普通用户值。
- **FR-009**：上传校对、论文编辑和管理员审核必须复用同一分类选择契约和共享 MUI `Autocomplete`；不得继续使用静态候选或原生 `datalist`。
- **FR-010**：系统必须对规范中文名、规范英文名、内部稳定编码和已审核别名执行规范化后的精确匹配；不得使用模糊匹配自动写入正式分类。
- **FR-011**：未匹配名称必须作为待审核建议保存，界面明确显示待确认名称、状态及可用处理动作。
- **FR-012**：普通管理员必须能够映射已有项、提交别名建议或提交新正式项建议；超级管理员必须能够批准别名和正式项，并创建、重命名、停用或合并正式目录。
- **FR-013**：所有目录治理动作必须记录操作者、时间、动作、原因及变更前后内容。
- **FR-014**：分类结果必须记录 `reported`、`derived` 或 `reviewed` 来源；有论文证据时同时保存页码、章节、原句和 `current_paper|referenced_work` 作用域。
- **FR-015**：普通界面、普通接口和目标正式 Schema 必须删除 `referenced_materials`、`sc_type`、`type_code` 和 `type_proposal_raw`；管理员内部证据可以查看 AI 原始名称及引用作用域，但不得重建论文级“引用材料”正式字段。
- **FR-016**：只有 `current_paper` 证据可以形成本文材料状态和正式分类；`referenced_work` 只用于后台排除误判和管理员追溯。
- **FR-017**：旧草稿读取路径必须对顶层 `sc_type` 执行一次性白名单转换并从响应移除旧字段；新保存接口必须拒绝旧格式。
- **FR-018**：旧值 `hydride/cuprate/iron_based/nickel_based/organic/heavy_fermion` 及已确认中文同义词必须确定性迁移；`carbon`、`others` 和其他歧义值必须进入报告或待审核队列。
- **FR-019**：旧数据库迁移必须按论文、材料和压力唯一定位材料状态；零个或多个匹配均不得写入并必须进入报告。
- **FR-020**：`高压氢化物`必须归一为氢基超导体，压力只能来自论文中独立抽取的具体数值或范围；系统不得由“高压”文字补造数值或阈值。
- **FR-021**：系统必须支持把同一材料的家族批量应用到多个材料状态，同时允许逐状态修正。
- **FR-022**：正式接口必须以 `{id, name}` 表达材料家族，以 `{id, name, is_primary}` 表达结构家族；待确认项必须有明确状态而不能伪装成正式 ID。
- **FR-023**：材料家族缺失或元素种类数无法确认时，管理员不得批准论文；结构家族缺失和材料维度为未知不阻塞批准。
- **FR-024**：目录读取对普通登录用户和管理员可用；目录治理与建议审核必须按管理员和超级管理员权限分层。

### 关键实体

- **材料家族**：材料状态的唯一主要领域归类，具有稳定内部标识、规范中英文名称、启用状态和可审核别名。
- **结构家族**：材料状态的结构拓扑或家族分类，可多选并指定一个主项，不替代空间群事实。
- **材料状态分类**：材料状态上的家族、结构家族、元素种类数、压力和材料维度组合。
- **分类建议**：无法确定性匹配的用户或 AI 名称，具有待处理状态、建议维度、来源和最终处理结果。
- **分类证据**：支持或解释分类的论文证据、派生依据或人工审核记录；引用作用域只在管理员证据中可见。
- **分类目录审计事件**：正式目录和别名治理的不可变操作记录。

## 成功标准

- **SC-001**：上传、论文编辑和管理员审核三个入口的启用材料家族候选与数据库目录完全一致，不再包含代码内静态七项数组。
- **SC-002**：规范中文名、英文名、稳定编码和所有已审核别名的固定测试样例 100% 映射到同一目录 ID；未匹配样例 100% 不写入正式 ID。
- **SC-003**：包含本文材料和引用材料的回归样例中，普通草稿和正式科学数据的引用材料字段数量为 0，后台证据仍能逐条区分两种作用域。
- **SC-004**：`LaH10`、`CeCu2Si2`、`CeCoIn5`、`UPt3` 和 `UTe2` 回归样例的元素种类数与已确认家族全部符合本 Spec。
- **SC-005**：任一材料状态在数据库中最多有一个主结构家族；并发写入也不能产生两个主项。
- **SC-006**：普通管理员和普通用户对超级管理员目录治理接口的越权测试全部返回 403，且不产生审计或数据变更。
- **SC-007**：旧草稿固定样例首次读取全部可用，保存后的响应及持久草稿中旧字段数量为 0；所有歧义值均出现在迁移报告或待审核列表中。
- **SC-008**：后端、Go、前端、Alembic Schema 和端到端上传审核测试全部通过，覆盖成功、目录不可用、未匹配、权限拒绝、别名冲突和旧草稿兼容场景。

## 假设与依赖

- 依赖 #32 和 #46 已建立并接通的 `Paper -> MaterialState -> TcResult` 条件化科学数据主路径。
- 依赖 #45 的内部证据作用域判断，但由本 Feature 替代其“自由材料类型不归一化”和“引用材料公开展示”约束。
- 结构家族首批只预置当前已有证据可确定的“笼状结构”；其他名称进入审核，不在本 Feature 猜测完整领域词表。
- 当前新 Schema 没有可恢复的旧 `superconductor_type` 数据；只有提供旧数据库或备份时才运行旧数据迁移。
- 删除目标 Schema 的 `papers.referenced_materials` 是用户明确要求的数据结构变更；本 Feature 只生成和验证迁移代码，不自动对生产数据库执行迁移。
- 本 Feature 不自动运行生产数据库迁移或写入生产数据。

## 范围外事项

- 搜索页的材料家族、结构家族、元素数量、压力和材料维度筛选。
- 常压、低压和高压的固定数值阈值或压力等级枚举。
- 基于向量、编辑距离或 LLM 的模糊自动匹配。
- 从当前新数据库恢复已经删除且不存在于备份的数据。
- 建立完整结构家族本体、物性标签体系或分类父子树。
- 改变论文整体类型和每个数据结果理论/实验来源的既有语义。

## 澄清记录

### 2026-08-25

- 问：分类属于论文还是材料？→ 答：属于每个材料状态；同一论文可有多个材料及压力/结构状态。
- 问：正式类型来自历史字符串还是目录？→ 答：建立正式数据库目录，不使用历史字符串去重充当目录。
- 问：材料分类有哪些独立维度？→ 答：材料家族、结构家族、不同元素种类数、压力和材料维度分开保存。
- 问：材料家族初始值？→ 答：七个正式家族；重费米子按论文领域归类保留为主材料家族，不能因含铜等元素机械改类。
- 问：高压氢化物如何表达？→ 答：材料家族归一为氢基超导体，压力独立保存，不建立复合正式类型。
- 问：结构家族如何关联？→ 答：可多选并指定一个主项；首批仅录入已有证据能确定的项目。
- 问：材料维度和元素数量？→ 答：维度使用七个受控值；元素数量指不同元素种类数并从化学式计算。
- 问：中英文和编码如何统一？→ 答：正式关系只保存 ID；普通界面显示规范中文名，内部编码仅用于系统集成和迁移。
- 问：AI 原始输出如何处理？→ 答：不作为第二套正式分类，只保留在管理员审核证据中。
- 问：未知名称和旧数据如何处理？→ 答：只做确定性映射；未知项进入审核，无法唯一迁移的旧记录只生成报告。
- 问：权限如何划分？→ 答：管理员映射已有项并提交目录建议；超级管理员治理正式目录，所有治理动作审计。
- 问：旧 `sc_type` 兼容多久？→ 答：只在旧草稿读取时一次性转换，保存后只保留新结构，新接口不接受旧格式。
- 问：本次是否实现搜索？→ 答：暂不实现搜索筛选，也不定义压力等级阈值。
