# 技术研究：简化材料分类审核

## 决策 1：迁移故障与产品设计分别处理

MySQL 8.4 不允许 CHECK 引用自增主键，且带级联外键的 `STORED GENERATED` 列会导致外键创建失败。`0012` 必须删除自合并 CHECK 并使用 `VIRTUAL` 生成列。该故障是 DDL 兼容问题，不等同于产品设计错误。

旧治理设计仍然过重。它引入三个治理表、合并链、角色分级和独立页面，却没有增加论文主要研究对象的科学维度。最新设计删除治理工作流，但保留多维科学模型。

## 决策 2：不修改已发布迁移的业务含义

`0012` 已存在于 Git 历史。只对其做使 MySQL 能执行的兼容修复，再由 `0013` 删除旧治理结构。这同时支持 fresh MySQL 和已经执行过 `0012` 的开发库。

## 决策 3：AI 建议属于论文审核上下文

AI 原始值、理由和引用作用域先存在临时 review artifact。批准后临时文件会清理，因此长期追溯落在 `paper_review_events.classification_snapshot`。正式 `material_states` 只保存人工确认后的目录关系。

拒绝为 AI 建议建立独立 proposal 队列：它会把一次论文审核拆成多个状态机，并导致 proposal 与论文 revision 生命周期不一致。

## 决策 4：审核事务内创建目录

有论文审核权限的管理员可直接输入新材料家族或结构家族。服务端先进行规范名、英文名、编码和 seed 别名的精确匹配；仍未匹配才创建新项。

内部编码由规范化名称的 SHA-256 前缀确定性生成，`name_en` 可空。普通界面不要求也不显示这两个实现字段。

## 决策 5：seed 别名只读

保留可靠 seed 别名用于 `hydride`、`高压氢化物` 等明确映射，不提供在线别名创建与审批。AI 原始名称不会自动成为永久别名，避免目录污染。

## 决策 6：所有最终写入原子化

原实现先 PUT 分类、再 POST 审核；第二次请求失败时会留下未批准但已修改的正式分类。新接口在一个 GORM 事务中完成解析/创建、最终分类写入、完整性检查、论文状态和审核事件。

## 决策 7：批量批准关闭

批准要求逐材料状态人工确认，批量批准没有承载分类选择的可靠界面和契约，因此返回明确错误。批量拒绝和退回不创建分类，可继续使用。

## 决策 8：科学维度不随治理简化删除

材料家族、结构家族、不同元素种类数、压力和材料维度相互独立。`高压氢化物`表达为“氢基超导体 + 独立压力”；含铜不构成铜基分类证据。
