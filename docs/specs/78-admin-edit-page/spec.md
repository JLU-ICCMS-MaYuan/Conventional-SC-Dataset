# Feature 规格：管理端审核编辑页独立化并功能对齐提交页

**GitHub Issue**：[#78](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/78)

**创建日期**：2026-09-02

**状态**：已实施，待 Issue 验收

## 背景与目标

管理端审核编辑存在两个现状缺口：

1. **结构功能不完整**：编辑弹窗中已落库的结构经 `frontend/src/pages/AdminPage.tsx:137` 的 `candidateFromStructureModel` 转换时只保留落库的规范表示（`representations.conventional.cif`），**没有 primitive 表示、没有 POSCAR**。而 `StructureCandidatePanel` 的晶胞切换（惯用胞/原胞）与格式切换（CIF/POSCAR）依赖 `representations[cell][format]`——管理端切到原胞或 POSCAR 时无内容可预览、下载按钮禁用。提交页的候选由 `build_structure_candidate` 生成完整表示，因此可以自由转换——两处功能不一致。

2. **编辑是弹窗**：`AdminPage` 的编辑在 Dialog 中堆叠（论文级字段 + key_properties 表 + 材料状态编辑器 + 审核区），内容多、空间局促，无法良好承载与提交页等价的完整功能，也不便多开对比。

本 Feature 把管理端审核编辑改为**独立页面（新标签页路由）**，并把结构附件功能补齐到与提交页完全一致：晶胞表示（惯用胞/原胞）自由转换、CIF/POSCAR 格式切换、结构文件下载。尽可能把提交页的内容与功能逐一搬到管理端审核页。

## 用户场景与验收

### 用户故事 1：管理员和超级管理员在独立页面编辑论文（优先级：P1）

管理员或超级管理员从各自工作台的论文列表点「编辑」跳转到独立页面（新标签页），页面承载论文级字段、科学数据、材料状态分类与结构附件的完整编辑能力；论文审核弹窗只负责审核结果和审核意见。

**优先级理由**：独立页面是本 Feature 的基础布局改造，也是后续功能对齐的承载容器；弹窗在内容多时已不可用。

**独立验收**：两类后台角色点「编辑」均不再出现弹窗，而是打开 `/admin/papers/:id/edit` 独立页面，全部编辑能力可用。

**验收场景**：

1. **假如** 管理员在论文列表点击「编辑」，**当** 请求发出，**那么** 跳转到 `/admin/papers/:id/edit` 独立页面（新标签页语义），不再渲染编辑弹窗。
2. **假如** 独立页面加载完成，**当** 查看，**那么** 论文级字段、科学数据（MaterialStatesEditor）、审核区、升版警告齐全，布局为页面而非弹窗。
3. **假如** 非管理员访问该路由，**当** 请求发出，**那么** 被 `RoleRoute` 拒绝。
4. **假如** 超级管理员在超级管理员工作台点击「编辑」或直接访问该路由，**当** 请求发出，**那么** 保持在独立编辑页，不被重定向到 `/superadmin`；返回或取消时回到 `/superadmin`。
5. **假如** 管理员打开论文审核操作，**当** 审核弹窗显示，**那么** 弹窗只显示审核结果、审核意见和确认/取消，不重复显示材料状态分类。

### 用户故事 2：结构晶胞/格式自由转换与下载（优先级：P1）

管理员在独立页面像提交页一样切换结构的惯用胞/原胞表示与 CIF/POSCAR 格式，并可下载对应文件。

**优先级理由**：这是「功能对齐提交页」的核心。落库只存惯用胞 CIF，但审核者需要查看/导出其他表示。

**独立验收**：独立页面结构区切换惯用胞/原胞、CIF/POSCAR 后预览正确，下载得到对应文件。

**验收场景**：

1. **假如** 已落库结构（惯用胞 CIF）加载完成，**当** 切换晶胞表示为「原胞」、格式为 POSCAR，**那么** 预览显示原胞 POSCAR 内容。
2. **假如** 切换到任一 cell/format 组合，**当** 点击下载，**那么** 下载得到对应格式的文件（文件名含结构与格式标识）。
3. **假如** 表示生成服务不可用，**当** 页面加载，**那么** 结构区降级为仅显示落库的惯用胞 CIF（现有行为），不阻塞其他编辑。

### 用户故事 3：保存与升版行为一致（优先级：P1）

独立页面的两段保存、升版警告与退回提示与现有弹窗完全一致。

**优先级理由**：编辑能力迁移不能引入行为差异。

**独立验收**：独立页面保存按 C4 顺序调用两个端点，`pending` 原地保存、`approved` 保存前显示升版警告、保存后按 `revision_bumped` 提示。

**验收场景**：

1. **假如** 修改论文级字段与科学数据并保存，**当** 请求发出，**那么** 先 `PUT /api/admin/papers/:id` 后 `PUT /api/rag/papers/:id/scientific-draft`（C4）。
2. **假如** 论文为 `approved`，**当** 打开页面，**那么** 显示升版警告。
3. **假如** 保存成功且 `revision_bumped=true`，**当** 响应返回，**那么** 提示论文已退回待审核。

### 边界与异常场景

- 表示生成服务失败：降级为仅显示落库 CIF（现有 `candidateFromStructureModel` 行为），编辑与保存不受影响。
- 结构文件不存在（`structure_models` 无记录）：结构区空态，不报错。
- 直接访问 `/admin/papers/:id/edit`（非列表进入）：页面自行加载论文详情，行为一致。
- 超级管理员通过复用的论文列表进入编辑页：允许访问同一编辑路由；返回与取消回到 `/superadmin`，不重新触发管理员工作台重定向。
- 旧弹窗入口：独立页面上线后移除编辑弹窗，列表「编辑」统一跳转。

## 需求

### 功能需求

- **FR-001**：管理端论文列表的「编辑」必须跳转到 `/admin/papers/:id/edit` 独立页面，不再打开编辑弹窗。
- **FR-002**：独立页面必须由 `admin` 与 `superadmin` 角色保护（`RoleRoute`）；普通用户拒绝访问，超级管理员访问该子路由不得套用 `/admin` 工作台的重定向规则。
- **FR-003**：独立页面必须承载论文级字段、科学数据（`MaterialStatesEditor`）、审核区与升版警告的完整编辑能力。
- **FR-003a**：材料状态分类必须在独立编辑页的 `MaterialStatesEditor` 中维护，位置与上传草稿表单一致；审核弹窗不得编辑分类。
- **FR-003b**：独立编辑页的审核结果必须与审核弹窗统一提供“通过、拒绝、退回待审核”三个状态；选择“退回待审核”时文案前显示回退箭头图标。
- **FR-003c**：选择“通过”并提交审核时，必须携带当前编辑页材料状态分类；管理员无需先单独点击“保存修改”即可提交，后端仍负责最终完整性校验。
- **FR-004**：已落库结构必须在独立页面获得完整表示（primitive/conventional × cif/poscar），使晶胞切换与格式切换可用。
- **FR-005**：独立页面结构区必须支持切换惯用胞/原胞与 CIF/POSCAR，切换后预览正确。
- **FR-006**：独立页面必须支持下载结构的 CIF 与 POSCAR 文件。
- **FR-007**：表示生成服务不可用时必须降级为显示落库惯用胞 CIF，不阻塞其他编辑。
- **FR-008**：独立页面保存必须沿用两段保存（C4）：先论文级后科学数据。
- **FR-009**：`approved` 论文在独立页面必须显示升版警告，保存后按 `revision_bumped` 提示退回待审核。
- **FR-010**：上传校对页行为不得回退。

### 关键实体

- **结构表示**：同一结构在不同晶胞（惯用胞/原胞）与格式（CIF/POSCAR）下的文本序列化，由 `backend/services/structure_candidates.py` 的 `export_representations(atoms)` 生成。落库只保存惯用胞 CIF，其余表示按需生成。
- **独立编辑页**：`/admin/papers/:id/edit` 路由下的页面组件，承载现编辑弹窗全部能力。

## 成功标准

- **SC-001**：列表「编辑」跳转独立页面，弹窗编辑移除。
- **SC-002**：独立页面结构区可切换全部 cell/format 组合并正确预览。
- **SC-003**：独立页面可下载 CIF 与 POSCAR。
- **SC-004**：两段保存、升版警告与退回提示在独立页面行为与弹窗一致。
- **SC-005**：上传校对页既有自动化测试全部通过。
- **SC-006**：超级管理员访问 `/admin/papers/:id/edit` 时独立编辑页可渲染，不重定向到 `/superadmin`。
- **SC-007**：审核弹窗仅提交审核结果与审核意见，分类由编辑页保存后参与后端审核校验。
- **SC-008**：编辑页审核结果包含三个状态，且“退回待审核”选项在中英文界面均带回退箭头图标。
- **SC-009**：编辑页直接选择“通过”提交时，审核请求包含当前材料状态分类，并可在分类完整时成功批准。

## 假设与依赖

- 依赖 [Issue #76](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/76) 的 `MaterialStatesEditor`、两段保存编排与升版逻辑。

## 范围外事项

- 修改 `structure_models` 表结构或详情接口契约。
- 修改上传校对页的现有交互。
- 修改提交链路（`_confirmed_candidates_by_state`）与 C1 契约。
- 历史版本结构的浏览与回滚。
- 弹窗编辑的保留：独立页面上线后移除。

## 澄清记录

### 2026-09-02

- 问：结构表示是落库还是按需生成？ → 答：按需生成。`structure_models` 只存惯用胞 CIF（提交链路契约不变），表示由新端点从落库 CIF 实时生成（`read_atoms` + `export_representations`）。理由：落库全部表示会改动提交契约与表结构，且原胞/POSCAR 可从 CIF 无损推导。
- 问：独立页面是「新开浏览器标签页」还是「SPA 路由跳转」？ → 答：SPA 路由（`/admin/papers/:id/edit`）。「新标签页」指不再是弹窗、而是独立的页面级视图（浏览器新标签打开同一路由也成立）。不引入 `window.open` 强制新标签。
