# Feature 规格：公开科研身份页

**GitHub Issue**：[#41](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/41)

**创建日期**：2026-08-24

**状态**：已确认

## 背景与目标

#31 建立了唯一公开用户名，但当时明确不提供个人主页并保持实名私有。本 Feature 是后续受控扩展：用户填写的科研身份字段通过独立白名单接口公开，登录和排行榜 DTO 仍保持最小化。

## 用户场景与验收

### 用户故事 1：查看研究者公开资料（优先级：P1）

任何人可从稳定用户名地址查看该用户主动填写的科研身份。

**独立验收**：匿名访问 `/users/:username`，只看到允许公开的字段。

**验收场景**：

1. **假如**用户填写了头像、姓名、机构、ORCID 和研究方向，**当**匿名访客打开公开页，**那么**这些字段可见，邮箱和内部状态不可见。
2. **假如**字段为空，**当**页面渲染，**那么**不显示空卡片或占位文案。
3. **假如**目标是管理员或超级管理员，**当**查看公开页，**那么**显示对应身份；普通用户不显示默认角色。

### 用户故事 2：从科研活动进入资料页（优先级：P2）

访客可从贡献榜和审核记录的用户名进入公开页，本人可从用户中心预览公开主页。

### 用户故事 3：理解受治理账号状态（优先级：P2）

封禁账号保留公开资料并标注封禁；注销账号移除资料且历史贡献匿名化。

### 边界与异常场景

- 用户名修改后旧地址返回 404，新地址立即生效，不创建别名。
- 页面必须设置 `noindex`，卸载后不得污染全站 robots 元数据。
- 公开 API 不得直接序列化 User ORM。
- 封禁标识公开；封禁原因、操作者和内部状态不公开。

## 需求

### 功能需求

- **FR-001**：系统必须提供匿名可访问的 `/users/:username`。
- **FR-002**：公开白名单仅包含头像、用户名、真实姓名、所属机构、ORCID、研究方向和允许公开的角色标识。
- **FR-003**：邮箱、验证状态、账号权限、审计和内部 ID 不得出现在公开响应。
- **FR-004**：普通用户不显示角色标识；管理员与超级管理员显示身份。
- **FR-005**：空字段不得渲染无意义占位；真实姓名清空后立即停止公开。
- **FR-006**：页面必须设置 `noindex`，但不得要求登录。
- **FR-007**：贡献榜、审核记录和本人用户中心必须提供公开页入口。
- **FR-008**：用户名更改后旧 URL 必须失效。
- **FR-009**：封禁账号保留资料并显示“账号已封禁”；注销账号不再公开资料，历史身份显示“已注销用户”。
- **FR-010**：贡献排行榜统计、排序、缓存和 #31 DTO 不得改变。

## 成功标准

- **SC-001**：匿名公开响应的字段集合严格等于白名单，敏感字段泄漏数为 0。
- **SC-002**：三个确认入口均能在一次点击内到达正确用户页。
- **SC-003**：封禁、注销和改名状态在下一次读取时准确反映。
- **SC-004**：搜索引擎 robots 元数据只在公开页存在。

## 假设与依赖

- 依赖 #40 的资料字段与头像服务，依赖 #31 的唯一用户名。
- 本 Feature 覆盖 #31 当时“无个人主页、实名始终私有”的范围边界，但不修改历史 Spec。

## 范围外事项

- 搜索引擎收录、社交功能、公开邮箱、用户名别名跳转、全站用户名一次性链接化。

## 澄清记录

### 2026-08-24

- 问：资料是否公开？ → 答：用户填写后，头像、用户名、姓名、机构、ORCID 和研究方向均公开。
- 问：搜索引擎是否收录？ → 答：暂不收录，页面设置 noindex。
- 问：封禁账号如何展示？ → 答：保留主页并公开标注封禁。
