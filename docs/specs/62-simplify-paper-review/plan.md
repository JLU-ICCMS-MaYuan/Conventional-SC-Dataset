# 实施计划：简化论文审核功能

**GitHub Issue**：[#62](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/62)

**日期**：2026-08-31

**Spec**：[spec.md](spec.md)

## 摘要

简化审核弹窗，移除所有 AI 解析内容展示，只保留基础信息（DOI、年份、记录数）、审核状态选择器和批注输入框。同时在编辑页面添加审核控件区域，供需要详细查看时使用。

**技术方案**：
1. 修改前端 `AdminPage.tsx` 中的审核弹窗，删除 AI 解析内容展示
2. 在编辑页面顶部添加审核控件区域（固定定位）
3. 保持现有审核API契约不变（后端无需修改）

## 技术上下文

- **语言与版本**：TypeScript 5.x + React 18 + Material-UI 5
- **主要依赖**：`@mui/material`、`react`
- **测试体系**：Vitest + React Testing Library
- **目标平台**：现代浏览器（Chrome、Firefox、Safari）
- **约束**：
  - 不修改后端审核API
  - 保持现有审核状态枚举（pending、approved、rejected）
  - 编辑页面的审核控件不影响现有表单布局

## 实施步骤

### 步骤1：简化审核弹窗（30分钟）

**目标**：移除 AI 解析内容展示，只保留基础信息和审核控件。

**操作**：
1. 定位 `AdminPage.tsx` 中的审核弹窗（`<Dialog open={reviewDlg.open}>`）
2. 删除"AI 建议、用户提交与原文证据"整个区块
3. 保留：DOI、年份、记录数标签，审核状态选择器，批注输入框，操作按钮
4. 调整布局，减少弹窗高度

### 步骤2：编辑页面添加审核控件（45分钟）

**目标**：在编辑页面顶部添加固定的审核控件区域。

**操作**：
1. 定位编辑页面弹窗（`<Dialog open={editPaper.open}>`）
2. 在 `<DialogContent>` 顶部添加审核控件区域：
   - 使用 `<Box sx={{ position: 'sticky', top: 0, zIndex: 1, bgcolor: 'background.paper', pb: 2, borderBottom: '1px solid', borderColor: 'divider' }}>`
   - 包含：审核状态选择器 + 批注输入框 + 确认审核按钮
3. 复用审核弹窗的 `handleReview` 函数逻辑
4. 提交成功后关闭编辑弹窗并刷新列表

### 步骤3：测试与验证（15分钟）

**测试场景**：
1. 审核弹窗：打开后验证无AI内容，只显示基础信息和审核控件
2. 编辑页面：验证顶部审核控件始终可见，下方仍可查看和编辑AI字段
3. 审核提交：验证两个入口提交审核后状态正确更新

## 技术决策

### 决策1：不提取审核控件为独立组件

**理由**：
- 审核控件逻辑简单（状态选择器 + 批注输入框）
- 两个使用场景的上下文不同（弹窗vs编辑页面）
- 提取为组件会增加 props 传递复杂度
- 代码重复量小（约20行），可接受

### 决策2：编辑页面审核控件使用 sticky 定位

**理由**：
- `position: sticky` 可以在滚动时保持控件可见
- 不需要额外的滚动监听逻辑
- 兼容性好（现代浏览器全支持）
- 比 `position: fixed` 更符合页面流

### 决策3：保持现有审核API契约不变

**理由**：
- 后端已支持所需的审核功能
- 不需要新增或修改审核状态枚举
- 批注字段已存在（`review_comment`）
- 审核记录已自动保存到 `paper_review_events` 表
