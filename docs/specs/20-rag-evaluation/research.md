# 技术研究决策：Mentor RAG 分层评测

## 决策 1：组件诊断与端到端消融分层

- **决策**：S1–S3直接评价工具结构化输出，S4评价 Mentor 答案，S5评价部署链路。
- **理由**：避免把检索、路由、生成和网络故障混成一个分数。
- **备选方案**：只做端到端正确率；无法定位失败来源，拒绝。
- **证据**：当前 Mentor 在 `backend/rag/agent/mentor.py` 内同时绑定工具并生成答案。

## 决策 2：物理工具隔离

- **决策**：以 runner 配置注入工具集合，不依赖提示词禁止调用。
- **理由**：当前 `ALL_TOOLS` 在模块加载时固定绑定，提示约束无法证明工具不可见。
- **备选方案**：四套复制 graph；重复且易漂移，拒绝。

## 决策 3：Qdrant 两层指标

- **决策**：分别测原始 vector search 与去重/截断后的 Agent wrapper。
- **理由**：wrapper 按 paper_id 去重并截断 snippet，二者回答不同问题。
- **风险**：当前代码可能反转 Qdrant score 语义，正式跑分前必须用 fixture 和回归测试确认。

## 决策 4：不可变运行账本

- **决策**：原始 JSONL 不覆盖，派生产物从原始记录重建。
- **理由**：支持审计、失败保留和统计复算。
- **备选方案**：数据库覆盖更新；难以审计，拒绝。

## 决策 5：PDF Gate

- **决策**：PDF 缺失期间只做 provisional 工程评测；到位后保持 chunk 边界并做旁路对齐。
- **理由**：现有 Qdrant 29,311 个主集合 point 没有页码、PDF 哈希或稳定 point ID，无法满足 gold evidence 回查。
- **备选方案**：以数据库或 Wiki 作为 gold；属于被测数据自证，拒绝。

## 决策 6：统计推断

- **决策**：问题为配对单位；三个相邻增量为主要比较，采用 Holm 校正和问题级配对 bootstrap。
- **理由**：四组共享问题，配对分析更高效且符合消融归因。
- **备选方案**：把重复运行当独立样本；会造成伪重复，拒绝。

## 决策 7：样本量

- **决策**：pilot 后展示 120/160/200 题的区间精度与可检测效应，再按预算冻结。
- **理由**：用户未预设最小关注效应，不能声称严格功效驱动。
- **报告限制**：未显著不等于无效果。

## 决策 8：运行环境

- **决策**：先在个人电脑跑通骨架，未来在开发机以独立环境重跑。
- **理由**：降低初始依赖成本；不同硬件结果不合并。
- **约束**：每个结果必须记录环境指纹，性能结论仅适用于对应环境。
