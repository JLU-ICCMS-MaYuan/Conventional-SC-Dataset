# Feature 规格：Mentor RAG 分层评测与工具消融

**GitHub Issue**：[\#20](https://github.com/JLU-ICCMS-MaYuan/SC-Wiki/issues/20)

**创建日期**：2026-08-17

**状态**：已澄清，待实施

## 背景与目标

当前 Mentor 能调用 Qdrant、MySQL 和 Neo4j，但缺少组件级指标、可注入工具组合、可审计 gold evidence、端到端消融和 HTTP/SSE 性能基线。本 Feature 建立先在个人电脑验证、后在开发机执行的统一评测流程；原始 PDF 缺失期间仅允许 development/provisional 结果。

## 用户场景与验收

### 用户故事 1：本机验证评测骨架（优先级：P1）

研究者可在不调用真实模型和数据库的情况下，用确定性 fixture 验证配置、数据契约、四组工具隔离和 S1–S3 指标。

**优先级理由**：先证明评测器本身正确，避免用未经验证的指标评价真实系统。

**独立验收**：在个人电脑执行 quickstart 命令，所有离线测试通过且不输出 `.env` 密钥。

**验收场景**：

1. **假如** 未启动外部服务，**当** 执行离线测试，**那么** fixture、schema 和确定性指标全部通过。
2. **假如** 配置四个消融组，**当** 构建 runner，**那么** 每组只能看到其声明的工具集合。

### 用户故事 2：执行组件和端到端评测（优先级：P2）

研究者可运行 S1–S5，获得不可覆盖的原始 JSONL、汇总 CSV、错误样例、配对统计和资源消耗。

**优先级理由**：形成可比较、可复算的实验记录。

**独立验收**：使用 development 数据运行四组消融，产物包含唯一实验 ID、配置哈希、Git commit、轨迹、指标、延迟、token 与成本字段。

**验收场景**：

1. **假如** 数据库和模型可用，**当** 对相同问题运行四组消融，**那么**除工具集合外的模型、prompt、检索参数和数据快照保持一致。
2. **假如** 请求超时或 SSE 中断，**当** runner 完成固定最多一次重试，**那么** 首次失败和重试结果均被保留。

### 用户故事 3：发布 PDF 可审计正式结果（优先级：P3）

两名领域标注者可依据原始 PDF 独立制作 pilot 和正式集，并发布可回查的科学质量结论。

**优先级理由**：这是正式结论的证据门，但依赖合作者提供原始 PDF。

**独立验收**：任一 gold evidence 均可由 DOI、PDF SHA-256、页码、定位符和内容哈希回查；标注一致性达到门槛。

**验收场景**：

1. **假如** 原始 PDF 尚未取得，**当** 请求正式评测，**那么**系统必须拒绝并说明 PDF Gate 未通过。
2. **假如** 20 题 pilot 完成，**当** 关键一致性低于 0.80，**那么**只能修订标注规范并重跑 pilot，不得进入正式集。

### 边界与异常场景

- 原始 PDF 缺失、哈希不匹配或 chunk 对齐低置信时，不得生成正式 gold。
- Qdrant、MySQL、Neo4j 或 LLM 单项不可用时，记录结构化失败，不静默删题。
- 同一 experiment ID 已存在时拒绝覆盖。
- 对称图关系不强制方向；有向关系必须匹配 schema 契约。
- 正式集结果一旦被查看，影响回答或评分的修改必须产生新实验版本并完整重跑。

## 需求

### 功能需求

- **FR-001**：系统必须定义 S1–S5 的输入、输出、指标口径和失败语义。
- **FR-002**：系统必须在代码层注入四组固定工具集合，LLM-only 不得接触检索上下文或历史会话。
- **FR-003**：S1 必须分别评估原始向量检索和 Agent wrapper，并计算 Recall@{1,3,5,10}、MRR 与 nDCG@{1,3,5,10}。
- **FR-004**：S2 必须以类型化结果分别评价数值、单位和适用条件，范围值不得只取最大值。
- **FR-005**：S3 必须直接评价结构化节点、边、路径、关系方向及证据覆盖；自然语言转述归入 S4。
- **FR-006**：S4 必须对四组使用相同问题、模型、prompt、参数、数据快照和评分器，并对评分器隐藏组名。
- **FR-007**：S5 必须分别测量 FastAPI 内部入口和 Go 外部代理的成功率、SSE 完整率、文本 TTFT、总延迟及错误率。
- **FR-008**：每次运行必须生成唯一 experiment ID，原始 JSONL 只追加不可覆盖，派生 CSV 和报告可重建。
- **FR-009**：系统必须记录 Git commit、配置哈希、数据快照、模型版本、随机种子、事件轨迹、重试、token、成本与延迟；估算 usage 必须显式标记。
- **FR-010**：pilot 必须为 20 题双人独立标注，题型配额为 3/3/2/3/3/3/3，并分别计算适用的一致性指标。
- **FR-011**：正式集必须与 pilot 隔离，按题型分层；pilot 后在 120、160、200 题中依据预算和精度冻结样本量。
- **FR-012**：主要终点必须为按题型宏平均的回答正确性；关键次要终点为忠实度、引用 F1 和正确拒答表现。
- **FR-013**：三个相邻消融增量为主要比较，完整组对 LLM-only 为总体比较；主要比较采用 Holm 校正与问题级配对 bootstrap 95% CI。
- **FR-014**：正式 gold evidence 必须保存 DOI、原始 PDF SHA-256、物理页、印刷页、图/表/公式/段落定位、原文、规范化内容哈希、标注者及裁决状态。
- **FR-015**：原始 PDF 不得重新切块；取得 PDF 后应保持既有 chunk 边界，仅补建页码/段落对齐、chunk 哈希、方法、置信度和未匹配状态。
- **FR-016**：PDF Gate 未通过时，全部真实语料结果必须标记为 development/provisional，禁止正式科学结论。
- **FR-017**：密钥必须仅从被 Git 忽略的 `.env` 或环境变量读取，禁止写入配置、日志和产物。
- **FR-018**：测试源码、小型 fixture 和 benchmark 骨架必须位于 `tests/05_rag_question_answering/`。

### 关键实体

- **Experiment**：一次不可变运行，关联配置、代码、数据快照和多条 RunRecord。
- **Question**：带题型、split、可回答性和类型化判定规则的问题。
- **GoldEvidence**：可回查原始 PDF 的证据定位与哈希。
- **RunRecord**：单个问题、消融组和重复序号的答案、轨迹、usage、延迟和错误。
- **EvaluationResult**：规则、人工或盲化 LLM judge 产生的逐项分数。
- **DataSnapshot**：Qdrant、MySQL、Neo4j、PDF manifest 和模型配置的冻结标识。

## 成功标准

- **SC-001**：个人电脑在无外部服务条件下可一次命令通过全部离线 fixture 测试。
- **SC-002**：四组工具可见集合与声明集合完全一致，隔离测试通过率 100%。
- **SC-003**：S1–S3 fixture 指标与人工计算结果完全一致。
- **SC-004**：原始运行记录覆盖率 100%，且不存在 experiment ID 覆盖。
- **SC-005**：pilot 的离散/等级人工一致性达到 0.80；证据集合一致性单独报告。
- **SC-006**：正式 gold evidence 的 DOI、PDF 哈希、页码、定位和内容哈希完整率 100%。
- **SC-007**：正式报告包含所有预注册主要比较、95% CI、错误样例、延迟、token 与成本，不选择性遗漏失败样本。

## 假设与依赖

- 初始运行平台为个人电脑；后续开发机结果作为独立环境重新运行和报告。
- `.env` 已被 Git 忽略，服务凭据由用户本地维护。
- 两名具备超导领域判断能力的人员可在 PDF 到位后独立标注。
- 供应商 usage 可缺失；缺失时允许本地估算并标记。

## 范围外事项

- 不重新切割 638 篇原始 PDF。
- 本阶段不做生产容量极限压测。
- PDF Gate 前不发布正式科学质量结论。
- 不把 Inspiration Agent 混入 Mentor 主消融。
